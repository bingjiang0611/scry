# Scry Remote G0 transport probe

Local implementation evidence for the current iOS remote product and host boundaries documented in [`apps/ios/README.md`](../../apps/ios/README.md). **Not a remote-control product, public relay, pairing authority, or completed G0 gate.** No Provider, real workspace, `.scry`, analytics DB, APNs or user credentials are accessed.

## Implemented

- A real SwiftNIO SSL client and Node TLS host, each dialing an outer TLS 1.3 WebSocket relay. The host uses an additional loopback TCP connection to its Node TLS server; this is an experiment adapter, not the production Electron connector.
- Inner TLS 1.3 mutual certificate verification, independent outer/inner CAs, server hostname verification, no application writes before inner handshake completion. Standard BoringSSL / Node TLS, no custom encryption. Resumed host sessions are rejected in this probe; production renewal/resumption policy is not yet implemented.
- Binary-only bounded relay, fixed two-peer routes, no arbitrary destination proxy. Clean close drains queued bytes; tamper, gap and overflow fail closed. No application-write retries.
- An **authenticated rendezvous admission** layer (`relay-admission.mjs` + `authenticated-relay.mjs`): single-use join tickets verified by SHA-256 (never stored/logged raw), host/device role binding, replay refusal, monotonic+wall-clock expiry, bounded session capacity, a sliding-window attempt rate limit, and log redaction. The relay still only shuttles opaque inner-TLS ciphertext and is never the security root. `register()` models the trusted Mac control channel publishing token hashes; that control channel's own authentication is out of scope here and required in production.
- One deliberately read-only `probe.echo` operation. A limited JSON Schema generates JS runtime validation, TS DTOs and Swift Codable validation, with drift checks and a shared malformed-input corpus.
- Test-only certificates generated by OpenSSL into a mode-0700 OS temp directory; private keys mode 0600. The fixture is deleted on ordinary success/failure. An abrupt process kill may leave a temp directory; keys are never committed or used by the real app.

## Run (from repository root)

Requires macOS, Xcode/Swift 6.2+, Node 22+, OpenSSL 3. Dependency versions are locked. iOS 17 is a **probe deployment target**, not a finalized public product minimum.

```sh
npm --prefix experiments/remote-g0 ci --ignore-scripts
node experiments/remote-g0/generate-wire.mjs --check
npm --prefix experiments/remote-g0 test
swift test --package-path experiments/remote-g0/swift -j 4
swift build --package-path experiments/remote-g0/swift -j 4
node experiments/remote-g0/smoke.mjs
node experiments/remote-g0/enrollment-smoke.mjs
node experiments/remote-g0/pair-smoke.mjs
node --import ./experiments/remote-g0/ts-relative-resolve.mjs experiments/remote-g0/g1-smoke.mjs
node --test experiments/remote-g0/relay-admission.test.mjs
node_modules/.bin/vitest run src/main/remote/pairing.test.ts   # run from repository root
```

Changes to `wire.schema.json` require `node experiments/remote-g0/generate-wire.mjs`; do not hand-edit generated TS/Swift validators. Only required flat scalar objects are supported so far. This is not a claim that the entire product operation registry has been generated.

Cross-compilation check (not an installed iPhone app):

```sh
swift build --package-path experiments/remote-g0/swift \
  --triple arm64-apple-ios17.0-simulator \
  --sdk "$(xcrun --sdk iphonesimulator --show-sdk-path)" -j 4
xcrun vtool -show-build experiments/remote-g0/swift/.build/arm64-apple-ios-simulator/debug/scry-remote-probe
```

The macOS smoke resolves SwiftPM's host binary path explicitly: a simulator build changes `.build/debug` and must not make the runner execute an iOS binary.

## Evidence on 2026-09-12

- macOS Swift build and 4 XCTest methods passed (wire corpus/bounds plus enrollment key/CSR/PEM tests).
- 30 Node tests passed (23-case wire corpus + 5 CSR/issuance + 2 bounds); generated JS/TS/Swift matched the schema; generated TS passed strict typecheck.
- 13 Vitest cases for `src/main/remote/pairing.ts` + `pairing-file.ts` passed (verifier-only secret, CSR channel-key binding, attempt cap, candidate immutability, single-transaction consume+issue, clock-rollback expiry and restart non-revival, write-failure/unknown-receipt fencing, cancel-during-signing, immediate+durable revocation, private atomic file with an exclusive lease, symlink/corruption/stale-lock refusal).
- Seven actual Swift ↔ Node transport scenarios passed: normal mTLS, bad outer CA, replaced inner host anchor, untrusted device certificate, encrypted-record tamper, forced disconnection, fresh authenticated connection after failure. Negative cases accept zero application requests and are not runner timeouts.
- Relay byte inspection did not find the probe's plaintext marker. This is supporting observation, not an independent cryptographic security audit.
- Initial standalone arm64 iOS Simulator cross-build linked but emitted a clang incompatible-sysroot warning. The later native Xcode app built with the actual simulator SDK and successfully executed the shared transport plus Keychain on iOS Simulator. See [native evidence](../../apps/ios/README.md). **Physical iPhone, IPA and signing/provisioning acceptance are still missing.**
- Found and fixed a real integration ordering bug: adding inner NIOSSL inside the HTTP upgrade callback causes the HTTP upgrader to reject its immediate ClientHello. Inner TLS is now installed on the event loop after upgrade completion.

## Still required before G0 completion

Complete first-device secret/live-channel proof and certificate enrollment with local human confirmation; one-time pairing replay/expiry and durable grant failure tests; real-device Keychain/installation/lock behavior; real device over an authorized public relay and cellular network while Mac is locked; reconnect/revocation/renewal semantics; packaging/licensing/security review. A native test app bundle and Simulator Keychain-to-TLS execution now exist, but are not real-device proof. The preissued client certificate in this fixture is **not** proof that onboarding works.

No cloud accounts, route tickets, user authentication, paid resources or deployed endpoints are created. The loopback relay is intentionally **not safe to expose on a public interface**. Keep the technical plan's high-privilege development gate closed until required G0 evidence is obtained.

## Native client reuse

`swift/Sources/RemoteTransport/` is the shared `ScryG0Transport` library; `RemoteProbe` is only the CLI wrapper. Generated Swift wire models moved with the library and the generator/test imports were updated. Private keys enter TLS from memory, allowing the native app's service actor to load from Keychain rather than creating PEM key files.

The isolated native app and Keychain/TLS regression are in `apps/ios/`. Once its dedicated simulator is installed, `node experiments/remote-g0/ios-smoke.mjs <UUID>` executes the real native model through Keychain and the same relay. This is not a production UI or onboarding substitute.

## Pairing state machine (still not completed device pairing)

`src/main/remote/pairing.ts` implements `PairingAuthority`: a short-lived base64url secret (SHA-256 verifier + `timingSafeEqual`, 5-attempt cap), CSR-proven channel key binding, a single fsynced transaction that both issues the certificate and consumes the secret, `await`-serialized operations, monotonic-clock expiry independent of wall-clock rollback, and a fail-closed fence on any write failure or unknown commit receipt so no certificate leaves on an unproven durable write. `pairing-file.ts` is a private `0700`/`0600` atomic file store with an exclusive `O_EXCL`/`O_NOFOLLOW` lease, directory fsync, and refusal of symlinked data, corrupt snapshots and unknown stale locks (no backup resurrection). It has no IPC, network, Provider or workspace-path surface; only a trusted local controller may call `begin`/`confirmLocal`/`cancel`/`revoke`.

`pair-smoke.mjs` drives the real thing end to end: the Swift `pair prove` CLI dials a host-authenticated (server-auth-only) bootstrap channel through the outer WSS relay into a Node `/pair` host wired to a live `PairingAuthority`. It exercises wrong-secret denial, pending-before-confirmation, a synthetic local confirmation, a granted certificate that then completes a real mTLS `probe.echo`, and revocation refusal (`proves=4`, `issued=1`). The local confirmation is called directly against the authority to represent the Mac user pressing approve; there is no real human, no persistent product UI and no iPhone. Passing this smoke is **not** completed device pairing.

## Enrollment interoperability (still not pairing)

The shared library can generate a software P-256 key, standard CSR and short-lived self-signed bootstrap certificate. `enrollment.mjs` verifies CSR signatures with bounded parsing and issues a host-controlled clientAuth certificate only for a matching expected fingerprint. It is an internal crypto adapter, not a remote signing endpoint. The bootstrap certificate is rejected by the authenticated echo host.

`enrollment-smoke.mjs` proves Swift-generated key/CSR → Node certificate → the same key in real NIOSSL mTLS. Native tests additionally prove the generated key is stored/read from an insert-only Keychain account before public proof leaves the service actor. No one-time pairing secret, host user confirmation or durable grant transaction is claimed. See [versions, tests and gaps](../../docs/research/scry-ios-remote-enrollment-interop.md).
