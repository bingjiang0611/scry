📝 总体评估

📋 总体评估

项目概况：Scry 是 Electron + React + TypeScript 的本地 AI coding-agent 工作台，适配 Claude、Codex、Qoder、OpenCode，并把 trace、账单、会话和 canonical records 写入本地多套存储。Node 22 下 typecheck、全部启用测试、build、macOS dir pack 与 CLI dry-run 均通过。

主要风险：普通 Markdown 外链可把特权窗口导航到不可信页面，而 preload 仍暴露全部 50 个 window.scry API；另有远端图片零点击外传、Provider 环境 secret 扩散、MCP 仓库命令执行和权限 fail-open。稳定性上存在锁 TOCTOU、不可重入 migration 与 Codex orphan turn。

亮点：shared DTO、workspace 路径/修订防护、Git hook/filter 隔离、canonical record 原子正常路径、Provider registry 与大量真实文件系统测试都做得扎实。

优先修复：先封导航/IPC/网络边界和 child env，再修 MCP trust、permission fallback、migration、锁与 Provider terminal lifecycle；之后补 Electron/交互/CI gate。

总评：4.5/10（C）。基础工程能力不差，但当前安全、迁移、并发和发布闸门不足，不应作为稳定公开桌面应用分发。

🔍 Detailed Findings

Critical Confirmed

F-01 · 不可信导航继承完整 preload，形成远端到本地文件/Agent 的权限跃迁

置信度：High类别：Security范围：BrowserWindow、Markdown、preload、IPC、workspace API
证据： src/main/index.ts:393-425,489-520；src/preload/index.ts:56-145；src/renderer/components/MarkdownImpl.tsx:1-5。Electron/CDP 将窗口导航到无网络 data 页面后，页面仍获得全部 50 个 window.scry API。
问题： 窗口允许不可信导航，preload 对每次导航继续暴露高权限桥；workspace 只比较不随导航变化的 webContents.id，且 cwd 由调用方提供。违反 4.6 Principle of Least Privilege。
为什么重要： 一次普通链接点击可变成本地文件读写、移入废纸篓与 full_access Agent 控制。
现实失败场景： 恶意 README 或模型回复给出外链；用户点击；远端脚本读取配置、修改 shell 文件或启动 Agent。
Minimal fix默认阻止非可信导航与 window.open；HTTP(S) 只交给 shell.openExternal；所有 privileged IPC 验证主 frame、精确 origin 和 main 签发 workspace token。
Better long-term fix恢复 sandbox:true，按最小能力拆 preload，建立统一 IPC authorization middleware。
Regression test · EffortElectron 点击恶意外链后主窗口 URL 不变；非可信 URL 调全部 privileged IPC 均拒绝；错误 workspace token 拒绝；预计 1–2 days
High Confirmed

F-02 · Markdown 远端图片构成零点击数据外传通道

置信度：High类别：Security范围：模型、工作区与问答 Markdown
证据： src/renderer/components/MarkdownImpl.tsx:1-5；src/renderer/index.html:1-23；ChatTurn.tsx:819,843。SSR 动态验证把远端 Markdown 图片直接渲染为 https img。
问题： ReactMarkdown 默认图片和缺失 CSP 使 Chromium 在渲染时自动请求任意域，不需点击或工具审批。
为什么重要： prompt injection 可把模型已知的代码、路径、提示词编码进 URL，也会泄露 IP/时间/跟踪标识。
现实失败场景： 恶意仓库指示模型返回攻击者图片 URL；聊天一显示就发 GET。
Minimal fix只允许受控 data/blob/local 图片；远端图片默认占位并需显式加载；补严格 CSP。
Better long-term fix统一安全 Markdown 组件和 renderer 网络 allowlist/webRequest 拦截。
Regression test · Effort三类预览注入远端图片时网络请求为零，本地附件仍显示；预计 0.5–1 day
High Confirmed

F-03 · Billing Admin 凭据进入 Provider 环境，终端继承时也进入 MCP probe

置信度：High类别：Security范围：login-shell、billing connector、Provider spawn、MCP probe
证据： src/main/index.ts:95；claude-locate.ts:41-95,458-495；providers/claude.ts:142-154；providers/codex.ts:493-511；providers/qoder.ts:50-80；providers/opencode-server.ts:120-126；mcp-config.ts:132-135。
问题： billing 与 Agent 共用完整登录 shell 环境，sanitize 不删除 Admin 变量；终端启动时 process.env 路径也让 MCP probe 继承这些变量。
为什么重要： 组织级账单凭据被扩大到项目可影响的 Provider 子进程和部分 MCP 执行面。
现实失败场景： 用户启用 Admin billing；恶意仓库诱导 Provider 命令或 MCP 读取 env 并外传。
Minimal fixbilling secret source 与 runtime env 分离；Provider 剥离 Admin/organization/member 变量；MCP 固定 allowlist env。
Better long-term fixsecret 放入 Keychain/main-only service，只在固定官方 HTTPS 请求构造时注入。
Regression test · Effortsentinel 只对 billing fetch 可见，对 Claude/Codex/Qoder/OpenCode/legacy/MCP spawn 均不可见；预计 1 day；Keychain 3–5 days
High Confirmed

F-04 · MCP 状态操作直接执行仓库控制的命令或任意 URL

置信度：High类别：Security范围：.mcp.json、MCP modal/trust panel、main MCP probe
证据： src/main/mcp-config.ts:48-90,117-231；providers/claude.ts:174-208；useIntegrations.ts:233-277；App.tsx:832-848。
问题： 打开/刷新/测试/启用 MCP 可直接 spawn enabled command 或 POST 任意 URL；Guard 是并列按钮而不是前置 gate。违反 5.3 No Hidden Side Effects。
为什么重要： 用户只想看状态也可能执行仓库代码、泄露环境或访问内网。
现实失败场景： 用户打开陌生仓库并点 MCP；恶意 command 立即执行。
Minimal fix以 canonical cwd + config fingerprint 建立授权，显示 command/args/env key/source；变更即撤销；Guard 前置。
Better long-term fixprobe 使用最小环境、资源沙箱和网络策略，静态配置/扫描/执行分离。
Regression test · Effort未授权 sentinel 脚本在打开/刷新/测试/启用时均不执行；精确授权后才运行，修改字段后失效；预计 2–4 days
High Confirmed

F-05 · 运行控制不可用时 fail-open 到 full_access

置信度：High类别：Security范围：renderer run controls、shared normalization、Provider adapters
证据： src/renderer/hooks/useIntegrations.ts:416-451；src/shared/runtime.ts:216-246；providers/registry.ts:51-59；agent-runner.ts:90-105；providers/qoder.ts:50-68。
问题： 旧 preload、IPC reject、no-data 或缺 permissionMode 都可能落到 full_access，并映射为 bypassPermissions/dangerously-skip-permissions。
为什么重要： 控制面故障反而扩大执行权限，违反 4.4 Fail-Fast 与 4.6 Least Privilege。
现实失败场景： Provider 升级造成 capability 漂移；下一轮自动绕过审批。
Minimal fix全部缺省改为 default；无法确认权限时禁用发送；legacy bypass 需显式确认。
Better long-term fix版本化权限状态机，权限只可经用户动作单调升级。
Regression test · Effortreject/no-data/旧 preload/缺字段均不得产生 full_access，只有用户主动选择才出现 bypass 参数；预计 0.5–1.5 days
High Confirmed

F-06 · Renderer 把缺失证据渲染成绿色安全或真实零

置信度：High类别：Security范围：MCP Trust 与 Diagnostics
证据： McpTrustPanel.tsx:43-63,100-122,183-198,479-505；preload/index.ts:81；DiagnosticsView.tsx:217,258-270。
问题： partial unknown 报告缺 status/severity/offline 时显示 policy-pass/online/0；stats 缺失显示 0 轮/0 token。
为什么重要： 安全 UI 假阳性可诱导用户运行不可信 MCP，诊断零值会掩盖加载/存储故障。
现实失败场景： CLI/renderer 版本漂移返回 partial payload，面板却显示未发现阻断项。
Minimal fix共享严格 schema；缺必填字段显示 unknown/error；Diagnostics 区分 loading/absent/error/true-zero。
Better long-term fix所有观测 DTO 带 freshness/completeness，renderer 不猜事实。
Regression test · Effortpartial MCP payload 不能绿色，null stats 不能显示 0，明确 true-zero 才显示零；预计 0.5–1 day
High Confirmed

F-07 · 陈旧目录锁回收 TOCTOU 可让两个 recorder 同时提交

置信度：High类别：Stability范围：canonical recorder lock 与 sequence
证据： src/core/turn-recorder/io.ts:60-113；store.ts:68-126；recorder.test.ts:1254-1286。
问题： 恢复者先判断 stale 再无条件删除目录；A 取得新锁后，B 可依据旧判断删掉 A 的锁，双方进入临界区。
为什么重要： canonical sequence 可冲突、记录覆盖或永久丢轮。违反 5.4 Shared Mutable State Synchronization。
现实失败场景： 崩溃留锁后两个并行 agent 同时完成 turn 并回收。
Minimal fix采用可靠跨进程锁；或 recovery mutex + 不可变 owner token CAS。
Better long-term fixsequence/recordId 再受数据库 unique constraint 或原子索引约束。
Regression test · Effort双进程 barrier 强制同时判 stale，断言 maxActive=1、sequence 唯一且 verifyStore 通过；预计 1–2 days
High Confirmed

F-08 · SQLite migration 非事务、非重入，中断可永久降级

置信度：High类别：Stability范围：scry.db schema migration
证据： src/main/db.ts:86-134；span-ledger.ts:16-65；docs/product/billing-guardian-issues.md:141。
问题： DDL 逐条执行后才更新 user_version；未 guard 的 ALTER 重跑会 duplicate-column，initDb 捕获后 db=null。
为什么重要： 一次崩溃/掉电可让分析、账单和 span 数据库每次启动都失败。
现实失败场景： 列已添加但 version 未更新，重启重复 ALTER 并永久降级。
Minimal fix每版本在 transaction 内执行 DDL+version；ADD COLUMN 前检查 table_info。
Better long-term fixmigration journal、升级前备份、integrity check 和自动恢复演练。
Regression test · Effort每条 DDL 后注入中断，反复重开最终都收敛 v7；列已存在+旧 version 可重入；预计 0.5–1 day
High Confirmed

F-09 · Codex RPC 超时可能留下无人追踪的真实 turn

置信度：High类别：Stability范围：Codex app-server lifecycle
证据： src/main/providers/codex-app-server.ts:53-124；providers/codex.ts:1083-1160。

Better long-term fixclient request id、恢复查询、显式 cancel 和多阶段 health。
Regression test · Effortfake server 延迟 initialize/turn/start，断言 child 清理、重初始化且无 orphan turn；预计 1–2 days
High Confirmed

F-11 · app-sessions.json 非原子写入，损坏后静默清空

F-12 · 附件无大小上限、重复持久化并在删除后残留

置信度：High类别：Performance范围：attachment、trace archive、privacy deletion
证据： src/shared/runtime.ts:295-319；src/main/index.ts:116-126,293-315,618-634；transcript-archive.ts:73-164,213-235。
问题： 只限 8 张、不限字节；原始 blob 与 base64 双存；每轮全量读写 session JSON，累计 O(n²)；delete 不清所有 store。
为什么重要： 大图/长会话阻塞 main、放大 RSS/磁盘；敏感数据在用户以为删除后仍可恢复。
现实失败场景： 多个 10 MB 图片持续几十轮，每轮重写全部历史，删除后附件仍在。
Minimal fix单图/总请求字节上限；archive 只存 metadata+blob ref；删除清所有 Scry-owned store并明确 .scry 保留。
Better long-term fixappend-only/SQLite turn store + content-addressed blob/refcount/retention/GC，重 I/O 移出 main。
