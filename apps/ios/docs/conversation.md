# Conversation reading

Behaviour and verified evidence of the shared conversation reader: positioning and
freshness, the Markdown block renderer, tables, and the screenshots that covered them.
Moved verbatim out of `apps/ios/README.md` on 2026-10-26 so the positioning section can
be corrected without growing a file that already exceeds the repository 20 KB
single-file gate.

Visual verification (2026-09-15): v5 was built and launched on the iPhone 17 Pro simulator. Home/pair/new-task plus live-chat and transcript layouts were replayed from the **DEBUG-only** harness. Chat verification covers rendered Markdown, collapsed/expanded reasoning, collapsed/expanded long tool output, compact short tool results, attachment bubbles and the Composer. The launch arguments (`-uiPreview [-connected] -route home|new|chat|pair|settings|transcript [-uiMockData] [-uiMockSlash]`) affect screenshots only; they are not authentication, and mock conversation data is compiled out of Release builds.

Conversation positioning and freshness: opening a session starts at the latest message, including history whose Markdown finishes parsing after layout. Tail positioning observes committed content geometry, not the background reader's placeholder size. Long prose is split into block-level rows, so no lazy row is thousands of points tall: a Markdown entry longer than 600 characters is parsed into one row per block, the parse runs in a background task, and until that result exists the entry keeps its original single row. Cache entries are keyed by turn identity plus entry index and versioned by the exact source text, bounded at 64 entries and 2,000,000 retained characters, so the reader body never hashes, compares or parses full text; while a live reply streams, only the entry that changed is parsed again and a cancelled parse publishes nothing. Each split carries a cheap version token: the id of the entry's last source line plus its UTF-16 length (archived entries use their page revision and entry index). `coalesce` keeps the output count and only replaces the last line with a new seq and longer text, so the token is what decides whether a split is still current. While a live entry is behind its token, the reader keeps the parsed prefix blocks stable and renders everything from the last parsed block's start to the current end as one tail row taken from the CURRENT text — an append-only chunk can never leave the previous reply on screen, and the entry never flips back to a single giant row. Text that was replaced or shortened drops the split until a fresh parse lands. Table rows, fenced code blocks and reasoning stay inside their own entry row. An accepted send restores tail-following even when the reader was browsing older messages. While following the tail, source-version changes fetch a fresh recent window (even after loading a full cache or older pages); old and new snapshot pages are never concatenated. While reading older messages, keep that snapshot and position, then reconcile immediately on “回到最新”. Earlier turns remain available through the older-history controls after rebasing. DEBUG `-uiMockLongOutput` plus `-uiMockFirstScreen` cover long live/archived replies; `-uiMockMacStartsLater` runs the same freshness decision against a full cached base.

Markdown tables: live assistant output, reasoning and archived replies share the native block renderer. Pipe-delimited tables retain headers, left/center/right alignment, inline Markdown and escaped pipes. Cells wrap at a readable 220pt column width; wide tables scroll horizontally. Short rows are padded and surplus cells ignored, following GFM. This remains a small conversation parser, not a full CommonMark engine (nested block tables are not supported). `-selfTest` checks parsing; `ConversationUITests.testMarkdownTableInLiveOutputAndHistory` uses DEBUG `-uiMockMarkdownTable` / `-uiMockMarkdownHistory` fixtures to check rendering and horizontal gestures without a relay or Provider.
