# LLM 性能截图评审

## 结论与范围

底子不错，但“看见数据”还没有变成“快速判断”。不需要重做配色或换风格，应该先处理统计层级、图表识别和运行状态。

评审基于用户提供的截图，核对 src/renderer/components/LlmPerformancePanel.tsx、llm-performance.css、src/shared/llm-performance.ts 与 designs/scry-llm-token-speed/brief.md。采用 PRODUCT.md adaptive 平台的 Assessment A 单评审路径，没有运行 web detector。未操作当前 App；交互、键盘和读屏表现不作通过判断。artifacts/llm-performance-dark.png 是较早界面，不能代替用户当前截图。

## 值得保留

- 彩色曲线与模型色点对应一致，适合多模型对比。
- 中位数与分布带比只有平均值更有用。
- 暗色表面、克制边框与强调色符合诊断工具定位，不需要增加视觉装饰。

## 优先问题

| 优先级 | 问题 | 具体改法 |
|---|---|---|
| P1 | 同一模型出现两套速度：顶部平均 21.0，下方中位 29.8；首 token 为 8.6 秒和 4.2 秒。当前运行会话和所选时间范围的分区不明确。 | 顶部明确归为“运行中”，下方归为“24 小时模型对比”。保留两套数据，让统计对象先于数字被看见，不合并为一个指标。 |
| P1 | “多种状态”没有告诉用户三个会话是在生成、执行工具还是等待。 | 直接显示真实状态数量，例如“生成 1 · 工具 2”。具体会话放入展开详情，避免只靠悬停发现。示例数量不是当前会话事实。 |
| P2 | 曲线与模型名称距离远，读图需要来回找颜色；速度分布色带和竖线也没有就近解释。 | 在图表附近增加紧凑模型标识，或曲线末端标注名称；分布列用按需提示解释 P25–P75 与中位数，不增加常驻说明段落。 |
| P2 | 运行中统计说明横穿图表上方；关键列标题、坐标、单位较弱。“91 + 3 运行中”换行拖慢扫读。 | 统计说明收进就近提示，保留必要临时数据标识。轮数明确区分已完成与运行中，给该列足够宽度，提高关键辅助文字可读性。 |

## 必须保留的设计与剩余风险

连续曲线、空闲落到零轴是用户已确认的 v9 设计，不得擅自改回断线。零轴容易被读成速度为零；在首 token 模式下甚至容易被读成等待为零。源码已区分绘图高度和真实测量，空闲悬停显示“空闲”，不是统计造零。建议增强空闲段与测量段的视觉区别，保留连续性；本轮没有修改。

Claude 只有 4 轮，另外两个模型有 94、41 轮；排序不是受控评测。保留排序，不增加“最快”等结论。

外部方法论核对：https://artificialanalysis.ai/methodology 。其 Output Speed 从首 token 后计时，TTFT 另计；Scry 既有输出速度包含请求等待。采纳速度与等待分开展示，不直接套用不同统计口径。网页仅定向提取相关定义，不声称完整阅读。

## 认知负荷、情绪与用户视角

重度用户（Alex）会在 21.0 和 29.8 的关系处停顿；新用户（Jordan）会卡在“多种状态”和分布带；低视力用户（Sam）可能难读弱化文字，实际对比度和读屏待单独检查。阅读路径从运行中摘要进入曲线，最后才找到模型和口径，用户获得解释较晚。应让统计对象更早被识别，不增加介绍性文案。

## 次要观察

24 小时横轴两端同为 00:21，首次阅读缺少日期锚点。属于低优先级，不能为此打乱已认可的图表结构。
