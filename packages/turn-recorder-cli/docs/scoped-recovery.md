# 按会话恢复

只处理一个保留的 Qoder 会话时，必须同时指定 provider 和原始 session ID：

```bash
scry recorder recover --workspace "$WORKSPACE" --provider qoder --session-id "$SESSION_ID"
```

目前只支持 Qoder。缺少任一参数、空 session ID 或其他 provider 均明确拒绝，不退回整个工作区恢复。不带这两个参数的原有 `recover` 仍处理整个工作区。

## 隔离范围

- 只恢复目标会话的 open 和 inbox；持久身份必须与请求一致。
- 只投递属于目标会话的正式记录。成功投递保留独立 receipt，不推进共享 ACK 游标，也不重试其他会话的通知。
- 损坏或无法判定身份的正式记录不能当成“非目标”跳过。错误保留在日志中，并使定向通知恢复失败。
- 工作区 health 和错误日志仍可更新。返回的通知 backlog 是工作区总量，不是目标会话的数量。

通知队列支持首次使用状态或已迁移的 v2 状态。若存在尚未合并的同身份 legacy ACK，或 isolated v1 状态，定向投递会拒绝隐式迁移。只有在操作者另行确认可以处理**整个工作区通知**后，才执行原有 `scry recorder notify-drain --workspace "$WORKSPACE"` 完成迁移，再重试定向操作。已被 v2 吸收的旧 ACK 文件可以原样保留，不必删除。

## 不能恢复什么

该命令缩小操作范围，不重建丢失的开始事件，也不推断历史轮次边界。执行前应备份原始数据并检查身份、终态和轮次边界。若多个轮次的事件已经混入同一 open，不能仅凭命令能提交就认为恢复正确；应保留现场，不人工补造事件或手动改写账本。

命令可能已提交目标记录、随后才在通知阶段失败。先读回记录和 receipt，再决定下一步；不要把非零退出当成“什么都没写”，也不要把零退出当成完整恢复证据。
