# 018: Recover remote Desktop reads without guessing about writes

**Status:** Accepted (documents existing behavior)

Keep SSH addressing separate from the pinned Scry host identity; accept explicit coordinates, not aliases or arbitrary SSH flags. Refuse a run-protocol version mismatch rather than silently mixing protocols. Negotiate capabilities separately: older hosts may have one of fork/delete, lack trace deltas, or lack host-owned directory selection. Cached Provider metadata is not a current auth or capability proof. Scope fresh controls to the requested Provider, profile and directory. The host validates the repository, prepares the worktree and reauthorizes the directory for each explicit workbench call or continuation. After a lost reply only allowlisted read-only calls may be retried automatically.

Observation time and publication sequence are separate; monotonic sequence is not a wall clock. Missing questions or terminal results mean unknown. Local attention derives from the client's connection baseline; do not present it as host evidence or send it to the host. A local-scope grant may request a recently settled run's retained trace, while a device gets no live run after settlement. Oversized history and trace responses use lossless bounded byte chunks and a separate assembled-size cap. A trace delta applies only to an exact base revision and item count; any mismatch requires a complete snapshot. Only a delta-aware snapshot carries a revision for the next update.

The local App frame adapter does not own a socket, credentials, or run state. A malformed reply is not empty success. Treat an unclassified or possibly written request as unknown; retry a proven unsent write or use the same replayable intent ID, never a replacement prompt. Adoption can return an inline snapshot or an authorized trace address; a refusal is distinct from absence. A question answer is proven only by the host's answered or duplicate receipt. Encode omitted positional arguments separately from explicit null so forwarding preserves the handler contract.

Recording a submit is not execution. Main owns the durable pending receipt and downstream intent ID; keep any upstream phone identity separate. A lost outcome must not be retried with a new ID. Reconnect or recovery can find acceptance or fence the original ID, not resend a prompt or stop an accepted run. Keep the original diagnostic bounded and omit the payload. A missing long-poll change hint is not proof of no change. For a run started by another device, use the host run ID for stop and answer; use the bound Scry run ID for trace.

A remote run's catalog-write notice prompts a local session-list refresh; it does not focus or start a local run. Question attention exposes bounded counts, not transcript content. A duplicate start receipt reuses the run ID from the first accepted command.

Remote and local conversations can share `ChatView`, not the runtime or its evidence. The remote host owns Provider setup, credentials, files and history; if it is offline, unknown or forgotten, keep the draft and block send rather than falling back locally. Do not present a missing archive as a missing session while the initial poll or the live trace is still pending.

Let the host long poll wait for changes; the renderer’s inter-request gap is not the freshness budget. Back off quiet replies. Follow an external run on the first report that names it and read its first trace window immediately. For the same displayed run, coalesce trace reads behind a minimum interval: the live-set revision may not reflect new content, but reading on every change report amplified load. Name the outdated endpoint when refusing a protocol version. Worktree progress comes from the host status subscription, not a faster renderer poll.

Refresh the remote control catalog without replacing the user's model, effort or permission selection. Keep an unavailable selected Provider visible without substituting another. A trace delta with a gap or reset requires a fresh snapshot. A foreign run can finish between the first history read and the live lookup; refresh the archive and catalog when that happens. Terminal `runStatus` can retire a receipt, so reconcile App-owned queues even after the view has changed and refresh history before the final trace read. Reconcile once more without relying on another host event. A receipt is not proof of dispatch; only matching host run state clears that wait. Resolve an unknown receipt by its original ID, not by resending the prompt or stopping the run.

Keep the displayed run and its host revision together so polling continues from the visible snapshot. A context switch clears prior evidence; adopting the returned session retains its accepted run. Publish late control observations only for the exact Provider, profile and directory that requested them. Keep same-context choices while refreshing, but discard a failed observation. Settle stop and answer routing against the run that owns the current session on the host. An unknown host receipt blocks every composer on that connection, even in another context, and takes precedence over freshness messages. Stale or refreshing host evidence also blocks sending. An earlier run's state cannot clear the current receipt.

Remote prompt queues belong to the App, not the current view. Track an in-flight prompt by message ID because draining may skip an edited row. After a submit throws with unknown delivery, retain the claimed row and hold later prompts; never resend based on a missing reply. The current UI asks the operator to remove the unknown row, but the queue guard refuses that action ([#179](https://github.com/bingjiang0611/scry/issues/179)).

Only the primary enrolled App can receive and complete forwarded execution-target work; the daemon does not own the App's stored Desktop credentials. An absent App yields gateway-only discovery and a clear refusal for targeted calls. A replacement poll supersedes the older poll; a still-open control lane is not proof that work is being read. Keep the forwarding deadline longer than the downstream watch/status wait and give submits a separate budget for receipt persistence. Reserve frame headroom so a too-large reply can fail the pending call explicitly rather than leaving it to time out. Test disconnect and recovery, wrong-owner replies, and queue saturation separately.

Daemon session actions preserve the workspace and grant checks used in-process. Device deletion requires explicit confirmation and an archived session. Workbench shell actions require an active primary App; validate paths before forwarding. Test refusal with a live poll and check that no work was queued.
