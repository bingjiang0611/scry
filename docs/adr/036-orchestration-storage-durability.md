# 036: Commit orchestration evidence atomically and fence indeterminate writes

**Status:** Accepted (documents existing behavior)

The event sink commits events, projections, command receipts and effects together. A bulk startup import can use one transaction without changing rollback semantics. A failed observer must not invalidate an already committed command. Set effect policy when enqueuing. Hash client intent, not the newly allocated run ID, so a retry of the same command can return the original receipt. A resolve-absent write permanently records absence rather than allowing the same intent to arrive later. Usage is not orchestration event evidence. Obtain conversation ordinals from the authoritative conversation file instead of inventing them from the shadow projection.

Inline bodies at or below 16 KiB. Authoritative submission persists larger bodies in the private content-addressed store before committing a reference. Pin a prepared body until the commit completes so concurrent session deletion cannot unlink it. Preserve inline intent for non-dispatched runs whose snapshots may be rebuilt from the database. Session deletion writes a tombstone, removes projections and effects, and redacts old previews in one transaction. Only then unlink bodies no longer referenced. Pruning retains the latest event per stream and updates the replay floor atomically; command receipts survive pruning.

Use a local database. The pre-open check refuses detected network filesystems, using statfs on Linux and a type-filtered `df` query on macOS; this is detection, not proof of locality. Acquire the exclusive SQLite lock even when there is no migration to run. Check integrity without rebuilding a corrupt file. Default to `synchronous=FULL`, `fullfsync=ON` and `checkpoint_fullfsync=ON`; callers can override the last two for shadow mode and experiments. Schedule passive WAL checkpoints off the commit path rather than letting auto-checkpoints delay commits. SQLite needs to cycle through DELETE journaling to release an exclusive WAL lock for an independent checkpoint connection. Preserve the original open failure if cleanup also fails.

If write outcome is indeterminate, fence further storage access rather than claiming rollback or accepting more commands. Stop is tightening-only: it can still interrupt live runs and cascade through their in-memory parent edges without accessing SQLite. Verify replay from an empty projection against the online projection, including revisions. Check both transaction fault injection and genuine SQLite `SQLITE_FULL` using the page cap; reopening must show no partial events or projections. A local directory probe and a forced network result do not constitute an actual network mount test.
