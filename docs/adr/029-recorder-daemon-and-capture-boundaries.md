# 029: Keep daemon acknowledgements and capture boundaries explicit

**Status:** Accepted (documents existing behavior)

The recorder daemon supports older installed hooks on the legacy route. The versioned route refuses a mismatched version before reading or applying the event. A completed refusal that proves non-application can permit fallback; an unknown result cannot. A wake acknowledges a request to inspect the inbox, not processing or delivery. The capture guard and fallback CLI share the same versioned document and payload validation; the shell uses the daemon to avoid a Node launch per hook. An optional caller PID describes observed ancestry, not required identity. See [ADR 004](004-recorder-hook-delivery.md) and [ADR 028](028-recorder-inbox-replay.md).

The launcher and listener need separate ownership locks: the launcher waits for the child, while direct listeners and workspaces can request the same endpoint. Publish the short socket hint only after listening; hash the requested endpoint as well as the workspace, and use a short directory when the temporary directory does not fit. Keep ownership until socket removal and wait for background delivery before shutdown. Deliver committed records after responding to the Provider; durable delivery state covers interrupted work. Startup can prune stale temporary files independently of commit-time cleanup.

Idle update policy belongs to the caller, not the offline recorder core. Do not race the bounded update steps with another timeout that abandons supervision. Recheck idleness after the update callback: work arriving during it still needs the current daemon.

For capture, the host marker is the enable switch; recorder state exists for recovery, idempotency and stop boundaries. Validate workspace, configured capture storage and matching session identity before queueing a claim; the current preparation checks regular-file metadata, not actual transcript readability ([#159](https://github.com/bingjiang0611/scry/issues/159)). Persist the host-supplied callback when the claim is prepared, because the daemon and receiver do not inherit that environment. Repeated claims preserve their boundary; replay under the existing session lock instead of retaking it. A capture hook can wait for its pending claim, but an unclaimed ordinary session contributes no evidence and should not retry. Stop freezes the transcript boundary and prevents the next turn from recording; other sessions are unaffected. Discover newly edited repositories from pre-write evidence.

Exclusions affect only diffs. Resolve existing absolute paths once so symlink aliases agree; preserve nonexistent declarations. A repeated claim can only add exclusions. Persist the union in session state first, then repair the published context and open turn even if the union already appears in control state. A missing baseline does not deactivate an otherwise active claim.

Keep the wire shape stable: the Provider hook payload stays unchanged, task identity is verbatim or null, and client identity is distinct from the capture source. Report invalid, unsupported and unavailable as exit codes 2, 3 and 4 respectively. Publish receiver and inbox coordinates instead of requiring the host to infer paths. External inbox writers must obey the advertised lock, marker and atomic publication contract before asking the daemon to wake.
