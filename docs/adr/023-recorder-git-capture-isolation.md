# 023: Capture Git evidence without mutating the repository

**Status:** Accepted (documents existing behavior)

Turn and session baselines at the same moment must not be captured independently: concurrent external changes can make the two disagree. Share the immutable baseline object store through alternates, but give each capture independent scratch space, index and operation queue. Keep the baseline store alive until the final reference is released, including a retained segment baseline used by later processes. Explicit commit and frozen-segment baselines do not snapshot the current worktree. Write after trees into the capture's own object store, not the repository. Final capture can publish its after tree as the next segment's baseline; a shared recomputation must not publish another capture's tree. Serialize preview and final reads within each capture because temporary indexes share names.

Read layout and porcelain status in parallel; status supplies the observed HEAD and the clean-baseline fast path when no explicit exclusion changes its meaning. Reuse a baseline index only when the captured index identity still matches and the reusable index represents the before tree. Sparse rules are per worktree; only absence of the rules file makes that check negative. On ambiguity, use the reset path so skipped entries are not reported as deletions. Explicitly exclude visible or tracked paths, but do not give Git exclusions for already ignored paths: adding the exclusion can otherwise make Git reject an ordinary snapshot. A bare repository or non-repository is not a worktree.

Repository location is optional evidence about the live worktree, not about a frozen diff baseline. Start a root request's location sample alongside layout and status. Use only evidence available at the capture boundary rather than waiting for metadata. Fall back to packed refs only when the loose ref is missing; an unreadable ref is not proof of absence. Reject origin paths that URL parsing would reinterpret. The [location contract](../../packages/turn-recorder-cli/docs/evidence-limits.md) describes the supported Git layout and the difference between detached and unknown. Mapping fixtures read real Git metadata before injecting the observation so they do not depend on I/O winning a race against the capture boundary.

Parse patch framing with stable Git command options, NUL-delimited path records and hunk counts, not repository display config or quoted headers. Pair raw metadata and numstat from one Git read; preserve type-change and binary handling. Match literal paths without a directory-prefix fallback, and pass each pathspec as one argument. Keep patch capture batched and bounded by file count, argument bytes, time and content budget; attempt a single long path rather than dropping it. Do not recapture paths already denied by policy or untracked-file limits. Remove batch files after use: preview captures may outlive many reads. Recorder capture can retain complete patches before projecting bounded previews; the workspace inspector is read-only and has a separate bounded policy.

The targeted fast path must agree with the full isolated snapshot. A clean baseline plus a trustworthy clean status can skip discovery and use the existing commit as the end tree. Otherwise seed from a proven equivalent index or reset to the before tree. Refresh to uncover hidden index entries and recheck conversion configuration at finish. Keep the discovery index immutable for overlapping views; an empty candidate set can reuse it. If discovery cannot prove equivalence, fall back to a full snapshot. Do not run repository filters or trigger lazy network fetches for observational reads. The separate direct workspace inspector must refuse when staged attributes or index flags change its interpretation; exceeding its limits is unavailable, not a clean diff. Derive review context from the same tree pair as patch totals.

Query untracked status only for additions. The current index-query fallback retains patches, but may bypass the untracked patch-count budget; [#160](https://github.com/bingjiang0611/scry/issues/160) tracks preserving the manifest without unbounded classification. Exclusions keep only the hit paths and counts, never patch bodies. Clean up isolated capture stores only once no surviving snapshot or segment owns them.

Discover new linked worktrees only at finalization and within the original capture scope. Read only the bounded first HEAD reflog line. Compare its full one-second interval with the turn window and require a valid creation record, existing Git link and checked-out index. Never treat an unreadable or unprovable baseline as a real diff. When the first entry cannot prove creation, directory timestamps can only filter candidates that predate the turn or leave a possibly new candidate unavailable. Prefer known baselines in deterministic path order; capture at most eight, preserve excess as partial, and report at most 32 candidates. Begin and finish use the respective turn budgets; a failed secondary worktree capture stays partial rather than failing the turn.
