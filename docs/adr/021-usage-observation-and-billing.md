# 021: Keep measured speed, recorded usage and account billing distinct

**Status:** Accepted (documents existing behavior)

Billing can belong to a custom upstream; do not derive it from a model name. Qoder credit evidence selects sources by the actual runtime, not just the billing provider. Match native prompt and request identities and parent links, not timestamps or prompt text. Keep request-set identity distinct, cache ancestry resolution, and ignore cumulative totals, fork copies and replay. Deduplicate stable requests. Missing amounts may converge; conflicting known amounts stay unknown. Missing identity must not turn message blocks into multiple charges. A run-scoped meter retains only usage, not bodies. The estimate covers matched main requests, not an account bill. [Issue #154](https://github.com/bingjiang0611/scry/issues/154) tracks handling malformed rows separately from an incomplete final line.

Qoder's base-plan USD equivalent comes from individual subscription tiers, not cash paid: add-ons, bonuses and taxes alter effective prices. Without published token rates for auto-routed tiers, missing credits remain unknown. Keep estimation and attribution visible on all clients; credits may be attributed to a billing provider rather than a model.

Speed uses either SDK API time or observed completed main-agent request intervals, not network bandwidth or server telemetry. Include first-content wait only for calls with an aligned signal. Preserve evidence coverage even without timing. Failed or stopped rounds do not enter distributions. Read the bounded run observation (not its full trace), then replace it with persisted evidence at completion. Observer freshness differs from poll time. Cross-project rows are per Agent and known model, with unknown models separate; metrics use independent arithmetic session means and measured-session denominators, not combined or call-weighted throughput.

Claude continuation results are cumulative; other supported results here are increments. Wall-clock bounds use the envelope of valid result intervals, not a sum that double-counts overlaps. Missing canonical bounds prevent a full-turn wall-clock claim. Tool wall time uses the observed call/result span; missing long-task support must not become zero. Performance payloads crossing IPC contain numeric aggregates, not content.

Pi metering includes abandoned branches, but only exact archived user identities establish ownership. Keep copied fork observations under their original session. Read topology and metering without retaining message or tool bodies, and memoize ownership rather than whole ancestry paths. Keep a valid JSONL prefix when the last row is unfinished; reject corruption inside completed rows. Untracked users can be external continuations. Attribute only observations after the previous message; an older charge does not establish that a later response was metered.

USD rollups exclude credit amounts; credit reconciliation carries a unit. Add only usage estimates that do not overlap canonical USD cost, and calculate them on read rather than rewriting historical evidence. SQLite remains the structured source when a best-effort JSONL write fails. Performance rows share retention and deletion with usage rows but do not count as billing turns. For a performance append, advance only a cache matching the pre-append file identity and size; otherwise rescan. Run IDs can recover ownership of unattributed legacy rows but cannot override a different complete session identity. Retain corrupt rows without claiming ownership.

The V16 repair is insert-only. Recover only Scry-persisted results for managed sessions and preserve existing canonical costs and provenance. Existing per-model usage cannot prove exact reasoning counts or original cost provenance.

The App and daemon reuse billing handlers. In daemon mode the daemon owns the ledger. Resolve the login shell before reading Admin API configuration. Synchronization and fixture import are writes and must not replay after a lost reply; paginated sync uses the long lane. The normal suite injects billing functions and makes no real Admin API calls. [Real reconciliation tests](../../src/main/billing-admin-real.test.ts) are opt-in (`BILLING_ADMIN_REAL=1` plus an explicitly authorized provider credential), use temporary in-memory SQLite, and must not print or persist credentials. An unavailable native SQLite binding degrades billing evidence rather than preventing App startup.

Observe raw text deltas before coalescing; snapshots and subagents do not contribute. Without aligned Provider API time, pair tokens only with their own observed call intervals. Whole-turn usage includes failed or retried calls and cannot supply that numerator. Historical performance uses a bounded streaming read and the same deletion ownership as the usage journal; missing measurements stay unknown. Share concurrent scans and invalidate on append or file replacement. An Antigravity transcript may supply observed model attribution, but an absent, oversized or unreadable sidecar leaves the original sample unchanged. Retry recent unresolved rows because the usage append can precede the terminal archive.

Antigravity ACP usage observed with `agy 1.5.12` counts input, cache reads, cache writes and output separately; thought tokens are already included in output. ACP reports neither the actual answering model nor cost. Missing token evidence is unavailable, and reported usage from cancelled, failed or subagent turns is partial. Transcript attribution is separate: parse only complete rows in the bounded read. The timestamp has second precision; multiple candidate user inputs make attribution ambiguous even when the output counts match.

After a terminal notice, a visible turn can lack its result or Qoder credit evidence because the view missed live delivery. Backfill the missing terminal evidence from the archive by event ID, without overwriting events already present or treating missing billing data as zero.

In the usage chart, a missing day or metric breaks the line; an isolated observation is a point. Keep observed Provider rows even when the amount is unknown. Show that a partial total is a lower bound next to the value, not solely on hover.
