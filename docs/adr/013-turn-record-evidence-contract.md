# 013: Keep missing evidence and negative evidence distinct in turn records

**Status:** Accepted (documents existing behavior)

Turn records are consumed by the CLI, reporting systems and older readers. Do not infer an observation from a missing field. Keep the required and optional sections in the shared contract; a missing optional section is unavailable, not an empty result. Diff producers publish machine-readable omission codes in the same order as their reasons; consumers must not parse human prose to recover a code. Accept early schema-v1 evidence that omitted `omissionReason` for backward compatibility. For diff baselines, overlap and exclusions, see [ADR 012](012-diff-evidence-and-attribution.md).

- **Tools and hooks.** Human wait is not tool execution time. A call with a human intervention ID refers to the question, and the intervention owns its duration. New hook records preserve failures individually; older records may carry a collapsed failure count. Keep the correlation ID of an unmerged failed run, not a made-up ID for a group. Preserve exit codes verbatim (including `-1`); command text does not override the observed outcome. Quote bounded Provider error text without interpreting it.
- **File access and content.** One status per path and operation distinguishes confirmed access, reported failure, rejection before execution, and unobserved result. Only confirmed access counts for new records. A legacy record with no status keeps the earlier interpretation. Transcript evidence refers to the immutable bytes used for parsing. Reassemble full model segments from ordered content references; inline text is bounded. Full steer attachment payloads stay in the archive, while records keep their identity. Discovery covers observed request directories, not every repository on disk.
- **Usage and identity.** Credits are independent of dollar cost and have their own coverage. Canonical dollar cost is non-negative and fits DECIMAL(20,8). A Pi credential and a native Qoder invocation do not borrow each other's usage sources. A logical model tier is not a native model ID. Only `observed` permits treating the model as fact, with provenance; incomplete, conflicting or unobserved models need a reason, not a guess. Legacy absence makes no claim; usage provenance describes a billed model, not necessarily the requested model. Task association and turn roles come from explicit structured evidence, never prompt text. Unknown roles cannot count toward a main-agent denominator.
- **Capture and completion.** Attach capture provenance only to an explicitly claimed session. Keep its source verbatim and distinguish it from the observed client app. An absent claim means ordinary recording. A managed run can end without a Provider terminal. Treat completion and duration as exact only if termination evidence supports that; late events such as the next prompt do not establish the previous turn's end. The observation timestamp is separate, and pre-0.2.38 records lacking termination make no claim about its quality.

Aggregate tool, skill and MCP records into mutually exclusive sections, retaining the Agent category for schema-v1 compatibility. Preserve source order and metadata even after body budgets are exhausted. For hook dispatch-only evidence count the deliveries without inventing script identity, outcome or duration. Collapse equivalent successes, never individual failures, and carry a denominator for mixed or unknown results. Hook invocations sharing one tool ID may still be distinct lifecycle stages. Keep per-run credit snapshots separate from charges and never sum them with result shadows. Confirmed file access dominates repeated negative evidence for the same operation; when only negative evidence exists, retain the more informative explicit refusal. A child response is not the root answer, and admission is not another logical turn.

In Overview, missing structured Skill evidence is not proof that no Skill was used. A risk observation is not proof that execution was blocked.
