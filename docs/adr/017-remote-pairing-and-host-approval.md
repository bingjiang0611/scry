# 017: Keep device approval local and distinct from transport

**Status:** Accepted (documents existing behavior)

The local pairing screen needs the short-lived, single-use code and host trust anchor so a device can reach and verify the host. Do not expose the stored verifier, private keys, or issued client certificates to that screen. The relay code is absent when no relay route is advertised. This does not rule out a separately configured Desktop connection. A device proves possession first; the operator then confirms its displayed fingerprint. Keep revocation in durable host state even when the UI omits revoked devices. Relay counts only cover the host's own connections and do not prove relay-side capacity or availability.

Host CLI support and permission to approve via CLI are separate. The feature defaults to enabled unless explicitly switched off; the approval switch itself defaults off and requires native App confirmation. Readers had to accept approval provenance before writers published it. With the feature off, do not expose its switch or admin socket or write approval provenance. A notice may record the operation and a display-only fingerprint prefix, not secrets, invite strings or private keys. Managed provider and terminal environments carry a marker to prevent accidental host-admin operations; this is not a sandbox.

Host administration authenticates each request over a local-only socket with a one-use private challenge. The client validates the opened file rather than trusting the path. Check protocol version before issuing a challenge, consume it on a verification attempt, and clean abandoned challenges at startup. Sanitize method names in logs and omit invitation contents. Keep CLI cancellation and revocation available when approval is off, but do not allow invitation or approval. Persist approval and invite rate counters so a daemon restart cannot restore the quota; count attempts, not successful approvals. Unreadable or unsafe admin state does not enable approval. An unavailable admin listener does not prevent the regular App channel from serving.

Invite secrets stay on the interactive terminal, not in JSON output. Approval requires a matching fingerprint prefix and explicit confirmation; the terminal test checks both rejection through a pipe and provenance through a real PTY. Strip terminal control characters from untrusted display labels. The CLI does not take over a stopped daemon when asked for status. A restart requires confirmation when run count is nonzero or unknown. A daemon running without its admin endpoint is still running; point the operator to its diagnostics instead of reporting it absent.

The App channel uses a Unix socket, not a TCP listener. Keep the state directory owner-only before binding, then verify the socket mode. Refuse an overlong path rather than silently binding elsewhere. Filesystem isolation and mTLS authorization are independent: a completed handshake does not authorize a revoked grant. Use the same protocol version gate as the network endpoint. The App reuses the host controller and TLS material but uses the local transport scope; a local grant is not valid on the device network endpoint.

App enrollment bootstraps the certificate on a separate local socket. It requires an owner-only secret and proof of possession of the CSR key, not a second pairing dialog. Validate the CSR before spending the secret and spend it before issuing the grant. Use a bounded, single-request exchange with machine errors rather than echoing CSR contents or exception details. The secret does not age out while waiting for an App after login; it rotates on use or daemon restart and is normally absent while a local grant is live.

A confirmed reconnect stops the verified daemon and leaves a fresh one-time request for the next start. The request contains no secret and grants nothing by itself. Reject stale, invalid or non-private requests and consume the request once. Successful re-enrollment replaces the previous local grant. Without a valid local credential the App must surface reconnect, not wait for a launch that cannot restore it. The [credential-loss regression](../../src/daemon/host-process-lost-credential.test.ts) uses daemon disposal for the restart; it does not test PID verification or signaling.

Remote host enablement is one dependency-light rule shared by App, daemon and CLI. An unset value permits remote access in packaged builds, not in development. Report disabled rather than presenting an empty ready host.
