# 034: Test recorder optimizations against independent evidence

**Status:** Accepted (documents existing behavior)

## Git capture

Compare targeted capture with a full isolated snapshot on an independently prepared twin repository. Compare the after tree, file metadata and patch bytes, using repository-relative paths. Assert that capture never writes to the real index or adds objects to the real store. Fixture mutations may change those files on purpose; take comparison stamps around the capture, not around the mutation. Strip host Git config, templates and repository-locating variables so Git runs only against the fixture.

A new turn must see changes made between turns, including same-size edits with a restored mtime, commits, checkout and stash. Fix fixture timestamps and require a positive check that the racy-clean fixture really fools a stat-only check. Exercise sparse paths, linked worktree rules, stage changes, attributes, filters and gitlinks. The filter fixture installs its side effect after making the baseline commit. A sparse-rules lookup error other than absence must take the conservative path. Validate reusable index contents against the actual before tree, using both the repository and the capture's object store. APFS coverage uses valid multibyte filenames, not invalid UTF-8. The raw/numstat oracle compares the combined parser against the older independent Git calls, including type changes and binary counts.

A bounded depth frontier is discovery metadata, not evidence of missing diffs. Actual Git/read failures still degrade evidence; exercise those failures without replacing the downstream Git, aggregation and canonical store with fake records. The patch-count limit must preserve manifest entries and tracked patches, and per-claim exclusions must not erase a repository nested inside the excluded material directory.

## Content custody

Mirror the receiver's content and envelope checks independently of the sender. Count base64 and JSON escaping, including an inline-only record. Prove crossings of both byte and distinct-reference limits without changing evidence priority. Retained references must read back locally, not from an implicit App store. A clipped body without a reference is no longer exact; JSON content must remain valid or be explicitly omitted. Same length is not proof of matching bytes. Repair keeps damaged existing bytes and skipped files intact; dry-run reports the same classification without mutation.

Copy crash fixtures prove recovery at publication boundaries, not power-loss behavior. A Vitest timeout does not cancel its promise; join and reap only registered fixture children.

## Recorder lifecycle and recovery

Use sanitized Provider wire rows to cover behavior the recorder cannot infer from normalized events. Preserve the native identifiers, order and timestamps that matter; test duplicate receipts, omitted fields and unsupported shapes explicitly. In Qoder child logs, null or missing parent IDs alone do not invalidate a child with a separately proven parent. Oversized rows are cut at complete line boundaries, without claiming any bytes past the budget. Codex compaction has a top-level-only fixture without a terminal event. A transcript-denial fixture faults the filesystem syscall, not its retry wrapper; the superseding prompt must survive both persistent and transient denial. A cache oracle compares against a cold scan, ignores random event IDs, and covers repeated prompt text and replacement of a cached line.

Capture tests use the real claim document, external inbox publication and both transport paths. A late baseline, even if valid, cannot cover the interval before capture. Freeze a turn before its successor writes and do not let a replayed synthetic start or post-stop prompt create another turn. For a continuation, native Qoder wakes carry a new request ID but belong to the same human question. Compare each sealed segment's work and shared capture identity without attributing the Provider transcript file to the repository. Keep provenance distinct from a real-host acceptance claim: controlled clocks and process evidence prove only the exercised transition.

For recovery, backdate the observed event and transcript files as well as open state. Silence, missing ancestry, and tool waits are not termination evidence. Advance only the intended clock or lock deadline, not unrelated I/O timers. A true terminal keeps its verdict even when its evidence becomes partial. Assert recorder ACK behavior against durable receipts, not timing or callback output read too early. Test a lost outcome separately from an absent record, including compacted hole samples that must not count the same sequence twice. Test exact payload hashing with bytes that differ from a re-serialized record. Managed recovery must retain live and unknown owners, and an explicitly interrupted or abandoned provisional state must not block other work.

Fault the relevant filesystem operation while leaving production locking, replay and storage in the path. Use separate processes for native lock contention and wait on observable fixture state instead of arbitrary sleeps. A local waiter must still check the current filesystem owner and keep its original deadline. Bound test time for durable I/O: the periodic-rebuild case intentionally performs 64 real recovery passes and exceeded the default five seconds on shared CI storage; the larger test timeout does not alter production lock deadlines. Cover synchronous and callback-based process-table failures; both leave liveness unknown.
