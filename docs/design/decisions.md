## 侧栏「动态」的加强（2026-10-21）

范围是 `SidebarActivity` 与 `sidebar-activity.css` 呈现的侧栏动态列表；项目视图、标签栏、行交互、文案模块和证据语义不变。此前的平铺文字仍保留，只把「哪个时刻正在发生」做成整块列表的峰值：

| 决定 | 理由 | 落地 |
| --- | --- | --- |
| 分组标题成为「幕」 | 整屏只有等高灰色文字时，用户无从分段 | 标签 + 通栏细线（`--border3`）；进行中的标签与线更亮（`--fg` / `--border2`），已完成的标签降到 `--dim` |
| 右侧状态列 | 运行状态原先只藏在标题扫光里，右列只有已完成图标 | 进行中的旋转环与「需要回复 / 已完成」图标居中对齐；悬停或聚焦时让位给操作按钮 |
| 修正强调反转 | 运行中的标题原本比已完成更暗，最重要的工作是最淡的文字 | 运行中标题回到 `--fg`，扫光带改为向中间调调制（深色里像阴影、浅色里像高光），已完成标题为 `--dim` |
| 完成段更密 | 归档是检索对象，不是当前工作 | 已完成行 28px、运行中与需要回复行 34px |

保留的既有决定：无卡片、无数量徽章、无项目副标题；动态标题与项目列表保持相同字号与字重；每组 40 行上限、布局动画、指针按住不漂移、`prefers-reduced-motion` 与强制颜色回退均不变。

验证：隔离 Electron fixture `node scripts/session-capability-ui-smoke.mjs --sidebar-activity-only` 通过全部检查，其中新增三项针对本次设计承诺（运行中标记与状态图标同列、完成段行高更小、运行中标题亮度高于完成段）；把行高改回 34px 或把状态环移出该列后，对应断言会失败。深浅主题在 280px 侧栏宽度逐张查看，运行中扫光仍以像素差确认可见。未保留其他临时测量脚本。

## 总览证据块：横向刻度（2026-10-22）

范围是 `OverviewPanel` 面板头到数据标签页之间的证据块：上下文占用、判词行、Token 总量与派生指标、会话摘要。轮次列表、证据语义与控件行为不变。设计稿先出四稿（`designs/scry-overview-bolder`，A 环 + 通栏卡片 / B 台账 / C 横向刻度 / D 单峰），用户选定 C。

| 决定 | 理由 | 落地 |
| --- | --- | --- |
| 占用改用横向刻度 | 58px 环与 16px 数值同级，占用率读不出主次；环还占 66px 高度 | 一行「上下文占用 … 26%」，8px 轨道按 26% 填充，下面一行「已用 / 窗口」13px（已用 `--fg`，窗口 `--dim2`）；显示文本仍是「已用 / 窗口」 |
| 阈值跟随判词 | 占用接近窗口上限是要人介入的状态，不该只在环上换色 | 轨道填充沿用既有阈值：≥50% 用 `--warn`，≥80% 用 `--bad`，其余 `--accent` |
| 指标去卡片 | 三格等高卡片读作同级，380px 下还空出一格 | 一条发丝线起头：主证据行左右分置（标签 10px、数值 26px `--accent`），下面并排两格由一条竖线分隔，不再有卡片底色和圆角 |
| 让出一个峰值 | 会话压缩计数 20px、标签页填充胶囊都比证据本身响 | 计数 14px；标签页去掉填充与内描边，只留 `--selected` 下划线；面板头说明降到 `--dim2` |
| 判词行保留状态点 | 状态要能一眼读出，不能只是灰字 | 判词 13px/620，7px 状态点配 2px 同态软光环（复用面板标题写法） |

保留的既有决定：未新增颜色、字体或组件原语；缺证据仍显示 `—`；隐藏 tooltip、aria 文案、会话摘要的 ID 展开/复制与失焦回退、标签页的 tab 语义与键盘往返都不变。文案「上下文占用」「暂无上下文数据」移入 `OVERVIEW_SESSION_COPY`。

验证：`npx vitest run src/renderer` 849 项通过；`npm run typecheck:web` 通过；`node scripts/session-capability-ui-smoke.mjs --overview-only` 深浅两主题 × 380/340/535 通过，`firstTurnTop` 430.34（契约 ≤460，比上一版矮约 19px）、`headerHeight` 44、间距 14/10/8、双列、三格指标、无横向溢出；`--summary-only` 通过（`.ctx-copy` 文本仍为「100.0k / 272.0k」这类原样比值，改用 `.ctx-track` 后 aria 校验同步更新）。另用临时 fixture 渲染真实数值（26%、70.5k / 272.0k、1.7M、$31.81）逐张比对深浅主题与三种宽度，并确认空态（— + 空轨道 + 暂无上下文数据）。对比度：轨道填充与底色 5.72:1（深）/ 3.72:1（浅），单看填充与面板底色的 3:1 图形下限通过；主证据数值 5.72:1 / 3.72:1（26px）。已知限制：指标标签仍是全应用约定的 10px `--dim2`，浅色主题 3.52:1，属既有标签色决定，本次未改。

## 已回答问答块：台账式记录（2026-10-23）

范围只有 `AskUserQuestionResult` 渲染的 `.question-result` 内层块：状态行、问题与答案、`查看原始输入与输出` 折叠。外层工具组行、工具卡行与待回答的内联表单都不动。设计稿先出四稿（`designs/scry-question-result-bolder`，A 裸渲染现状 / B 倒置 / C 台账 / D 单行），用户选定 C。

前置事实：这块从 `ab5601b` 起就没有任何样式——`.question-result*` 规则在该提交里从 `styles.css` 整段删除且没有补回，真实界面渲染的是浏览器默认的 `<dl>`（上边距 1em）、`<dd>`（缩进 40px）与 `<summary>`。所以这一轮是重建而不是再加一层装饰。

| 决定 | 理由 | 落地 |
| --- | --- | --- |
| 状态与等待压成一行等宽小字 | 「已回答」是判词，问题数与等待是附注，三者不该占同等视觉重量 | `--ok` 10px/650 等宽配 11px 对勾图标（未完成类判词改 `--bad` 与预警图标），问题数与等待 10.5px `--dim2`，等待靠右 |
| 问答成行、答案落在右轨 | 问题与答案同行才读得出对应关系；短答案需要锚点 | 两列 grid（`1fr` / `minmax(84px, 38%)`），问题 12.5px `--dim`、答案 13px/600 `--fg` 右对齐；等待时长与答案共用同一条右边缘 |
| 只用发丝线分隔 | 旧版（已删除）给每条问答套了 `--panel2` 卡片，与工具卡形成嵌套容器 | 块顶、列表顶、行间、折叠前各一条 `--border3` 发丝线，无新容器、无新圆角 |
| 窄栏退化为上下两行 | 右栏打开时两列会被挤到读不出对应关系 | `@container main-pane (max-width: 640px)` 转单列，答案改左对齐 |
| 缺答案单独标记 | 「没拿到答案」不能与「用户选了某项」同形 | `dd.missing` 用 `--dim2` 与 500 字重；没有 duration 时不渲染等待 |

保留的既有决定：判词文案（已回答 / 用户取消 / Provider 取消 / 未完成）、`<dl>/<dt>/<dd>` 语义、`question-result-fallback` 与 `<details>` 折叠、`aria-label` 都不变，未新增文案与颜色。原始输入输出区沿用 `--surface-inset` 底、11.5px 等宽与 280px 上限，与 `.tool-detail` 同一写法。

验证：`npx vitest run src/renderer/components/AskUserQuestionDialog.test.tsx` 14 项、`src/renderer/components/render.test.tsx` 244 项通过；`npm run typecheck:web` 与 `npm run build` 通过。新增 `node scripts/session-capability-ui-smoke.mjs --question-result-only`：在隔离 Electron fixture 里用真实 React + 真实 CSS 断言 `dl` 不再带浏览器边距、行是两列 grid、答案 600 字重右对齐、等待与答案右边缘相差 ≤1px、判词取 `--ok` 变量而非字面色、取消态渲染 `dd.missing` 且不编造等待、`summary` 可键盘聚焦且展开后箭头旋转、560px 容器下退化为单列左对齐；把本轮 CSS 注释掉重跑该检查会失败（已作为对照执行一次）。深色与浅色截图（`SCRY_QUESTION_RESULT_SCREENSHOT`）各看一次。已知限制：右对齐的长答案（如 4 行）左侧参差，这是台账方向的已知代价；桌面打包版内未用真实会话重放（需要一次真实 Provider 的回答），本轮只做到隔离 Electron fixture 与真实 CSS。

## 设计系统地基：尺度 token 与债务棘轮（2026-11-15）

范围是桌面 renderer 的全部 CSS。目标是把“风格不连续”从靠评审发现，变成由测试持续约束；本轮不改变任何可见外观。

| 决定 | 理由 | 落地 |
| --- | --- | --- |
| 字号收敛为 8 档 scale | 审计时共有 26 种字号，其中 10.5／11.5／12.5／13.5 等半像素字号与相邻档位只差 0.5px，读不出层级 | `--text-2xs` … `--text-2xl`（10／11／12／13／14／16／20／24px），旧的 `--text-supporting-size`／`--text-compact-size` 改为别名 |
| 字重收敛为 4 档 | 审计时共有 17 种数值字重（400 … 720，含 510、520、530 等相邻值） | `--weight-regular`／`medium`／`semibold`／`bold` |
| 间距落在 4px 网格 | 网格外的 5／6／7／9／10／14px 等约占间距声明的一半 | `--space-*` scale；1px 发丝线与 2px 光学补偿是唯一例外 |
| 债务只降不升 | 一次性重排全部界面无法逐一验证；但新代码不应继续增加债务 | `design-system.test.ts` 按文件比对 `design-system-baseline.json`；`npm run design:audit -- --write` 只允许写低 |

等价迁移：在 scale 上的字号与字重字面值（含 `font` 简写）由一次性脚本替换为 token。验证方式是反向替换——把 token 换回原字面值后与迁移前的 69 个 CSS 文件逐字节一致，主题文件只多出新增的 token 定义；因此计算样式不变。

初始基线：网格外或 scale 外的字号声明 272、字重 119、间距值 1329、裸颜色字面值 145。这些是后续分批偿还的起点，见 DESIGN.md「迁移路线」。

## 按钮收敛：Button 与 IconButton（2026-11-15）

范围是渲染进程里所有“执行动作”的文字按钮与纯图标按钮。选择器触发器（`.wdbtn`、`.clibtn`、`.location-button`）表达当前选择而不是执行动作，不在本轮范围；弹窗关闭继续使用 `ModalCloseButton`。

收敛前的状态：`.btn` 在两个文件中各定义一次，后定义的覆写了 hover 与主按钮文字色；另有 `.hosts-button`、`.mp-button`、`.turn-branch-btn` 三套文字按钮和 `.iconbtn`、`.mp-icon-button`、`.icon-button` 局部覆写、完全没有样式的 `.icon-btn` 四套图标按钮。尺寸从 28px 到 40px 不等，圆角有 `--r-sm` 与 `--r-md` 两种，Meta Prompts 的主按钮用反色（`--fg` 底）而非强调色，危险按钮有实心红、红字、`!important` 浅红三种形态。

| 决定 | 理由 | 落地 |
| --- | --- | --- |
| 一个组件、四个 variant、两个尺寸 | 视觉差异来自重复实现，不来自真实的语义差异 | `Button`：primary／secondary／quiet／danger × md 32px／sm 28px；`IconButton`：md 32px／sm 28px |
| 默认 32px，不再是 40px | 40px 按钮配 12px 文字在密集的工具界面里过重；与图标按钮、输入框的高度体系一致 | 弹窗按钮从 40px 降到 32px；对话工具栏、文件编辑栏、后台任务、分支按钮用 sm |
| 填充按钮文字用 `--fill-fg` | 深色主题下白字在强调色上只有 2.75:1、在危险色上 2.94:1；深色字分别为 6.65:1、6.22:1 | 新增语义变量：深色主题 `#151515`，浅色主题白色 |
| 危险操作统一为实心红 | 三种形态让用户无法从外观判断后果 | 删除会话、移除项目、移除主机、删除提示词、放弃编辑都用 `variant="danger"` |
| 默认 `type="button"` | 三个对话框里的按钮未写 type，放进 form 会触发提交 | primitive 默认 button，表单主操作显式 `type="submit"` |
| 图标按钮必须有名字 | 文件面板的 4 个图标按钮只有 `title`、没有 `aria-label` | `label` 为必填参数，同时生成 `aria-label` 与 `title` |

附带修复：终端录制历史弹窗的关闭按钮此前是浏览器默认样式且紧贴标题，底部两个按钮之间没有间距；改用 `ModalCloseButton` 并补上与其他弹窗一致的头尾布局。删除了 TSX 中已无引用的 `.gp-actions .btn`、`.wc-browse .btn` 覆写。

守卫：`Button.test.tsx` 断言 primitive 的输出、`.btn`／`.icon-button` 只在 `styles-buttons.css` 定义、退役类名不再出现、TSX 不再手写 `className="btn…"`；手写一个 `className="btn primary"` 的负对照会使该测试失败。设计债务基线随之下降（字号 272→269、字重 119→117、间距 1329→1311、颜色 145→144）。

验证：在 Playwright Chromium 中用构建后的真实 CSS 静态渲染 10 个真实组件（项目重命名与移除、会话重命名、工作区新建文件、终端录制历史、Meta Prompts、远程主机、对话删除与迁入、文件面板）和 primitive 画廊，深浅主题各拍前后对照。Electron 内的交互、键盘焦点与 UI smoke 未在本地运行（容器以 root 运行，Electron 拒绝在不加 `--no-sandbox` 时启动）；smoke 脚本中引用旧类名的选择器已同步更新，需由 CI 的 UI smoke 验证。已知限制：浅色主题主按钮白字在 `#3f7ee8` 上为 3.92:1，低于 4.5:1，属强调色本身的取值，本轮未改。

## 通知与标签页收敛：Notice、Tabs、Segmented（2026-11-15）

## PR CI 发现的两处行为回归（2026-11-15）

macOS 打包后的 smoke 在 PR 上报出两处由本次收敛引入的行为变化，均已修正：

1. **标题栏按钮失去 `no-drag`**。给容器级按钮规则统一加排除条件时，`styles-macos-window.css` 里让标题栏控件退出窗口拖拽区的规则也被加上了 `:not(:where(.btn, …))`。结果顶栏和侧面板顶栏里的 Button／IconButton 落在拖拽区内，点击会变成拖动窗口。这条规则只设置 `-webkit-app-region`，是行为而不是样式，已恢复为覆盖所有按钮。审计改为：只设置 `-webkit-app-region`、`pointer-events`、`user-select` 的容器规则不要求、也不应排除 primitive；`design-system.test.ts` 另加一条直接检查标题栏规则的测试，并用反向修改确认它会失败。静态渲染比对没有发现这个问题，因为它不带 `data-platform='macos'`，也不比对 `-webkit-app-region`。
2. **减少动态效果时按钮颜色过渡被关掉**。`styles-buttons.css` 在 `prefers-reduced-motion` 下写了 `transition: none`，而全局约定是把过渡缩短到 `--duration-reduced`、保留颜色反馈（动效 token 检查要求 `.btn` 的背景色过渡仍为 150ms）。已删除这段覆盖。
3. **Meta Prompts 详情栏失去纵向布局**。清扫无引用类名时删除 `.mp-row .mp-icon-button { margin-right: 4px; }`，前缀 `.mp-row` 残留并拼到下一条规则上，`.mp-detail { display: flex; flex-direction: column; … }` 变成了不匹配任何元素的 `.mp-row .mp-detail`。详情栏退回块级布局，正文不再在栏内滚动，页脚按钮被推到视口之外（1024×653 下底边在 1881px）。已恢复 `.mp-detail`，并以 `.mp-row > .icon-button` 补回复制按钮的 4px 右边距（按钮迁移到 IconButton 后丢失）。随后把每个样式表相对 main 新出现的选择器逐条核对，其余均为有意的迁移（标签页、`.notice-body`、去掉无效成员的 `:where()` 列表、终端录制弹窗布局），没有第二处拼接。416 个渲染片段里没有 Meta Prompts 详情页，所以逐元素比对没有覆盖到它。
4. **总览与能力弹窗的标签页键盘模型改变**。main 上侧栏、Skills 弹窗与 diff 导航的标签页已经是“只有选中项在 Tab 顺序里、方向键切换并选中”（roving tabindex，WAI-ARIA 推荐写法），总览数据标签与能力弹窗的种类标签则是两个都能 Tab 到、按 Enter 选中。Tabs 原语统一为前者，因此后两处的键盘行为有意改变：Shift+Tab 不再停在未选中的标签上，改用左右方向键。总览 smoke 原先按旧模型断言“Shift+Tab 到达轮次标签、Enter 选中”，已改为用原生方向键输入断言同样的结果（焦点与选中回到轮次标签、面板显示），并额外断言未选中标签不在 Tab 顺序里。侧栏 smoke 早已用方向键驱动同一个原语并通过。

## 浮层层级 token（2026-11-16）

## 菜单 primitive（2026-11-16）

六套命令菜单（Agent 选择、Provider 过滤、侧栏会话菜单、侧栏项目菜单、文件区右键菜单、右侧 Surface 菜单）各自定义容器和条目：条目高度 35／36／40px，圆角三种，内边距 8 或 12px，键盘支持从“完整”到“没有”不等。按[参考案例对比](references.md)的结论收敛为 `Menu` primitive 与单一的 `styles-menus.css`。

- 方案选择：自写，不引入 Radix 等依赖。现有菜单已经共享开关状态（`usePickerOpen`、`useMenuDismiss`）、进出场动效（`usePresence`）和各自的定位方式；依赖库会连同这些一起替换，改动面和行为风险都更大。缺的只是统一的条目合同、按首字母跳转和打开时聚焦。
- 外观：容器内边距 4px、条目 32px（与 `Button` md 同档，Radix 与 Primer 的默认值），文字 13px、前景色，危险操作红色。Chromium 中按真实祖先结构渲染五个菜单，深浅主题下容器与条目的计算样式一致。
- 键盘：方向键循环、Home／End、按首字母跳转，只在启用的 `menuitem*` 之间移动。侧栏项目菜单和文件区右键菜单原先没有方向键，现在有了，并在打开时聚焦第一项；侧栏会话菜单和 Surface 菜单原有的方向键处理改由 primitive 提供，各自只保留 Esc／Tab 关闭。
- 其他：文件区右键菜单补上可读名称，危险项前加分隔线，“重命名”“移入废纸篓”改用对应图标；侧栏会话菜单的“迁入已捕获历史”补上图标（同一菜单图标要么全有要么全无）。
- 不并入：diff 范围菜单（虚拟列表子菜单）、工作区选择器（带搜索的列表）、工作目录与位置选择面板（`role="dialog"`，行内有移除按钮）、slash 命令与模型／权限弹出面板。Agent 菜单里 Pi Profile 行的移除按钮违反“菜单里不放行内按钮”，留待后续把 Profile 管理移出菜单。
- 守卫：`Menu.test.tsx` 检查输出结构与键盘函数，并拒绝在其他样式表定义菜单容器与条目、拒绝手写 `role="menu"`（上面的不并入项除外）。两条守卫都用负对照确认会失败。
- 未验证：真实窗口中的键盘操作与菜单 smoke（依赖 CI）。
