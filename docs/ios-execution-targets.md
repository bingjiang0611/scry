# iOS execution targets · implementation contract

User authorization: phone pairs only with Mac1; it may use Mac1's existing approved desktop connections to read/run on Mac2. Interaction A aggregates sessions. No extra phone-to-Mac2 pairing, no new SSH endpoints from the phone, no arbitrary proxy, no recursive forwarding. This extends the existing owner authority explicitly for this task; Mac2 authenticates Mac1, not the phone. Mac1 can read forwarded content. Final workspace/trust gates remain on Mac2.

## Frozen wire contract

Discovery (unwrapped, to the paired Mac1):

```json
{"op":"executionTargets"}
```

```json
{"executionTargets":{"version":1,"gateway":{"hostId":"host-uuid","label":"Mac1"},"targets":[{"id":"existing-opaque-desktop-connection-id","binding":"64-lowercase-hex-sha256","hostId":"mac2-host-uuid","label":"Mac2","state":"connected"}]}}
```

`state` is the existing desktop connection state (`connected` / `disconnected`), not a fresh reachability promise. Pending pairing is not an execution target. Mobile v1 bounds discovery at 32 targets; exceeding it returns `execution_target_capacity_exceeded` rather than silently truncating. Upgrade to paged discovery before supporting larger catalogs. No secrets/SSH coordinates in this response. Gateway name is display metadata; identity remains hostId + CA/grant binding.

Local Mac1 requests keep the routing envelope unchanged; history carries the explicit display scope and execution Profile described below. Remote requests use:

```json
{"op":"target","target":{"id":"opaque-id","binding":"sha256"},"request":{"op":"sessionsPage","cursor":0,"limit":100}}
```

Forwarded replies preserve the original mobile response body and add the binding stamp:

```json
{"sessionsPage":{"sessions":[],"cursor":0,"total":0,"hasMore":false,"snapshot":"..."},"executionTarget":{"id":"opaque-id","binding":"sha256"}}
```

Errors retain `{"error":"code"}`; no success is accepted without the matching stamp. Target routing uses the same phone mobile operations, NOT desktop history/catalog wrappers. This preserves native history/preview capabilities and existing mobile frame/page bounds on Mac2.

Allowed existing mobile operations: projects, directories/directoriesPage (authorized roots only), providers, commands, sessions/sessionsPage, sessionAction, history/historyPage/historyPreview/historyVersion/historyTurnsPage, workspace (existing mobile read-only query only), submit, intentStatus, poll, watch, liveRuns, runState, output, questions, answerQuestion, stop. Validate each request with existing contracts or a narrow parser. Reject target/executionTargets nesting, pairing/lifecycle management, desktop/desktopDirectory/desktopWorkbench, arbitrary fields/URL/SSH/executable proxies. Do not forward phone deviceLabel/keepAlive authority metadata to Mac2.

## Authorization, identity, and writes

Every discovery/target call validates the verified upstream phone peer grant. Target lookup and the final send recheck existing desktop connection + hostId/CA/grant identity. `binding` hashes the connection identity and granted credential generation (not route/label); reconnecting the same grant retains it, re-pairing/CA/grant changes invalidate it. A disconnected target is not automatically reconnected by a phone request. No local fallback. Recheck upstream authorization after awaited reads and immediately before writes; never promise to retract an already dispatched downstream write.

Do not use DesktopRemoteClient.submit() afresh for each phone retry: it generates a new UUID. Extend the existing encrypted desktop receipt with origin `{phonePeerFingerprint, phoneIntentId, targetBinding, payloadHash}` and stable downstream intent ID. Persist before dispatch. Equal origin reuses the downstream ID; changed payload rejects. A deterministic namespaced UUID is acceptable if persisted in the existing receipt and payload conflicts remain checked. No second local Provider execution or turn record on Mac1. Existing desktop unknown-receipt fencing/retention remains intact. Late results and all IDs are interpreted within the target binding. Preserve recorded/unknown/terminal semantics.

## iOS state and recovery

Conversation selection and new-task selection are separate. Switching a new task's execution host selects that host's draft, resets project/Provider/model/permission choices, and leaves the original conversation and its draft on the original host. Home search, pins and project grouping operate over scoped session rows, not a second unscoped catalog.

Each target store has immutable routing. Its durable directory includes the gateway's phone grant and final-host binding. History caches and conversation drafts additionally include Provider/Profile/session identity. Local catalog/outbox names remain compatible. History keys include a session-display protocol generation, excluding old profile-filtered caches; old files are not used as a fallback. Directory/file/diff/status/HTML reads use that same target-bound store, including read-only transcript views; they never construct a default Mac1 client from global pairing preferences. The pooled transport registry retains at most 67 sessions; evicting a tunnel does not cancel a durable host intent. Discovery admits 32 current targets; at most 64 current/retained bindings are kept. A full retained set fails explicitly; unresolved stores are not evicted to make space.

Question-sheet identity includes gateway grant, target, session/Profile, run and question ID, so repeated question IDs cannot reuse another context's answer state. An unreadable target recovery index blocks pairing replacement/unpairing and is not overwritten by fresh discovery; recovery must be repaired explicitly. The index is bounded at 256 KiB.

A forwarded host/gateway error cannot prove an earlier attempt did not execute. Local grant/credential loss is also uncertain rather than proof of nonexecution. Keep the original intent, payload, Profile and binding in the protected outbox, mark it uncertain, and stop automatic submission. “核实发送结果” only queries that original target; no receipt means still unknown, not permission to clear or redirect the message. A target catalog authorization error is shown against that target; it does not automatically ask the phone to replace its Mac1 pairing. Pairing replacement and unpairing are blocked while any target has unresolved work. A new phone grant cannot reuse the old target's store.

## Session display and execution Profile

Maintainer decision, 2026-10-21: mobile conversation display must retain the complete Mac session, including old/fork turns with unknown or mixed Profile provenance. Current phone requests explicitly send `historyScope: "session"`; replies must echo that scope and retain the target binding. Old hosts without scope proof fail explicitly rather than silently falling back. Phone history cache keys use a new session-display generation.

The host binds provider + canonical cwd + native session ID + requested execution Profile to the authorized catalog. Session display does not filter durable turns by Profile or backfill missing provenance. `agentProfileId` still scopes live overlays and execution; stop, approvals, resume, attachment and trust checks are not widened. Catalog cwd aliases and legacy provider/native-ID normalization match the public catalog.

Claude display uses its transcript/archive authority. Pi display shares the desktop native-branch/archive reconciliation helper. The live registry owns in-flight native tails; a native read failure preserves intact archive content and reports that native history could not be verified. Stable source metadata serves version/watch probes without reparsing the whole native file. Session projections are coalesced and cached by source revision, with two sessions, a 256 MiB aggregate budget and two concurrent builds; larger histories need an on-disk projection index, not larger IPC frames. Older turns remain accessible through existing lazy pagination; a capacity failure is not a successful truncated history.

Legacy requests without `historyScope`, or with `historyScope: "profile"`, retain strict Profile reads and `historyProfile` response proof. New terminal archives still record effective `agentProfileId`; null proves default and absence remains unknown. Strict runtime evidence/image readers still reject unproven provenance. Desktop remote archive display also explicitly requests and verifies session scope, with the same catalog binding; its historical images are authorized against the exact canonical session/turn, not a guessed current Profile. Corrupt archive collections fail instead of silently dropping turns. No unknown old turn is relabeled from a directory name, current preference, or target Profile.

## Explicit file downloads

Maintainer selected phone preview plus original-file download/export, not a transparent dynamic website proxy. `fileDownload` is a separate owner-only operation; existing project directory browsing and UTF-8 workspace reads retain their containment rules. An explicit file link resolves through the existing canonical single-file authority, including home, absolute external and symlink targets. Only regular files are downloaded. No type is executed or blocked by extension.

Mac-local HTTP(S) links are fetched at the original URL/path/query on the selected Mac, never inferred as workspace paths. Requests are GET-only, loopback-pinned, carry no ambient cookies/authorization/proxy configuration, and allow at most five same-origin redirects. GET can still have effects on a local service; it occurs only for an explicitly opened link, never an automatic HTML subresource. Standard HTTP gzip/deflate/Brotli encodings are decoded as a browser would.

Opaque transfer IDs bind peer and canonical workspace. Authorization and file identity are rechecked on every chunk; changed files fail instead of mixing bytes. Chunks are 256 KiB; eight transfers/two per peer, two-minute idle expiry, eight-second HTTP open/read deadlines, and host teardown close streams. Local files are not buffered whole or limited by format/whole-file size. The phone writes to a private temporary directory, validates offsets/IDs, cancels on target changes, and removes partial/dismissed downloads.

Supported formats use native phone preview; unsupported formats remain available through Save/Share. UTF-8 source is locally paged in 64 KiB windows. HTML runs in nonpersistent WebKit with network blocking and read access only to the selected download directory. It is an offline document snapshot: external assets, API calls, forms, WebSockets and full website interaction are not supported. Native iOS format support, readable Mac permissions and available phone storage remain necessary.
