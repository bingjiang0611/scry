# B4-F2 supervisor 余项：确定性启动失败不再重试

返回[批量状态](../STATUS-BATCH4.md)。

## 问题

`STATUS-BATCH3.md` 后续事项第 3 项：`remote_lease_owner_alive`、`remote_lease_identity_unverifiable`、`daemon_recorder_cli_unavailable` 这类启动失败，daemon 以 exit 1 退出，supervisor 按异常退出重试 4 次；同时 reason 正则只匹配 `daemon_` 前缀，于是 failure 文件里没有原因。

这些状态都要求人处理（有人持有 lease、身份无法核实、打包缺少私有 CLI），退避等待不可能自愈。

## 修法

新增 `src/daemon/startup-failure.ts`：

- `EXIT_DETERMINISTIC_STARTUP = 4`。
- `classifyDaemonStartupFailure(error)`：错误消息**完整匹配** `^(?:daemon|remote)_[a-z0-9_]+$` 时返回 `{ code: 4, reason: <code> }`，否则 `{ code: 1 }`。
- 只接受完整机器码，不做子串匹配，因此 `remote_lease_owner_alive because /Users/me/...` 这类自由文本不会被当成原因记录。

`src/daemon/main.ts`：`startDaemon` 的失败改为捕获后分类。确定性失败写机器码并以 4 退出；其他错误仍写原消息并以 1 退出。写出的内容仍然只有机器码或错误消息，不含 stderr 正文。

`src/daemon/supervisor.ts`：

- exit 4 与 exit 2 同样处理——写 `supervisor-failure.json` 后 `return { status: 'failed' }`，不重试。
- reason 提取正则改为 `((?:daemon|remote)_[a-z0-9_]+)`，stderr 仍只保留前 4096 字节且只有机器码进入结果。
