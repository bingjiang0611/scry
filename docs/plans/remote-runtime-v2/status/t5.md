# T5 协议版本硬校验

返回[执行状态](../STATUS.md)。

改动文件：

- `src/shared/desktop-remote.ts`：新增 `REMOTE_PROTOCOL_VERSION = 2`；`info.protocol` 类型从字面量 `1` 改为 `number`（版本由两端校验，不由类型假装）。
- `src/main/remote/remote-protocol.ts`（新增）：`HOST_PROTOCOL_VERSION`、`protocolMismatch(request)`（只接受与本机相同的版本）、`protocolFailure(hostProtocol, missing)`（把版本差翻译成「哪一端更旧」）、`framedRequest(request)`（给请求加上协议字段，客户端与直接说线上的测试共用）。
- `src/main/remote/inner-mtls-dispatch.ts`：`dispatchRemoteRequest` 在任何 op 之前执行版本闸门；不符时返回 `{ error: 'protocol_mismatch', hostProtocol, clientProtocol }`（`clientProtocol` 为 `null` 表示请求没带版本）。`executionTargets` 的键白名单加入 `protocol`，`target` 转发时剥掉 `protocol` 与其余传输字段（由接收端的客户端重新声明）。
- `src/main/remote/desktop-client-base.ts`：每条 lane 请求都带 `protocol`；回包为 `protocol_mismatch` 时按宿主版本抛 `desktop_protocol_host_older` / `desktop_protocol_client_older` / `desktop_protocol_mismatch`。
- `src/main/remote/desktop-client-capabilities.ts`（新增）：`validateInfo` 与 `DesktopCapabilities` 从 `desktop-client-validation.ts` 拆出（后者已到 20,000 B 门禁边缘），并加入版本校验：`info.protocol` 缺失 → `desktop_protocol_missing`，更旧/更新 → 对应方向，非整数 → `desktop_protocol_mismatch`。
- `src/main/remote/desktop-host-reader.ts`：`info` 回报 `REMOTE_PROTOCOL_VERSION`。
- Renderer：`remote-copy.ts` 新增三条文案（宿主更旧 / 本机更旧 / 版本不一致），`RemoteChatShared.errorText()` 与 `HostsView` 的连接错误都按错误码映射，区分该升级哪一端。
- iOS `experiments/remote-g0/swift/Sources/RemoteTransport/Lane.swift`：`RelaySession.protocolVersion = 2`，`keepAliveRequest` 的前缀改为 `{"keepAlive":true,"protocol":2,…}`，所以每个 lane 请求都带版本；`LaneHandlerTests`、`WireTests` 的期望字符串与断言同步更新。
