# T3 长轮询

返回[执行状态](../STATUS.md)。

改动文件：

- `src/main/remote/host-controller-watch.ts`：`LiveWatchers` 拆出 `watchRun`（含 output）与 `watchLifecycle`（不含 output），共用私有 `#watch(peer, input, includeOutput)`。`output: false` 时完全不调用 `runOutput`，返回体里也没有 output 字段（不是空页），所以输出缓存的溢出或 I/O 故障不可能阻塞生命周期。`inner-mtls-dispatch.ts` 校验 `output` 后据此分派。
- `src/main/remote/desktop-client-run.ts`：`runStatus` 改为在 watch lane 上长轮询该模式，窗口 15 s；`liveRun` 改为在 status lane 上带 `revision` 长轮询 `liveRuns`，窗口 15 s。第一个窗口例外：该 run 或该连接还没有游标/revision 时 `waitMs` 为 0，否则「打开会话」会先空等一个窗口。`liveRun` 内部取状态时 `waitMs` 为 0（live 集合刚刷新过，不再等一次）。runStatus 回包新增 `changed`：本窗口有新 ledger 事件或生命周期状态变了才为 true。
- `src/renderer/components/RemoteChatShared.ts`：`POLL_MS` 从 1500 改为 250，语义从「轮询间隔」变成「一次返回后到下一次请求的最小间隔」——等待发生在宿主侧。新增 `needsTraceRead()`：只在长轮询报告变化、显示的 run 不是当前 run、或超过 `TRACE_REFRESH_FLOOR_MS`（1 s）时读 trace。`RemoteChatControls.tsx` 用它替换每轮无条件 `followTrace`；`RemoteChatFoundation.tsx` 增加 `lastTraceRead` ref。可见性暂停、视图切换作废旧序列（`pollSequence`）、错误退避（`QUIET_POLL_MAX_MS`）都保留。
- `src/main/remote/host-controller-watch.ts`：`LIVE_RUNS_TICK_MS` 从 1000 降到 250。Mac run 没有变更信号进入 controller，只能靠这个 tick 重查；重查是一次内存快照加哈希，所以 250 ms 可接受，换来「Mac 侧变化 1 s 内到达设备」。

测试证据：

- `npx vitest run src/main` → 288 files / 2828 passed（3 skipped 为既有）。`npx vitest run src/main/remote src/renderer` → 180 files / 1678 passed。`npm run typecheck` 退出 0。
- 新增 `desktop-long-poll.test.ts`（4 passed）：
  - 空闲 run 每窗口 1 个请求（`watch` + `output: false`，首读 `waitMs` 0、后续 ≥15 s），`60_000 / waitMs + 2 ≤ 6`，即空闲 60 s 内 RPC 不超过 6 次；
  - 真实 `RemoteHostService` + 真实 TLS lane：`liveRuns` 带相同 revision 时宿主挂住请求（实测 ≥300 ms，窗口 400 ms），首个请求（无 revision）立即返回；
  - `LiveWatchers` 层：Mac run 集合在 50 ms 后出现新 run，等待中的长轮询在 1 s 内返回新 revision 与新 run；
  - 未知 run 的生命周期 watch 回 `{ error: 'unknown_run' }`，回包里没有 output，trace 中也没有 runId。
- 修改既有断言（用意不变，换成新的线上形状）：`desktop-client-catalog.test.ts` 的两处 stub 从 `runState`+`poll` 改为一次 `watch`（并断言 `output: false` 与游标前进）；`desktop-client-real-host.test.ts` 把「宿主从未收到 watch」改为「收到的 watch 全是 `output: false`」，`outputReads` 未调用仍断言；`desktop-client-connection.test.ts` 的畸形回包用例改为 `watch` 形状，并新增「状态从 settled 变 unknown 算变化、同状态窗口过期不算变化」。
- `scripts/desktop-remote-ui-smoke.mjs`（默认全部 scenario）与 `--session-parity-only`、`--session-lifecycle-only`、`--unknown-receipt-only --negative-unknown-receipt-control` 全部通过（含 `dispatchNoticeLifecycle.pollErrorRecovery`）。

自审中发现并修正的问题：`runStatus` 首读若也等窗口，测试与「打开会话」都会先空等 15 s，改为无游标时不等待；`changed` 不能用「刚返回过」判断，否则窗口空转会触发无谓的内容读。

已知限制：

- 「宿主发生变化后 1 s 内拿到更新」在本机实测为 tick 250 ms + RTT；跨 relay 的实际延迟未测。
- trace 内容刷新对「正在跟随的他人 run」按 1 s 下限进行，比原来的 1.5 s 轮询更频繁，但只在跟随期间且会话活跃时发生。
- 毫秒收益仍未测（L1 层面：请求数从每 1.5 s 一次降为每 15 s 一次）。`npm run performance:measure` 放在交付前统一运行。
