# B4-F1 renderer UI 门禁失败：fixture 控件条自身吞掉点击

返回[批量状态](../STATUS-BATCH4.md)。

## 结论

`session-capability-ui-smoke.mjs --performance-only` 的 `Performance control obscured: #performance-empty` **不是产品遮挡**，是 fixture 自己的控件条。

证据（调试日志 `/tmp/b4f1-debug.log`、`/tmp/b4f1-debug2.log`，来自未修改的 fixture）：

| 观测 | 值 |
|---|---|
| 点击坐标 | `x=927, y=757` |
| 目标按钮矩形 | `left=853.69 top=746 width=146.16 height=22` |
| 该点实际命中 | `DIV#performance-fixture-controls`（控件条本身） |
| `elementFromPoint` 栈 | 控件条 → `.modal-overlay` → 组合器 → `.main-content` |
| 控件条 | `clientWidth=1000 scrollWidth=1430 scrollLeft=39.5 clientHeight=22 scrollHeight=25` |

控件条是 `position:fixed; height:22px; overflow:auto`。11 个按钮总宽 1430 px，超过 1000 px 视口，于是 `pointOf` 的 `scrollIntoView({block:'center'})` 让控件条横向滚动（`scrollLeft=39.5`）。macOS 的覆盖式滚动条在滚动后立即出现，并把指针命中判给滚动容器本身。按钮矩形看起来仍覆盖该点，但实际命中是容器，所以命中检测报「被遮挡」。

`.llm-perf-modal` 在栈里位于控件条**之下**，产品弹层没有盖住按钮。因此命中检测没有放宽，改的是 fixture。

## 修法

`scripts/fixtures/llm-performance-smoke.tsx`：控件条改为 `flex-wrap:wrap` + `left:0;right:0`，按钮 `flex:0 0 auto`，去掉固定 `height` 与 `overflow:auto`。控件条不再滚动，每个按钮都可直接命中。控件条仍固定在底部、截图时仍隐藏，高度变化不影响任何产品断言。

`scripts/llm-performance-ui-checks.mjs`：在开始点击前增加一条 fixture 自检——控件条若有可滚动溢出，直接报 `Fixture control strip scrolls, so its own buttons are not directly hit-testable`。这样同类回归会给出正确原因，而不是伪装成产品遮挡。
