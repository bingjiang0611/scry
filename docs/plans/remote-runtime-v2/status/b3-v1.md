# B3-V1 security smoke 失败归属

返回[批量状态](../STATUS-BATCH3.md)。

## 结论

Batch 2 记录的 `electron-security-smoke` 失败**不是代码回归**，是我在 Batch 2 门禁里用错了调用方式：不带 `--dev` 时该脚本跑的是**已打包产物** `dist/mac-arm64/Scry.app`，而本机那个产物是 **0.2.220**，源码是 0.2.237。旧产物里的 `agent:gitDiff` envelope 不带 `collectedAt`，于是断言 `gitBoundary.result.collectedAt` 得到 `undefined`。

换成 `--dev`（跑当前源码构建）后，在 Batch 2 起点、Batch 2 中途、当前 HEAD 上全部通过。

## 因此本批不修代码

没有可修的回归。要防的是复现方式，所以：

- 验证源码时用 `node scripts/electron-security-smoke.mjs --dev`。
- 不带 `--dev` 的调用校验的是**打包产物**，只有先跑过 `npm run pack:artifact` 才有意义；用旧产物跑它会得到与源码无关的失败。

## 交付门禁里的记法

`electron-security-smoke` 一项记为「通过（`--dev`，当前源码构建）」。不加 `--dev` 的那次是跑错了对象，不是未通过的检查——原始输出仍保留在 `/tmp/g6.log`，结论写在这里以免下次误判为回归。
