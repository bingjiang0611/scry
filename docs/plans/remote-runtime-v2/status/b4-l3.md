## 已决定

- **撤销后的「重新连接本机后台服务」放在设置页，与 B4-S 的 daemon 状态页一起做**（维护者 2026-11-07 答复）。在此之前开关打开时撤销只显示命名错误 `daemon_device_not_authorized`，不弹任何确认、不静默重新入网。设计 §13.2 的链路（`daemon.lock` 重验身份 → SIGTERM → 二次确认 → 新 secret → 重新入网）留到那一步实现，因此 L3 不再有未决项。

## 未验证

- **没有在真实 App 里跑过 daemon**：`SCRY_HOST_DAEMON=1` 的端到端（App 发起 run → daemon 执行 → renderer 显示）未在真实 App 中执行，只有单元/组件与帧层证据，以及 `scripts/daemon-launch-enroll.mjs` 的传输级拉起验证。
- 撤销后的重新入网流按上面的「已决定」推迟到 B4-S，因此「撤销 → 恢复可用」未验证。
- MCP 仍在 App 进程内（L4）；`daemon_capability_unavailable:mcp-auth` 只保证不再出现无排队的第二次认证。
- B4-S 的删除（开关默认打开、删进程内宿主与 App 直连 SQLite）未开始。
