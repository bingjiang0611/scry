# B4-F3 收窄 macOS 的 Scry command 兜底

返回[批量状态](../STATUS-BATCH4.md)。

## 问题

`STATUS-BATCH3.md` 后续事项第 2 项：N1 为了防 Linux `lstart` 漂移，增加了「身份不同但 command 看起来是 Scry 就拒绝接管」的兜底。macOS 的 `lstart` 是内核记录的绝对启动时间，不随校时不漂移；在那里这条兜底只会误拒。M1 只补了「pid 恰好是本进程」的特例。

## 修法

不再按平台分支，而是按**能否比较**判定：`process-diagnostics.ts` 新增

```ts
processIdentitiesComparable(recorded, observed)
```

只有当两侧都匹配同一种已知身份格式时才返回 true：

| 格式 | 例子 |
|---|---|
| Linux 精确身份 | `42:linux:<boot_id>:<starttime>` |
| macOS UTC lstart | `42:Tue Feb  2 00:00:00 2026` |

格式相同 ⇒ 身份差异是真实证据 ⇒ 按 `pid-reused` 进入原有 takeover/claim fence。格式无法识别（空串、旧记录、手工写入）⇒ 仍按 Scry command 兜底拒绝。这样跨平台读写同一 userData 也不会误接管：Linux 读 macOS 格式记录时两侧格式不同，落入保守分支。

`ledger-lock.ts` 与 `recover-dead-lease.ts` 都用这一条替换原来的 `exactLinuxIdentity` 判断，并删掉「macOS drift」的错误说法——保留的注释说明：只有无法比较的旧格式记录才需要 command 兜底。

## 先失败的测试

| 测试 | 旧实现表现 |
|---|---|
| daemon 锁：另一个 pid、可比较身份差 1 秒、command 是 Scry → 接管 | `expected 'already-running' to be 'replaced-stale'` |
| 远程 lease：同上 → 恢复 | 抛 `remote_lease_identity_unverifiable` |
| `processIdentitiesComparable` 格式判定 | 函数不存在 |

反例（旧格式记录 → 拒绝）在同一批里保留：

- daemon 锁：`identityKey: ''` + command 是 Scry → `already-running/identity-unverifiable`；
- lease：`identityKey: '<pid>:legacy-identity'` + command 是 Scry → `identity_unverifiable`。

这两条在原实现上也通过（它们就是原行为），作用是锁住「收窄不能顺手拆掉兜底」。

M1 的自身 pid 用例仍然通过：pid 是本进程时先命中 `pid-reused`，与格式无关。
