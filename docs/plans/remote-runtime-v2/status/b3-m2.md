## M2-1 trace-runtime 的 renderer 转发注入

**改动**：`createTraceRuntime` 的 `getWindow: () => BrowserWindow | null` 换成 `renderer: RunRendererSink`：

```ts
export interface RunRendererSink {
  send: (channel: string, payload: unknown) => void
  // Whether the owning window has focus; the dock badge only needs this much.
  isFocused: () => boolean
}
```

8 处 `getWindow()?.webContents.send(channel, payload)` 改成 `renderer.send(channel, payload)`，dock 徽标用的 `getWindow()?.isFocused()` 改成 `renderer.isFocused()`。实现留在 main 侧的新模块 `src/main/bootstrap/app-trace-runtime.ts`（`createAppTraceRuntime`）：只有它知道「在 Electron 里 sink 就是窗口的 webContents」。`index.ts` 因此变成一行 `createAppTraceRuntime({ getWindow: () => win, … })`，比原来的三行更短——`index.ts` 基线已是 19,974 B，直接写 sink 会顶过 20,000 B 提交门禁，所以按职责把「main 侧适配」抽成独立模块，而不是压缩代码凑大小。

为什么先做这一段：它是「事件源 / renderer 转发」分界的一半，改动面小、被 9 个测试文件覆盖，且能让后续段的 `run-*.ts` 注入有明确的 sink 契约可依。

测试侧：`trace-runtime*.test.ts`、`run-live-state.test.ts`、`desktop-trace-delta-hints*.test.ts`、`scripts/fixtures/concurrency-trace-*.ts` 都从 `getWindow: () => null` 换成 `renderer: { send: () => undefined, isFocused: () => false }`；`trace-runtime.test.ts` 的假窗口改用 sink 转发，断言内容不变。没有删断言、没有放宽超时。
