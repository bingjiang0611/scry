# B4-L1 本机入网与 `scope: local`

分支 `claude/remote-runtime-v2`。设计：[P3-batch4-design §13.2](../P3-batch4-design.md)；决策：[REVIEW-BATCH4-D2](../REVIEW-BATCH4-D2.md)。

## 做了什么

1. **grant 带 scope 与来源**（`src/main/remote/pairing.ts`）
   - `DeviceGrant` 新增 `scope: 'local' | 'remote'`，`source` 扩为 `'local_confirmation' | 'local_socket'`。
   - `enrollLocal({csrPEM, deviceLabel}, consumeSecret)`：先验 CSR，再在**同一个串行事务**里消费 secret、签发 grant、撤销上一个 local grant。
   - `authorizesCertificate(cert, transport?)`：`transport === 'network'` 时只接受 `scope: 'remote'`。省略 transport 表示可信内部调用（配对簿记、gateway 内部），不改变既有语义。
   - 状态校验要求 scope 与 source 一致（`local` ⇔ `local_socket`）；旧状态缺 scope 时按 `remote` 读入，不会把历史手机 grant 读成本机。
2. **传输就是授权边界**（`src/main/remote/inner-mtls-host.ts`、`host-controller-surface.ts`）
   - `InnerMtlsHost` 新增 `transport: 'local' | 'network'`（默认 `network`）。
   - 每帧在调用 controller 之前先问 `authorizesTransport(fingerprint, transport)`，拒绝时回 `{ error: 'device_not_authorized' }`（keep-alive 帧保持同一形状）。按帧检查，撤销下一帧即生效。
   - **fail closed**：controller 无法回答传输问题时一律拒绝。
3. **一次性 secret 与入网 socket**（`src/daemon/local-enrollment.ts`）
   - `openLocalEnrollmentStore`：`local-enrollment.json`，目录 `0700`、文件 `0600`、原子写；`ensure(hasGrant)` 在无有效 local grant 时轮换生成，有 grant 时删除残留文件；`consume` 只认当前 secret，成功后删文件。
   - **不按时间过期**：只在「被使用」与「daemon 重启」时轮换。登录时拉起、几小时后才打开 App 是正常路径。
   - `openLocalEnrollSocket`：`enroll.sock`（`0600`），一行 JSON 请求、一行 JSON 应答。
   - `localEnrollHandlers` 只返回证书+CA 信封，**不回显 secret**；版本不符或字段不合格先拒，不消耗 secret。
4. **daemon 接线**（`src/daemon/host-process.ts`、`remote-host-service.ts`）
   - `RemoteHostService.createLocalHost()` 用同一 controller/CA/服务端证书，但标 `transport: 'local'`，只服务 `local.sock`。
   - `hasActiveLocalGrant()`、`enrollLocalDevice()` 是 daemon 需要的窄接口，不把整个 authority 交出去。
   - `dispose` 依次关闭 enroll socket、local socket、local host、service。

## 失败先行的证据

- `src/daemon/local-enrollment.test.ts`（10 条）：首次入网成功；secret 复用返回 `local_enrollment_secret_invalid` 且不再签发；CSR 被拒时 secret 不被消耗；local grant 在 `network` 上被拒；手机 grant 在 network 上仍有效；撤销后 local 授权立即失效且不自动重入；重复入网替换而非堆叠；socket 应答不含 secret；secret 生命周期与 fail-closed 损坏/宽权限文件。
- `src/main/remote/local-grant-transport.test.ts`（3 条，真实 mTLS）：同一 controller + 同一 CA 的两个 endpoint，本机 grant 在 unix socket 上通过、在 TCP 上得到 `device_not_authorized`；手机 grant 在 TCP 上仍通过；撤销后 unix socket 同样拒绝。
- 修 `desktop-host-listeners.test.ts` 的双精度替身：host 现在要求 controller 回答传输问题，替身补 `authorizesTransport: () => true`，不掩盖 fail-closed 行为。

## 提交时的结构调整

`scripts/check-staged-file-size.mjs` 不接受「已存在的大文件」，`pairing.ts` 在本次改动前已 20.9 KB。按职责拆分而不是跳过门禁：

- 新增 `src/main/remote/pairing-state.ts`：持久化结构的类型、校验与纯 helper（`validatePairingState`）。它只回答「这份文档是不是合法 pairing 状态」，不碰状态机、IO 或时钟。
- `pairing.ts` 保留 `PairingAuthority` 状态机，并 re-export 这些名字，现有调用方无需改 import。
- 传输判定改为 `InnerMtlsHost` 直接问 `controller.authority.authorizesCertificate(fingerprint, transport)`，因此 `host-controller-surface.ts` 不需要新增方法，也回到改动前的大小。
