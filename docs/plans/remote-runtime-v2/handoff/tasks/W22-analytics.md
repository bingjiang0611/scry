## 规则

照 [README](../README.md) 执行：分支、提交身份、证据目录、报告格式、测量互斥都按它来。

- **分支**：远程分支 `feat/analytics-v1` 已经建好，基于 main，里面有设计、设计稿和本任务单。在这个分支上开发，只推送到这个分支。不开 PR，不合并 main，不 force push。
- **门限与测试**：
  - 不放宽任何性能门限、预算或棘轮；
  - 不跳过、不弱化任何测试或冒烟断言；
  - App 主进程模块数不超过 192。
- **价格**：只能来自官方公开价目表，并在代码里注明来源和日期。查不到的模型保持未定价，不许猜。
- **环境**：
  - 测试只用临时 HOME 和 userData；
  - 不碰日常的 `com.scry.daemon` 和真实的 `~/.scry`；
  - 不用 pkill 或 killall；
  - Electron 不加 `--no-sandbox`；
  - 单文件小于 20,000 字节；
  - 代码和文档里不写模型名之外的账号、邮箱或 ID。
- **流程**：小步提交，随时推送。中断后续跑时，先读 `reports/W22.md` 和 `git log`。被权限系统拒绝的操作不要绕过，记进报告。

## 验收

- **统计问题**：设计 §3 的 13 项，每项都有失败测试和修复，测试名称或注释里标出对应的编号。
- **显示规则**：用一个夹具同时覆盖下面几种情况，断言页面上不出现「—」「不上报」「未定价」「所选：」「多模型」「0.0%」，也不出现 0 轮的行：
  - 没有用量的 Provider
  - 0 Token 的记录
  - 只有失败轮次的模型
  - 不上报首 token 的 Agent
  - 查不到价格的模型
- **对照检查**：同一批夹具数据在两个标签里，Agent + 模型的行要对得上。
- **全量检查**：
  - `npm run typecheck`
  - `--strict` 导入检查
  - 全量 vitest，只允许已知的环境失败
  - `npm run check:cli-runtime`
  - `npm run design:audit`
  - 开发布局和打包布局的冒烟
  - 原生性能门跑一轮
- **截图**：明暗两种主题下，两个标签各截一张，和设计稿对照。截图放进证据目录。
- **真机**：在 mac1 上用真实数据打开「分析」页。以 24 小时和 30 天两个范围，分别检查：
  - 不再出现 cc-switch、radius、unknown 这样的 Provider 行；
  - 不再出现「所选：」行；
  - 曲线不断开；
  - 两个标签的 Agent 和模型对得上。

  先后截图对比，放进证据目录。
- **评审**：全部完成后，开一个只读子 agent 做独立评审，修掉阻塞项，然后复验。
