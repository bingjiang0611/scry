## 范围（P4-0 行）

- **纯决策器**：从现有 H1 台账（`src/main/remote/session-ledger.ts` 的转移表）抽出，不做 I/O，输入命令与当前 projection，输出事件或拒绝。
- **拒绝分类**：黏性（载荷冲突、非法转移，写回执）与可重试（忙、容量、`provider_authenticating`，不写回执）。
- **独立的 `orchestration.db`**，与 `scry.db` 分开：独立迁移执行器，遇到更高的 `user_version` 拒绝打开；**不得**复用 `db-migrations.ts` 里写死的「第 16 版修复用量表」钩子（`src/main/db-migrations.ts:46`）。`-wal`、`-shm` 也是 0600。
- **EventSink**：一个事务提交事件、projection、命令回执、outbox；提交遇 IOERR/FULL/fsync 错误即 fail closed（同 H1 的 `ledger_write_indeterminate`），但停止和取消照样可用。
- **策略表**、**正文存储**（≤16 KiB 存行内，更大的按内容哈希存文件；会话删除时清除）。
- **单写者三层**：daemon 的台账锁、`locking_mode=EXCLUSIVE`、静态检查 main 不导入编排存储。
- **Recorder Core 导入测试**：`src/core/turn-recorder` 不导入 `better-sqlite3` 与编排模块。
- **多 Agent 预留列**（core §2.10，R1–R12，只占位、不实现行为）。

## 不做

- 不接入 daemon 的运行路径，不改协议，不改 renderer，不改 scry CLI 与记录格式（维护者 2026-11-19 决定「第 1 步」暂不做）。
- 不新增或放宽性能门限。

## 验收与自验

| # | 标准 |
|---|---|
| 1 | 决策器：设计列出的每个合法与非法转移都有测试；同一命令 id 重放得到同一回执；载荷冲突为黏性拒绝；可重试拒绝不写回执 |
| 2 | 迁移：从空库到当前版本；遇到更高版本拒绝打开；不触发用量修复钩子；文件权限 0600（含 `-wal`、`-shm`） |
| 3 | EventSink：事务原子性（注入失败后无半条事件、无孤儿 projection）；fail closed 后拒绝新命令但放行停止 |
| 4 | 正文：边界 16 KiB；内容寻址去重；删除会话后正文与事件预览被清除 |
| 5 | 单写者：第二个连接或 main 侧导入被拒（静态检查进测试） |
| 6 | Recorder 独立的导入测试通过 |
| 7 | `npx tsc --noEmit -p tsconfig.node.json`、新增目录与 `src/daemon` 的 vitest 通过；`npm run check:cli-runtime` 通过（证明没碰 CLI） |
| 8 | 新文件登记进 `scripts/performance-paths.json` 的 `sources`（若设计要求），`performance-feedback.test.ts` 通过 |
