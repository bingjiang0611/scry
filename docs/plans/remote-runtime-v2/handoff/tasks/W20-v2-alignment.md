## 每项的最低验收

- **A1**：构造一次编号冲突，命令被拒绝，后续命令照常提交；IOERR 类错误仍然锁死（注入测试）。
- **A2**：真实 CLI 或 fixture 下，「本会话内允许」在第二轮依然生效；重启 daemon 后依然生效。
- **A3**：实时运行结束后，`last_run_outcome` 带 recorder 证据，不是 `unavailable`；`provider_settled` 和 `finalized` 两个事件按顺序出现。
- **A4**：停止和回答的副作用会走到完成；数据库里塞一个未知的副作用类型，daemon 照常启动，该行被置为 `failed`。
- **A5**：独占的共享进程在优雅窗口之后被回收；有其他运行共用时仍报 `no_safe_force_kill`。
- **B1**：租约不匹配时更新被拒绝；`attempts` 递增，退避有上限；同一会话先进先出；SIGKILL 后恢复正确；静态检查确认派发不再读内存台账。
- **B2**：清理后，被删除的会话不会复活，回执依然有效，重放一致（只在未裁剪的窗口内检验）；清理是分页的，并且有 `pruned_through`；正文在运行到终态后被回收。
- **B3**：唯一约束生效；查到多条匹配时报错，而不是新分配 key；迁移后旧数据行为不变。
- **B4**：长时间扫描一个外部持续写入的 transcript，回执数量有上界。
- **C1**：
  - 同一会话第二轮不再新起进程（用进程计数断言）。
  - 会话在空闲和满额时被释放，释放原因能查到。
  - 配置、MCP 或权限变化时，会话按策略在线切换或重建。
  - Provider 崩溃后能重建。
  - 有后台任务时会话被保留。
  - 真实 Provider 的首 token 前后对比数字写进报告。
- **C2**：Claude 和 Qoder 能中途插话；不支持原生 steer 的 Provider 走「中断后重启」，投递证据正确。
- **C3**：答完就结算这一轮；后台任务完成后以 `origin = 'agent'` 的运行唤醒会话；Claude 的后台任务能停止，并能看到实时输出。
- **C4**：
  - 原生会话被删除后能自动新开并交接。
  - 重启后的提示和「继续」都要求用户显式操作，并且有循环保护。
  - 用量限额能解析出重置时间，用户开启后到点自动恢复。
- **C5**：空闲压缩可配置，默认开启；报告里记录成本数据。
- **D1**：排队在重启和 App 刷新后都还在；Mac 和手机看到的是同一份队列；停止会挂起队列；队头能被自动放行。
- **D2**：四种派发模式都有端到端测试。
- **D3**：分叉、侧聊、远程分叉在数据库里的谱系与文件一致。
- **D4**：改名、置顶、归档、删除都由事件驱动，事件里的操作者是真实的调用方。
- **D5**：倒回对话可用；恢复文件只在受管 worktree 里允许；回滚后的运行带 `rolled_back`。
- **D6**：长会话的详情快照有上界并带 cursor。
- **iOS 与 Desktop 远程**：D1、D3、C2 等对客户端可见的变化同步到 iOS 和 Desktop。Swift 在本机编译并跑测试。iPhone 真机步骤需要维护者操作时，停下来告诉维护者做什么、看什么。
