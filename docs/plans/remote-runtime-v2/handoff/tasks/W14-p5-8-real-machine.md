# W14 · P5-8：命令行批准新设备的真机验收

执行方 A，在 W13 返修推送之后做。依据：[reports/W11.md](../reports/W11.md) 第 6 节的分步清单（第三轮已修正退出码、启动方式与收尾步骤），以及 [P5-host-security](../../P5-host-security.md) §6。

## 范围

- **手机和桌面各一次**：开关打开后，用 `scry-host invite` 和 `scry-host approve` 在终端里批准一台新设备。核对设备列表里的 `approvedVia`，以及 App 的原生通知。
- **反向用例**：
  - 开关关闭时，批准被拒绝。
  - 管道运行，以及在 `SCRY_HOST_CHILD` 下运行，都被拒绝。
  - 限速生效。
  - 指纹前缀有歧义时被拒绝。
- **混合状态**：daemon 带着开关、App 不带开关时，设置页仍显示这一项，能关闭，但不能打开。
- **登录时启动**：带着开关开启后，服务文件里有这个变量；收尾时不带开关重新开启，变量被移除。

## 约束

- 测试设备用 iPhone 13 和本机的测试实例；不用日常 App 的真实配对去做批准实验。新批准的测试设备，验收结束后撤销。
- 按清单第 7 步收尾：关闭命令行批准，不带开关重新开启「登录时启动」（或者恢复到验收前的状态），确认没有遗留 `SCRY_EXPERIMENTAL_HOST_CLI`。
- 证据放在 `~/.local/state/scry-handoff-evidence/W14/`。
- 报告写 `reports/W14.md`，第一行写状态。
