## 规则

- **基础规则**：照 [README](../README.md) 执行，包括提交身份、证据目录、报告格式和测量互斥。
- **分支**：远程分支 `feat/analytics-merge` 已经建好，基于 main，里面已有设计文档、设计稿和本任务单。
  - 在这个分支上开发，只推送到它。
  - 不开 PR，不合并 main，不 force push。
- **不碰 W20 正在改的文件**：订阅引擎（`subscribe-*.ts`）、`orch_*` 表结构、派发器、`run-*.ts` 的运行主流程。
  - 统计口径的修复主要改 `run-metrics.ts`、`pi-usage.ts`、`codex.ts` 的用量部分和 `billing*`，这些不属于上面的范围。
  - 如果确实要动 `run-live-state.ts`，改动越小越好，并在报告里写明。
- **门禁**：
  - 不放宽任何性能门限、预算或棘轮。
  - App 主进程模块数不超过 192（`node scripts/main-import-boundary.mjs --strict`）。
  - 不跳过、不弱化测试和冒烟断言。
- **数据安全**：
  - 测试只用临时 HOME 和 userData，不碰日常的 `com.scry.daemon`，也不碰真实的 `~/.scry`。
  - 历史用量数据只在读取时迁移，不改写原文件和数据库里已有的行。
- **其他**：
  - 不用 pkill/killall，Electron 不加 `--no-sandbox`。
  - 单文件小于 20,000 字节。
  - 仓库里不写模型名、邮箱或 ID；测试夹具用中性的示例名。
- **流程**：
  - 先写失败测试，再实现；小步提交，随时推送。
  - 中断后续跑时，先读 `reports/W22.md` 和 `git log`。
- **权限**：被权限系统拒绝的操作不要绕过，记进报告。

## 验收

- 设计 §5 的全部项目。
- 全量检查：
  - `npm run typecheck`
  - `--strict` 导入检查
  - 全量 vitest（只允许已知的环境失败）
  - `npm run check:cli-runtime`
  - `npm run design:audit`
  - 开发版和打包版冒烟
  - 一轮原生性能门
- 明暗两种主题的截图放进证据目录，和设计稿逐个画板对照。
- 用你本机的真实数据（只读）打开新页面看一遍，确认三件事，并把截图和结论写进报告：
  - 不再出现网关名（如 cc-switch）或 unknown 当作 Provider 的行；
  - 不再出现「—」；
  - Codex 的轮次有了金额。
- 全部完成后，开一个只读子 agent 做独立评审，修掉阻塞项，再复验一次。
