# W5 · P4-1：影子写、增量导入、daemon 模式 CI、首轮测量

依赖 W4。设计依据同 W4，重点看 [P4-orchestration-plan](../../P4-orchestration-plan.md) §8（性能）、§9 的 P4-1 行与「开关与 off↔on」、§10。

## 目标

daemon 在现有运行路径旁「影子写」事件与 projection，和现有台账逐项比对，证明模型正确且不拖慢首 token。**影子不改变任何用户可见行为**：影子写失败只让影子 fail open，不影响 run，并计数。

## 范围

- 开关 `SCRY_ORCHESTRATION=off|shadow|on`，只由 daemon 读；本段只实现 `off` 与 `shadow`。默认 `off`。
- 在 H1 `#emit`、H3 `settle` 处同时提交事件与 projection；测试比对影子 projection 与现有台账。
- off↔on 增量导入：`orch_meta.legacy_ledger_seq`、`orch_legacy_run`，按 scoped intent id 与台账 run id 幂等；`app-sessions.json` 哈希变化时增量导入（设计 §9 规则 1）。
- 新增 daemon 模式的 CI 作业（现有单元与集成测试默认走进程内，`src/main/daemon-mode-default.ts:6-9`）。
- 首轮测量：在维护者的 Mac 上按 S1 流程（[P3-s1-absolute-cap](../../P3-s1-absolute-cap.md)）测首 token，`shadow` 对 `off`；`PRAGMA fullfsync` 开与关各两轮；记录首 token 前的提交次数与提交合计耗时。规则见 plan §8.3：开着仍满足 S1 两条上限且提交合计 P95 ≤ 8 ms 就开，否则关并报维护者确认。Linux 的 ext4/btrfs 测量若无环境标 not-run。

## 验收与自验

| # | 标准 |
|---|---|
| 1 | `shadow` 下 fake provider 的发送、停止、回答、恢复全路径：影子 projection 与现有台账逐字段一致（测试） |
| 2 | 影子写注入失败：run 照常完成，计数增加，无用户可见变化 |
| 3 | off → shadow → off → shadow 往返：无重复、无遗漏、无重复派发（测试） |
| 4 | daemon 模式 CI 作业加入工作流并在本地以同样命令跑通 |
| 5 | 首 token：`shadow` 相对 `off` 不违反 S1 两条上限；数据、负载、样本数写进报告；不放宽任何门限 |
| 6 | fullfsync 两轮测量完成，按规则给出建议并列为「需要维护者决定」 |
| 7 | 受影响测试、类型检查通过；`npm run check:cli-runtime` 通过；改动了 `performance-paths.json` 里的源文件就跑 `npm run performance:measure -- --compare <基线>` 并解释变差的行 |

## 真机部分

测量只在空闲时做（1 分钟负载 < 核数）；负载高就延后，不用高负载数据下结论。中文系统语言与中文工作区路径各跑一轮 smoke。
