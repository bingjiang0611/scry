## 2. 发布顺序隔离（`SCRY_EXPERIMENTAL_HOST_CLI=1`）

- **默认关闭（未设 `SCRY_EXPERIMENTAL_HOST_CLI=1`）**：
  - `approvedVia` 不写入持久化配对记录；
  - `host-admin.sock` 不监听，`host-admin.json` 不因读取而创建；
  - `BackgroundServiceStatus` 不含 `cliApproval`，设置页不显示「允许命令行批准」与 `scry-host` 入口，`remote:hostAdmin:setCliApproval` 返回 `host_cli_experimental_disabled`；
  - `desktop info` 不带 `hostAdminNotices`，`catalogSnapshot` 不带 `hostAdminNoticeItems`（已补测试并变异验证）；
  - `scry-host status` 检测到 `daemon.lock` 持有者正在运行时，提示「命令行管理功能未开启」（退出码 `4`），不再误报 `daemon_not_running`。
- **关于 `SCRY_HOST_CHILD` 保持常设的说明（小项）**：
  - `scry-host login-start enable` 在实验开关关闭时也可调用；Scry 内置终端没有 `SCRY_MANAGED_RUN_ID`，依赖 `SCRY_HOST_CHILD=terminal` 阻止终端内提权安装登录服务；
  - 若先在无开关状态下打开终端/运行，之后用户开启实验开关并重启 daemon，已有子进程仍带 `SCRY_HOST_CHILD` 标记，不会出现旧终端绕过拦截的窗口；
  - `SCRY_HOST_CHILD` 是纯拒绝标记，伪造或存在不会授予任何权限，也不改变持久化文件格式或协议。
