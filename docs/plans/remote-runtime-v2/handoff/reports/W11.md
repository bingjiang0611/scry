为遵守 `P5-host-cli.md` §3.7（W3 读取端必须早于 `approvedVia` 写入至少一个版本发布），全部新能力默认关闭：

- **默认关闭（未设 `SCRY_EXPERIMENTAL_HOST_CLI=1`）**：
  - `approvedVia` **不写入**持久化配对记录（`pairing.ts`、`remote-host-service.ts`、`pairing-channels.ts` 仅在实验开关开启时传值）；
  - `host-admin.sock` **不监听**（`attachDaemonHostAdmin` 返回 `null`），`host-admin.json` 不因读取而创建；
  - `localBackgroundService:status` 与 `BackgroundServiceStatus` 不含 `cliApproval` 字段，设置页不渲染「允许命令行批准」与 `scry-host` 路径入口；

  - `catalogSnapshot` 与 `desktop info` 不暴露 `hostAdminNotices` 能力。
- **测试证明**：
  - `src/daemon/host-process-admin.test.ts`：默认关闭时不创建 `host-admin.sock`，且 App 确认配对不写 `approvedVia`；

## 5. 已定事项与待维护者决定事项

### 5.1 已定事项（按设计定稿落地，无变更）

- 采用方案 a：在执行端以 `scry-host` 命令行批准新设备；「允许命令行批准」开关默认关闭。
- 通过 `SCRY_EXPERIMENTAL_HOST_CLI=1` 隔离全部第 2 步能力（含 `approvedVia` 写入、`host-admin.sock`、App 设置入口与通知能力暴露）。
- `REMOTE_PROTOCOL_VERSION` 保持 `2`，已配对桌面端通知采用可选能力字段 `hostAdminNotices: 1` + `catalogSnapshot.hostAdminNoticeItems` 向下兼容。
- `scry-host status` 展示 `配对记录` / `pairingCapacity`（`pairings`、`grants`、`limit: 64`）。
- 打包 allowlist：`electron-builder.yml` 将 `build/scry-host` 打包至 `Contents/Resources/bin/scry-host`；`scripts/check-packaged-app.mjs` 校验 `out/main/host-cli.js` 与可执行 `bin/scry-host`。

### 5.2 仍需维护者决定的事项（附推荐）

1. **何时移除或默认开启 `SCRY_EXPERIMENTAL_HOST_CLI`**
   - **背景**：按 `P5-host-cli.md` §3.7，含 W3 读取端的正式版本发布后，下一版本才可默认写入 `approvedVia` 并默认暴露命令行批准入口。
   - **推荐**：待含 W3 的正式版发布且执行方 A 完成 P5-8 真机验收后，在下一个次版本切换默认开启，并保留环境变量关闭口至少一个版本周期。
2. **iOS 端是否跟进消费 `hostAdminNotices: 1`**
   - **背景**：本轮已在主机 `desktop info` 与 `catalogSnapshot` 暴露 `hostAdminNotices: 1` / `hostAdminNoticeItems`，并在桌面端 `HostsView` 完成展示；iOS 端未在本仓范围改动。
   - **推荐**：建议在 iOS 下一迭代同步读取 `hostAdminNoticeItems` 并展示顶部安全横幅，保持双端一致；未升级的旧版 iOS 端因协议版本仍为 `2` 且字段可选，不受影响。
3. **本机打包后是否提示用户将 `bin/scry-host` 软链到 PATH**
   - **背景**：目前 App 设置页提供「复制 `scry-host` 路径」，不自动修改 `/usr/local/bin` 或 shell rc（符合不碰用户全局配置的边界）。
   - **推荐**：保持现状，仅在设置页提供路径复制，不自动写 PATH 或全局目录。

## 6. 交给执行方 A 的 P5-8 真机验收步骤

前置条件：先完成打包（含 `build/scry-host` 与 `out/main/host-cli.js`），使用独立测试 `userData` 或维护者授权的 `/Applications/Scry.app` 环境。

1. **打包产物自检**
   - 运行 `node scripts/check-packaged-app.mjs <app路径>`，确认 `out/main/host-cli.js` 与 `Resources/bin/scry-host`（可执行）通过校验。
2. **默认关闭回归（不设 `SCRY_EXPERIMENTAL_HOST_CLI`）**
   - 启动打包版 Scry，打开「设置 → 后台服务」：确认**看不到**「允许命令行批准」与 `scry-host` 路径；
   - 确认 `<userData>/daemon/host-admin/host-admin.sock` **不存在**；
   - 在 App 内配对一台测试设备后检查 `<userData>/remote/pairing/pairing-state.json`：确认新记录**不含** `approvedVia` 字段；
   - 在外部终端运行 `<app>/Contents/Resources/bin/scry-host status`：确认报错退出码非 0（无 admin socket）且不会自动修改任何状态。
3. **开启实验开关与开关默认关闭门卫（设 `SCRY_EXPERIMENTAL_HOST_CLI=1`）**
   - 以 `SCRY_EXPERIMENTAL_HOST_CLI=1` 启动 Scry 与后台服务（确认已传递到 daemon）；
   - 打开「设置 → 后台服务」：确认看到「允许命令行批准（已关闭）」与「复制 `scry-host` 路径」按钮；
   - 外部终端运行 `scry-host status`：确认退出码 `0`，输出版本、运行模式、远程配置摘要、配对记录条数（`x / 64`）与「允许命令行批准：已关闭」；
   - 外部终端运行 `scry-host invite phone` 与 `scry-host approve`：确认均被拒绝，返回退出码 `4`（`cli_approval_disabled`）。
4. **App 原生确认开启开关与安全门卫**
   - 在「设置 → 后台服务」点「开启允许命令行批准」：确认弹出原生确认框；先点取消，确认状态仍为「已关闭」；再点确认，确认变为「已开启」且弹出系统通知；
   - 在 Scry 内置终端运行 `scry-host invite phone`：确认因 `SCRY_HOST_CHILD=terminal` 被拒绝（退出码 `4`）；
   - 在外部终端用管道执行 `echo abcdef0123456789 | scry-host approve`：确认因非 TTY 被拒绝（退出码 `4`）。
5. **手机（iPhone）命令行配对端到端**
   - 外部终端运行 `scry-host invite phone --wait`（或 `invite phone` 后 `pending` + `approve`）：用 iPhone 扫码发起配对；
   - 核对 iPhone 显示的指纹前 16 位，故意先输入不足 16 位或错误前缀确认被拒，再输入正确前 16 位批准；
   - 验证：
     - macOS 弹出原生通知「Scry · 命令行已批准新设备」，通知正文中**无**配对秘密；点击通知激活 Scry 并自动打开「设置 → 远程访问」；
     - 「设置 → 远程访问」已授权设备列表显示该 iPhone 且标注「批准方式（记录为）：命令行」；
     - `scry-host devices --json` 输出该设备且 `approvedVia: "host_cli"`；
     - iPhone 可正常列出项目并执行一次真实 run。
6. **桌面（SSH）命令行配对端到端 + 已配对桌面通知**
   - 用另一台/测试桌面实例：在执行端外部终端运行 `scry-host invite desktop`，复制到客户端 App「设置 → 远程访问 → 添加主机」配对；
   - 在执行端用 `scry-host approve` 核对指纹前 16 位批准；
   - 验证客户端完成配对后：在已配对桌面端刷新/展开该主机行，可见主机下发的 `hostAdminNoticeItems` 告警横幅；
   - 在执行端运行 `scry-host devices` 核对记录为「命令行」，随后执行 `scry-host revoke <deviceId>` 与 `scry-host desktop-off`，验证撤销生效、通知送达，且 `desktop-off` 不撤销其他已配对设备。
7. **恢复与清理**
   - 在 App「设置 → 后台服务」关闭「允许命令行批准」；
   - 确认测试完成后移除测试设备授权，不影响日常配对与日常 `com.scry.daemon`。
