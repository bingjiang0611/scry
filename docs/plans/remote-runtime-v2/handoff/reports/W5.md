## 7. 需要维护者决定

1. **macOS `PRAGMA fullfsync` 开关（按 `plan §8.3` 测量规则）**：
   - **实测事实**：`fullfsync=ON` 虽然满足 S1 首 token 上限（warm P50 101.9–103.5 ms ≤ 150 ms，P95 121.4–128.6 ms ≤ 200 ms，两轮差 7.2 ms ≤ 25 ms），但 2 次首 token 前提交合计达 **P50 8.38–9.01 ms、P95 10.28–10.32 ms**，**两轮均超过 `plan §8.1 / §8.3` 的 `P95 ≤ 8 ms` 门禁**。`fullfsync=OFF` + `checkpoint_fullfsync=ON` 的常规提交为 **P50 2.23–2.35 ms**（R1 P95 3.02 ms，R2 因 2 次 WAL 检查点长尾致 P95 10.77 ms）。
   - **推荐（按 `plan §8.3` 规则）**：在 macOS 上保持 **`fullfsync=OFF` + `checkpoint_fullfsync=ON`**，并在文档明示掉电窗口（仅整机掉电、非进程崩溃时可能丢失最近数次已提交事务，持久性弱于当前 H1 每条 `F_FULLFSYNC`）；同时建议在 P4-2 将 WAL 检查点改为异步/空闲时 `PASSIVE` 执行，消除 R2 的 10.77 ms 检查点长尾。
   - **备选**：若维护者希望保持与今天 H1 完全等同的整机掉电持久性，且认为本机 S1 首 token 余量充足（P95 128.6 ms 距 200 ms 上限仍有 >70 ms 余量），可明确批准放开或豁免「首 token 前提交合计 ≤ 8 ms」门禁并改开 `fullfsync=ON`。
