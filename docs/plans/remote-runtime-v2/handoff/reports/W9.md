   - **单快照 `reset` + 块预留编号上限（关闭 N5 + 应修 2）**：`on` 启动时 `buildH1SnapshotFromDb` 只由 DB 当前状态生成一份无历史尾部的快照（`retainedEvents: []`，`lastSeq = minCursor = R`，不重编号、不带旧事件），旧游标收到标准 `reset` 并经 `runState`/trace 拿到 `run_settled` 对应状态；彻底删除每事件的 `h1_seq_floor` 与 `h1_seq_offset`，改为 `orch_meta.h1_seq_reserved_until` 按 **1,024 块预留**（首 token 前零新增提交，终态事件接近耗尽时提前续块，保底不变量保证任意 `SIGKILL` 后不重复编号）。
