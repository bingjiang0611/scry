## 1. 改动摘要

### 1.1 远程会话操作（复用 daemon 既有会话生命周期与分叉实现）

- [src/daemon/local-ops/deps.ts](../../../../../src/daemon/local-ops/deps.ts)、[src/daemon/local-endpoint.ts](../../../../../src/daemon/local-endpoint.ts)、[src/daemon/local-ops/session-lifecycle.ts](../../../../../src/daemon/local-ops/session-lifecycle.ts)：
  - `DaemonSessionLinks` 增加 `sessionRefFromRequest` 与 `changeLegacySessionMetadata`，`daemonLocalEndpoint` 复用调用方传入的共享 `links` 对象；`sessionLifecycleLocalOps` 将其创建的同一 `createSessionLifecycle` 实例的 `deleteOneSession` / `sessionRefFromRequest` / `changeLegacySessionMetadata` 暴露给共享 `links`，不重复实现第二套生命周期逻辑。
- [src/daemon/host-process-assembly.ts](../../../../../src/daemon/host-process-assembly.ts)、[src/daemon/host-process.ts](../../../../../src/daemon/host-process.ts)：
  - 将 `sessionRefFromRequest`、`changeLegacySessionMetadata`、`deleteOneSession`（来自 `sessionLinks`）与 `forkSessionWithAuthority`（来自 `forkOperations`）接入 `RemoteHostRuntime`；
  - `providerDiscovery.supportsForkSession` 改为按 `providerRegistry.get(providerId).forkSession !== undefined` 如实上报（与进程内 `remote-connections.ts` 一致）；
  - 经 `createHostRuntime` 与 `host-controller-session.ts` 复用与进程内完全一致的远程对端授权：设备 grant 校验、规范工作区校验、删除要求 `confirmed: true` 且仅允许删除已存档会话（`sessionDeleteRequiresArchive('remote') === true`），撤销对端立即拒绝。

### 1.2 工作区 `openPath` / `trashItem`（复用 W10 主 App 桥接）

- [src/daemon/app-execution-target-bridge.ts](../../../../../src/daemon/app-execution-target-bridge.ts)：
  - 在既有 `AppExecutionTargetBridge`（保持 W10 核验过的 `isPrimaryAppPeer` 主 App 单例校验、单活 poll 抢占、`ownerPeer` 校验、断开即失效与帧长上限，不改安全语义）上增量支持 `shellOpenPath` 与 `shellTrashItem` 两种内部 work call，并导出 `shellOps: { isAvailable, openPath, trashItem }`；
  - daemon 自身不实现 `trash` 或外部打开；主 App 不在线时 `isAvailable()` 返回 `false`，调用 fail-closed 抛出 `desktop_workbench_operation_unavailable:openPath` / `trashItem`。
- [src/main/daemon-execution-target-pump.ts](../../../../../src/main/daemon-execution-target-pump.ts)、[src/main/bootstrap/daemon-run-mode.ts](../../../../../src/main/bootstrap/daemon-run-mode.ts)、[src/main/bootstrap/app-daemon-mode-deps.ts](../../../../../src/main/bootstrap/app-daemon-mode-deps.ts)：
  - App 侧 `DaemonExecutionTargetPump` 接收 `shellOps`（`appDaemonModeDeps` 注入 Electron `shell.openPath` 与 `shell.trashItem`），校参非空且无 `\0` 后执行并返回结果。同时将 `appDaemonModeDeps` 拆出至独立模块并从 `daemon-run-mode.ts` 重导出，并将 `disposeProviderRegistryWithTimeout` 移入 `host-process-assembly.ts`，保持所有改动文件均低于 20,000 字节门禁。
- [src/main/remote/desktop-workbench.ts](../../../../../src/main/remote/desktop-workbench.ts)、[src/host-runtime/host-runtime-types.ts](../../../../../src/host-runtime/host-runtime-types.ts)、[src/host-runtime/host-runtime.ts](../../../../../src/host-runtime/host-runtime.ts)：
  - `createDesktopWorkbench` 支持动态可用性探针 `hasOpenPath` / `hasTrashItem`，`operations` 改为实时 getter：主 App 在线时 `desktop info` 宣告支持（省略 `workbenchOps`），主 App 离线或断开后立即如实报告 `workbenchOps: { openPath: false, trashItem: false }`，且调用前仍由 `openWorkspaceFileExternally` / `trashWorkspaceEntry` 先完成工作区边界与路径逃逸校验再进入桥接。

### 1.3 准确文案（不误导「请更新」）

- [src/renderer/components/WorkspacePanel.tsx](../../../../../src/renderer/components/WorkspacePanel.tsx)、[src/renderer/components/RemoteChatView.tsx](../../../../../src/renderer/components/RemoteChatView.tsx)：
  - 传入远端主机显示名 `hostLabel`；当主机在线但 `workbenchOps` 因主 App 未打开而缺失时，面板显示「`需要在 <host> 上打开 Scry 桌面端以启用：…`」，运行中主 App 断开返回 `desktop_workbench_operation_unavailable:*` 时显示「`需要在 <host> 上打开 Scry 桌面端后才能执行此操作`」，绝不提示「请更新」。
  - `SidebarRemoteProjects` 的「请更新并重启」横幅仅在 `catalog.sessionActions !== true` 时触发；默认 daemon 现已宣告 `sessionActions: true`，该横幅仅针对真正旧版本主机出现。

### 1.4 回归夹具切回默认 daemon 模式

- [scripts/desktop-remote-host-smoke.mjs](../../../../../scripts/desktop-remote-host-smoke.mjs)：移除 W15 临时加上的 `SCRY_HOST_DAEMON=0`，恢复默认 daemon 模式运行。

## 3. 交给执行方 A 的真机验收清单（远程桌面连到默认 daemon 主机）

前置：被控端 Mac（主机）运行包含本提交的构建（默认 daemon 模式，`SCRY_HOST_DAEMON` 未设置），已开启远程桌面访问并与控制端桌面（客户端）完成配对；被控端有一个已授权测试项目及至少一条历史会话。

1. **会话操作（主机 App 打开状态）**：
   - 在客户端侧栏展开主机项目：确认**不再出现**「请更新并重启 … 上的 Scry，以启用会话操作」横幅；重命名、置顶、存档按钮均可点击。
   - 依次执行**重命名 → 置顶/取消置顶 → 存档**：确认主机本地侧栏与客户端刷新后一致生效；对运行中会话执行存档时运行被停止。
   - 打开「已存档会话」面板：执行**恢复（取消存档）**确认会话回到活跃列表；再次存档后执行**删除 Scry 副本**确认弹出二次确认并删除成功。
   - 在支持分叉的 Provider（如 Claude/Codex）历史回合菜单中确认**创建分支**入口可用且不再报「不支持创建分支」。
2. **工作区操作（主机 App 打开 vs 关闭对照）**：
   - **主机 App 打开时**：在客户端右侧「文件」面板中，确认无「打开 Scry 桌面端」缺项提示；对测试文件执行「在系统应用中打开」（主机弹出默认应用）与「移入废纸篓」（文件进入主机废纸篓，可还原）。
   - **关闭主机 Scry 窗口并仅保留后台服务（`Cmd+Q` 仅退出 App，不退出后台服务）**：在客户端刷新目录后打开「文件」面板：
     - 确认侧栏的会话重命名/置顶/存档/恢复/删除**仍然可用**（由 daemon 独立提供）；
     - 确认「文件」面板如实隐藏「在系统应用中打开」和「移入废纸篓」，并显示准确提示：「`需要在 <主机名> 上打开 Scry 桌面端以启用：在系统应用中打开、移入废纸篓`」，**不出现「请更新」字样**。
   - **重新打开主机 Scry App**：在客户端刷新后，确认「文件」面板恢复「在系统应用中打开」与「移入废纸篓」且可正常执行。
