## P6-6 Pi（凭据通道与权限模型评估）

### 结论
**保持 `unavailable`**（依据 D12、D16 与 `src/main/providers/pi-run.ts:62-64`）。
- 实核依据：Pi RPC 启动扩展当前仅能通过环境变量（如 `SCRY_HISTORY_READER_TOKEN`）传递凭据，而 P6-0 探针 4 已在 Codex 上实证环境变量会透传至子 shell（POSIX 进程继承模型下 Pi 同理），违反 D16（禁止编排凭据进入 argv 与环境变量）；同时 Pi 仅支持 `full_access`，缺乏可映射的审批模式。
- 升级触发条件与路径：待 Pi / Rotom RPC 提供非 argv、非环境变量的 per-run 凭据通道（如 stdin RPC 握手或每 run 私有 fd）后，再接入 `orchestrationTools?: true` 能力位并补齐端到端验证。
