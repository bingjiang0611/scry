## 3. 观察与验证边界（如实说明）

- **原生通知与点击跳转**：测试 App 以可见窗口（非 `SCRY_TEST_APP=1`）运行，`cli_approval_enabled` / `device_approved_via_cli` / `desktop_disabled_via_cli` / `device_revoked_via_cli` 路径均正常触发 `showHostAdminSystemNotification` 且无错误；因本机未向 `osascript` 授予辅助功能权限，未自动抓取 macOS 通知中心横幅像素与自动化点击通知测试。
- **手机端配对后跑一轮任务**：本次重点验证真机 iPhone 13 经公网中继证明、指纹比对、命令行批准、`approvedVia: "host_cli"` 记录与撤销；未在临时 `/tmp/w14/workspace` 上额外从手机发一轮 Provider 任务（公网中继跑通已在 W12 复验）。另外，因 iOS `ScryRemote` 仅保存单个主机连接描述符，将 iPhone 13 与测试实例配对并在验收后撤销，意味着 iPhone 13 后续连回日常 `/Applications/Scry.app` 时需重新扫一次日常 App 的配对码。
- **混合状态 UI 细节**：混合状态下关闭后，设置页仍展示「允许命令行批准（已关闭）」，点击开启会被主进程拒绝（`host_cli_experimental_disabled`），无法打开。
- **打包签名说明**：`dist/mac-arm64/Scry.app` 使用 `CSC_IDENTITY_AUTO_DISCOVERY=false`（adhoc 签名，与当前 `/Applications/Scry.app` 一致）；此前默认 `Apple Development` + Hardened Runtime 且无 provisioning profile 时，macOS AMFI 会在拉起 `scry`/`scry-host` 时发 `SIGKILL`（退出码 `137`）。
- **Linux 端**：本机为 macOS，Linux 端 `scry-host` 与 `systemd` 未在本任务验证。
