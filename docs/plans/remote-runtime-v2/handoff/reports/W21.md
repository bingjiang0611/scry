## 失败与处理

- **采样 p95 超门限**：首版顺序执行四个外部读取，p50 52 ms / p95 81 ms。改为并行、空闲时省掉 `nice` 进程、`ps` 用 `ucomm`，三次实测 p95 42.5 / 44.9 / 46.5 ms。门限未改。余量不大（评审方在自己的负载下测到 49.95 ms），报告如实列出三次结果与 load。
- **冒烟断言被搬迁带弱**：`sidebar-activity.mjs` 的焦点断言在搬迁后弱化成「焦点不在 body 上」。改回精确元素（`.sb-new`），并补「真按回车打开机器页」，见 `5b1530ac`。
- **打包失败（两次，都是本机环境）**：① `cpSync` `EEXIST`——我把 `node_modules/electron/dist` 做成了指向主检出的符号链接，换成真实副本后通过；② `codesign` 报 ambiguous——钥匙串里有两张同名「Apple Development」证书。本轮用 `CSC_IDENTITY_AUTO_DISCOVERY=false` 出未签名产物做布局冒烟。
- **打包冒烟抓到真缺口**：`scripts/desktop-remote-host-smoke/pairing.mjs` 的能力位断言缺 `hostMetrics`。补上，并新增「配对设备经真实 TLS 读远程快照 + 无 PID/路径」断言。
- **全量 vitest 一次单点失败**：`src/core/turn-recorder/session-capture-inbox.test.ts` 报 `record store changed while building derived index`。本分支没有改 `turn-recorder`（`git diff 52fe66c4..HEAD --name-only | grep turn-recorder` 为空）；单独运行该文件 7 项全绿。判定为全量并发负载下的既有抖动，不是本次改动引入。上一次全量出现同类单点失败时没有保留日志，那次无法定位。
- **评审 3 条阻塞项**：见 `reports/W21-review.md`，已修并复验。

## 与设计的出入

1. **排队数（§3）不可得**：`runs.queued` 报 `null`，界面写「排队 不可用」。排队数在编排投影（`orch_p_run` 的 `recorded`/`admitted`）里，第一版没有接；写 `0` 会把未测量值当成测量值，所以不写。
2. **Provider 根进程（§3）未接**：`providerRoots` 目前恒为空，Provider 行靠可执行名（`ucomm`）归属，其余进「其他」。设计允许「无法确定归属计入其他」，但「按启动它的 Provider 分组」这条要在 W20 的 run 链路里暴露根进程后才能完全成立。
3. **Linux 用 `ps` 而不是 `/proc/*/stat`（§3）**：两端共用一次 `ps -axo pid=,ppid=,rss=,%cpu=,ucomm=`，口径一致、代码只有一条路径；没有按平台分叉。
4. **`nice` 只在有运行/排队时用（§4）**：设计写「采样的子进程优先级降低」。空闲时直接 `ps`，省一次进程（实测约 8 ms）；有运行在跑或排队（排队未知时按有算）仍走 `nice`。
5. **`swapTotalBytes` 是新字段**：设计只要求「交换区已用」能显示，加总量是为了让交换条有分母。
6. **改动范围超出「只加一行」**：新 op 必须进 `inner-mtls-dispatch.ts`（+6 行）；采样器挂载在 `host-process.ts` 不止一行（来源装配 + `activeRuns`）；`host-controller-surface.ts`、`host-controller-desktop-reads.ts`、`desktop-ipc-routing-client.json`、`protocol-v3-retirement.test.ts`（登记新的标签时钟）各有一处改动。都在设计 §7 允许的界面/协议范围内，没有碰订阅引擎、`orch_*` 表结构、Provider 适配器、派发器、`run-*.ts`。
7. **`load1` 不归一化**：采样给 1 分钟负载原值，界面写「4.10 / 10 核」。设计表格写的是「1 分钟平均负载 / 核数」，这里把两个数并排显示而不是显示商；要改成归一化值请维护者定。
8. **`daemon.pid`**：local scope 里带着（设计允许），但界面没用到；remote scope 已剥离。
