## 4. 失败与处理

1. **macOS 单测失败：`src/main/providers/codex-mcp-argv.test.ts:217`（测试跨平台移植问题，非产品缺陷）**：
   - 命令：`npx vitest run src/main/providers/private-mcp-config.test.ts src/main/providers/claude-mcp-argv.test.ts src/main/providers/qoder-mcp-argv.test.ts src/main/providers/codex-mcp-argv.test.ts`（退出码 1；18/19 通过，唯一失败为 `Codex stdio env launcher > gives the original command exactly the env Codex would have given it`）。
   - 根因核实：在空环境下直接执行 `/usr/bin/env -i PATH=/usr/bin:/bin /bin/sh -c 'unset PWD OLDPWD SHLVL; readonly SHLVL; /usr/bin/env'`，输出仅含 `PATH=/usr/bin:/bin` 与 `_=/usr/bin/env`（无 `__CF_USER_TEXT_ENCODING`、无 `SHLVL`、无 `PWD`）；而 `exec node` 时 macOS CoreFoundation 会为 Node 进程自身补入 `"__CF_USER_TEXT_ENCODING": "0x1F5:0x19:0x34"`。原测试在 Linux 编写，用固定字面量 `toEqual({ ...codexDefaults, ...NASTY })` 断言，导致 macOS 上必然多出 `__CF_USER_TEXT_ENCODING`。
   - 处置：W6 范围仅限 macOS 核对，未越界修改核验方编写的测试文件；建议在测试中改为与直接 `spawnSync(process.execPath, [printer], { env: expected })` 的基线结果比对（或忽略 macOS CoreFoundation 注入的 `__CF_USER_TEXT_ENCODING`）。日志：`W6/w6-vitest.log`。
2. **首次跑 stub 脚本的脚手架修正**：首次因测试脚本把 stdio 脚本放在工作区外被信任门禁跳过、以及 dev Electron 需将打包 `scry` CLI 0.2.78 放入 PATH；修正测试脚本后通过，不属于产品问题。
