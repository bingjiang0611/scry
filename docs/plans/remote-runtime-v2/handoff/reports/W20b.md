## 阻塞项

### R1 推迟或重试的 effect 不再饿死别的会话

`effect-outbox` 加了 `available_at`（迁移 v14）和 `idx_orch_outbox_available`。`retryEffect`/`deferEffect` 写入退避时间，领取查询过滤 `available_at`，新增 `wakeDeferredEffects(db)` 与 `RemoteDispatcher.wake()`；`host-controller-execution.ts` / `host-controller-surface.ts` 的 pump 改为「先唤醒再泵」。一个被挂住的会话因此不再挡住别的会话。

- 测试：`effect-outbox.test.ts`「R1: a deferred effect does not starve the other sessions」「R1: a retried effect waits out its backoff before it can block another session again」；`remote-dispatcher.test.ts`「R1: a held run does not stop another session from dispatching」；`remote-dispatcher-backoff.test.ts`「R1: wakes each deferred session at its own deadline」。
- 负向对照：把 `available_at` 过滤去掉，两项都失败。
- 迁移提醒：手工重建的旧库要同时 drop `available_at` 和它的索引（`orchestration-catalog-scan.test.ts` 的 v5 构造已照此调整）。

### R2 排队 → SIGKILL → 重启 → 恰好执行一次

原来重启快照把 `queued` 当作 `cancelled`，还丢失完整请求。现在映射为 `recorded`，从待派发 outbox 读取并校验原文。无法读取要求保留的正文时记录失败，不发送预览替代。只有台账确认已派发或终态时，拒绝派发才可视为已处理。

- 测试：`host-process-orchestration-r2-queued-restart.test.ts`「dispatches the queued run after the restart, once, with its original request」。真实子进程 SIGKILL + 重启；独立记录测试 Provider 调用，核对完整 prompt 与 resume，且该条目的 `run.dispatched` 事件恰好一次。
- 负向对照：两个方向各一个（丢一次 / 跑两次）。

### R3 Qoder 会话身份与每轮回调

`fresh:<runId>` 与 `native:<resume>` 分开（`qoder-session-identity.ts`），池用 `nativeAliases` 记住 native id 对应的进程，每个进程有自己的 `QoderSessionTurnSlot`（当前轮回调、传输和进程身份），`qoder-run.ts` 每轮替换 `canUseTool` 与 `onExit`——所以第二轮不再由已结束的第一轮闭包回答权限问题。

- 测试（`qoder-session-run.test.ts`）：「R3: two new conversations in one workspace never share a CLI process」「R3: the second turn of one conversation reuses the same CLI process」「R3: the second turn receives the permission request, not the finished first turn」（`firstAsks 0 / secondAsks 1`）。
- 真实 Qoder 复测见下面「Qoder 第二轮重测」。

### R4 同一项目两个新对话都能跑完

两个原因：`session-host.ts` 用同一个 key 的并发 acquire 会 `release(key,'replaced')` 关掉活会话；`antigravity-run.ts` 把所有新对话的 key 都写成 `'fresh'`，同项目两段对话撞在一起。

修法：`session-host.ts` 加 `#waiters`，忙碌 key 的并发 acquire 改为等待（由 `settle`/`release` 唤醒），只有空闲/LRU 条目才被淘汰；`antigravity-run.ts` 的 `continuationKey` 改为 `request.resume ?? request.runId`。

- 测试：`session-host.test.ts`「R4: a concurrent acquire for a busy key never closes the live session」（修前 `expected [ 'a' ] to deeply equal []`）、`antigravity-session-reuse.test.ts`「R4: two new conversations in one project both finish」（两条都 completed，`externalSessionId` 不同，`openedKeys` 两条，`spawnCount` 2）。
- 测试夹具同步加了 `sessionIdPerProcess`（`sess-fake-${pid}`）与 `installFakeAgy(extraScenario)`，第二个 run 等 `firstOpened` 之后才启动。
