## 阻塞项

### R1 推迟或重试的 effect 不再饿死别的会话

`effect-outbox` 加了 `available_at`（迁移 v14）和 `idx_orch_outbox_available`。`retryEffect`/`deferEffect` 写入退避时间，领取查询过滤 `available_at`，新增 `wakeDeferredEffects(db)` 与 `RemoteDispatcher.wake()`；`host-controller-execution.ts` / `host-controller-surface.ts` 的 pump 改为「先唤醒再泵」。一个被挂住的会话因此不再挡住别的会话。

- 测试：`effect-outbox.test.ts`「deferred effect is not claimed before its retry window」、`remote-dispatcher.test.ts`「a deferred effect is woken by another session's pump」。
- 负向对照：把 `available_at` 过滤去掉，两项都失败。
- 迁移提醒：手工重建的旧库要同时 drop `available_at` 和它的索引（`orchestration-catalog-scan.test.ts` 的 v5 构造已照此调整）。

### R2 排队 → SIGKILL → 重启 → 恰好执行一次

原因是重启时的快照把 `queued` 映射成 `recorded`，与「已派发」区分不开，重启后要么丢、要么重复。现在 `dispatch-ledger-snapshot.ts` 明确映射，`remote-dispatcher.ts` 的 `#ledgerSettledOrDispatched(runId)` 区分三态：已派发/已终态 → 静默成功；`recorded` → 终态失败并 `outbox.fail(..., 'dispatch_fence_conflict')`。

- 测试：`src/daemon/host-process-orchestration-r2-queued-restart.test.ts`（真实子进程 SIGKILL + 重启，断言 `run.dispatched` 恰好一次），加 `remote-dispatcher.test.ts` 两项单测。
- 负向对照：两个方向各一个（丢一次 / 跑两次）。

### R3 Qoder 会话身份与每轮回调

`fresh:<runId>` 与 `native:<resume>` 分开（`qoder-session-identity.ts`），池用 `nativeAliases` 记住 native id 对应的进程，每轮有自己的 `QoderSessionTurnSlot {current, transport}`，`qoder-run.ts` 每轮写 `QoderTurnBindings {canUseTool, onExit, onPid}`——所以第二轮不再由已结束的第一轮闭包回答权限问题。

- 测试（`qoder-session-run.test.ts`）：「two new conversations never share one process」「the second turn of one conversation reuses its process」「the second turn receives its own permission request」（`firstAsks 0 / secondAsks 1`）。
- 真实 Qoder 复测见下面「Qoder 第二轮重测」。

### R4 同一项目两个新对话都能跑完

两个原因：`session-host.ts` 用同一个 key 的并发 acquire 会 `release(key,'replaced')` 关掉活会话；`antigravity-run.ts` 把所有新对话的 key 都写成 `'fresh'`，同项目两段对话撞在一起。

修法：`session-host.ts` 加 `#waiters`，忙碌 key 的并发 acquire 改为等待（由 `settle`/`release` 唤醒），只有空闲/LRU 条目才被淘汰；`antigravity-run.ts` 的 `continuationKey` 改为 `request.resume ?? request.runId`。

- 测试：`session-host.test.ts`「R4: a concurrent acquire for a busy key never closes the live session」（修前 `expected [ 'a' ] to deeply equal []`）、`antigravity-session-reuse.test.ts`「R4: two new conversations in one project both finish」（两条都 completed，`externalSessionId` 不同，`openedKeys` 两条，`spawnCount` 2）。
- 测试夹具同步加了 `sessionIdPerProcess`（`sess-fake-${pid}`）与 `installFakeAgy(extraScenario)`，第二个 run 等 `firstOpened` 之后才启动。
