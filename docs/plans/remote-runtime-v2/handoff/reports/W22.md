- **评审阻塞项 1**：`USAGE_ANALYTICS_COSTS_SQL` 用 `COALESCE(...)>0` 过滤，把「有金额但没报 Token」的账单行整行丢掉，与 JS 侧 `costRowHasUsage` 的语义相反。先写 `span-ledger-cost-rows.test.ts` 复现（`expected [] to deeply equal [...]`），再修 SQL；修复前后各跑一次该用例（修前失败、修后通过）作为对照。

- **评审阻塞项 3**：`多模型` 占位仍会变成一侧真实的模型行，且旧测试把它钉住。改为按输出 Token 归到最大模型，旧记录读取时按「没有模型」处理。
