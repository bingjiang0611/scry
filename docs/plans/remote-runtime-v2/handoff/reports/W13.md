2. **新增 [`src/main/mcp-executable-fingerprint.ts`](../../../../../../src/main/mcp-executable-fingerprint.ts)（14,353 B）**：
   - **进程内存 LRU 缓存（不写盘，上限 256 项，最长复用 10 分钟）**：
     - 目标缓存键：`realpath`（`canonical`），戳为 `stat({ bigint: true })` 的 6 元组 `{ dev, ino, size, mtimeNs, ctimeNs, mode }`，并记录 `cachedAtNs`。
     - 链接缓存键：原始绝对路径（`absolute`），戳为 `lstat({ bigint: true })` 同 6 元组 + `targetCanonical` + `cachedAtNs`；每次校验均执行 `lstat`、`realpath`、`access(X_OK)` 与 `stat`。
     - **10 分钟上限**：`MAX_CACHE_AGE_NS = 600_000_000_000n`；任一缓存项距写入时间达到或超过 10 分钟即淘汰并重新哈希。
   - **2 s 时间戳粒度保护**：以 `hashStartedNs - ctimeNs >= 2_000_000_000n`（且 `hashStartedNs >= ctimeNs`）为入缓存门槛；目标文件或符号链接任一 `ctime` 距计算不足 2 s 时不写缓存并清除旧项。
   - **权限位纳入身份**：`executableIdentity` 包含 `${stamp.mode}`（`${canonical}:${dev}:${ino}:${size}:${mode}:sha256:${digest}`），仅改权限位也会改变快照指纹并在启动边界被拒。
   - **分块异步哈希与复核**：`resolveMcpExecutableFingerprintAsync` 使用 `fs/promises` 的 `open(canonical, O_RDONLY | O_NOFOLLOW)` 与 `256 KiB` 分块 `handle.read`，每块让出事件循环；打开后先校验 `beforeStamp` 与 `stat(canonical)` 一致，哈希后复核 `fd` 6 元组、`stat(canonical)`、`lstat(absolute)` 与 `realpath(absolute)`，任一漂移即报错 `executable changed while hashing`。
   - **同步与异步路径的同一文件计算结果共享**：
     - 并发冷异步请求通过 `inFlightTargetAsync`（按 `${canonical}:${dev}:${ino}:${size}:${mtimeNs}:${ctimeNs}:${mode}` 分键）共享同一哈希 Promise，并发冷请求只算一次；每个调用方在 `await` 后仍独立复核自身 `lstat`/`realpath` 并维护 `linkCache`。
     - 同步路径与在途异步路径共享同一 `targetCache`：若在异步分块期间有同步请求率先完成同一不变文件戳的哈希并写入缓存，异步循环在下一块前检测命中、提前结束读循环并仍执行完整哈希后复核，避免重复计算。
     - 单次 `buildMcpExecutionSnapshot` / `buildMcpExecutionSnapshotAsync` 内部传递本次快照专属的 `runMemo`（按目标完整 6 元组戳分键），同一配置内多个 MCP 服务器指向同一可执行文件（即便 `ctime < 2 s`）也只计算一次，且不跨门禁与启动边界复用（保持 2 s 保护不变）。

## 3. 冷哈希同步路径与残余安全限制（如实说明）

### 仍会在冷态同步计算的路径
以下调用点在目标可执行文件**冷态（缓存未命中）**时仍调用同步 `buildMcpExecutionSnapshot`（热态命中共享缓存时只做 `lstat/realpath/access/stat`，不重算 SHA-256）：
- `mcpGuardScan`（`src/main/bootstrap/mcp-channels.ts:153`）
- `agent:reauthenticateMcp` 认证后复核（`src/main/bootstrap/mcp-channels.ts:119`；注：同一流程第 104 行刚经异步 `ensureMcpExecutionAuthorized` 预热缓存，非 `ctime < 2 s` 且未变化时会命中缓存）
- 远端工具面板 `mcpTrust`（`src/main/bootstrap/remote-host.ts:71`）
- `on` 模式下 C 的编排门禁（`src/daemon/orchestration-trust-gate.ts:155`，按要求不修改 C 的文件）
- 启动边界同步复核 `authorizedMcpExecution`（`src/main/bootstrap/trust.ts:229`，仅在未命中缓存如被篡改或 `ctime < 2 s` 时同步重算并 fail-closed）

### 残余限制：内容变化但状态戳不变的场景
- **可写共享内存映射（`MAP_SHARED`）**：在 Linux（如 ext4、tmpfs）上，通过已建立的可写 `mmap(MAP_SHARED)` 修改文件内容时，内核通常仅在页面首次变脏时更新 `mtime`/`ctime`，后续同页改写可能不推进时间戳。
- **网络文件系统与 FUSE**：NFS、SMB 或带属性缓存的 FUSE 挂载点可能返回缓存的 `stat`/`lstat` 元数据，导致短时间内未观测到远端内容变化。
- **缓解与边界**：进程内缓存已施加 **10 分钟最长复用上限**，超过即强制重算 SHA-256；该限制属于本地可写权限下的既有 TOCTOU 边界（拥有可执行文件写权限的本地攻击者本来即可在启动瞬间竞争改写），Scry 不是内核级沙箱。
