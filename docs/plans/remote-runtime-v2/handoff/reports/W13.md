## 2. 改动与设计

1. **新增 [`src/main/mcp-executable-fingerprint.ts`](../../../../../../src/main/mcp-executable-fingerprint.ts)（10,376 B）**：
   - **进程内存 LRU 缓存（不写盘，上限 256 项）**：
     - 目标缓存键：`realpath`（`canonical`），戳为 `stat({ bigint: true })` 的 6 元组 `{ dev, ino, size, mtimeNs, ctimeNs, mode }`。
     - 链接缓存键：原始绝对路径（`absolute`），戳为 `lstat({ bigint: true })` 的同 6 元组 + `targetCanonical`；每次校验均执行 `lstat`、`realpath`、`access(X_OK)` 与 `stat`，链接本身被替换（即便仍指向同一目标）也会使链接缓存失效。
   - **2 s 时间戳粒度保护**：以 `hashStartedNs - ctimeNs >= 2_000_000_000n`（且 `hashStartedNs >= ctimeNs`）为入缓存门槛；目标文件或符号链接任一 `ctime` 距计算不足 2 s 时不写缓存并清除旧项。
   - **权限位纳入身份**：`executableIdentity` 现包含 `${stamp.mode}`（`${canonical}:${dev}:${ino}:${size}:${mode}:sha256:${digest}`），确保仅改权限位（如 `0o700 -> 0o755`）也会改变快照指纹并在启动边界被拒。
   - **分块异步不阻塞主线程**：`resolveMcpExecutableFingerprintAsync` 使用 `fs/promises` 的 `open(canonical, O_RDONLY | O_NOFOLLOW)` 与 `256 KiB` 分块 `handle.read`，I/O 在 libuv 线程池执行、每块间让出事件循环（无 Electron `asar` worker 路径/启动开销）；哈希前后复核 `fd` 6 元组、`stat(canonical)`、`lstat(absolute)` 与 `realpath(absolute)`，任一漂移即报错 `executable changed while hashing`。
   - **同步回退说明**：启动边界的 `authorizedMcpExecution` 仍为同步函数（被多处同步启动路径直接调用）；因门禁检查 `ensureMcpExecutionAuthorized` 已先以异步路径完成哈希并填充缓存，热路径下同步复核仅做 `lstat/realpath/access/stat` 并命中缓存（不重算 SHA-256），仅在缓存未命中（被篡改或 `ctime < 2 s`）时同步重算并 fail-closed。
2. **修改 [`src/main/mcp-execution-trust.ts`](../../../../../../src/main/mcp-execution-trust.ts)（34,189 B，较原 34,346 B 净减 `-157 B`）**：
   - 抽取共享准备与快照收尾逻辑，导出 `buildMcpExecutionSnapshotAsync`；原同步 `buildMcpExecutionSnapshot` 复用同一指纹缓存模块。
3. **修改 [`src/main/bootstrap/trust.ts`](../../../../../../src/main/bootstrap/trust.ts)（9,673 B，较原 10,046 B 净减 `-373 B`）**：
   - `ensureMcpExecutionAuthorized` 改为单次 `await buildMcpExecutionSnapshotAsync(...)`，移除原先紧邻的无间隔重复 `build()` 调用；启动边界 `authorizedMcpExecution` 保留完整复核。
4. **未触碰范围**：未改 orchestration 文件（含 `src/daemon/orchestration-trust-gate.ts`，零依赖）、Antigravity 文件、host-admin 文件、`src/cli/` 与协议版本。
