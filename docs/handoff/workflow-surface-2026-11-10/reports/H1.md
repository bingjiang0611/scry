# H1 · 启动窗口停止（CLI 1.1.89）

**通过 R8 的三次有效停止与一次负对照。** 基线 `9b185959`，macOS arm64；每例用全新临时 userData、工作区和调试端口，`scry init`、`SCRY_PROVIDER_EVENT_LOG=1`。真实指针点击并截图，逐例保存主进程标准输出，仅把脱敏结构与日志字节数、SHA-256 交到 [H1 证据](../evidence/r8/h1-startup.json)。

| 场景 | 发送到停止点击 | 实时 UI | 原轮次 native | 原 run 的守护进程 | 下一轮 |
|---|---:|---|---:|---|---|
| 早期 | 114 ms | 本轮已中断 | 0 | 主进程完整标准输出中从未出现该 run 的 `started` | `completed`，有 Provider turn id |
| 中期 | 367 ms | 本轮已中断 | 0 | 同上 | `completed`，有 Provider turn id |
| 后期 | 712 ms | 本轮已中断 | 0 | 同上 | `completed`，有 Provider turn id |
| 不点停止的负对照 | 未点击 | 无中断提示 | 22 | `started` +21,065 ms，`query closing`/`stopping` +50,639 ms，`stopped` +53,544 ms（相对发送） | 当前轮 `completed`，有 Provider turn id |

三次停止均在 1 秒内，且有一次在 200 ms 内；无 Provider native 的原轮次没有伪造终态或 `.scry/records`。主进程日志筛选 `owner: run:<对应 runId>`；三次均无 `started`，因此也没有该 run 的 `stopped` 事件，符合「启动之前停止」分支。负对照没有被误停。截图和原始标准输出留在本机 `/tmp/scry-r8/`，不上传提示词、路径或进程 ID。

**未计入样本**：另一次 33 ms 停止已显示中断、native 为 0，但下一轮的守护进程因 recorder CLI 校验失败未能启动，伴随 5 秒版本探测超时；无法证明续发，所以没有算作有效停止。没有改超时或重发该轮。四个有效场景分别使用独立实例，主检出与日常 App 未受影响。
