# G2 · 两轮同一会话里,卡片入口 + 手动切换 + 流式更新

**结论**：把「chat 卡片要求选中 A → 用户手动选 B → A 又来一帧流式更新」这个组合做成 fixture 模式 `focus`，接进 `npm run test:workflow-ui`。检查在 1180px 与 460px 两个宽度都通过；把 `takeWorkflowRunRequest` 里清空请求的那一行删掉后，同一条检查**真的失败**，报 `a stream update dragged the selection back to run-1\u0000toolu_workflow_a`。

## 一个诚实的限制：选项列表点不了

`<select>` 的选项列表是操作系统级菜单,不是 DOM。headless 窗口里 `sendInputEvent` 的 Down 键既不改变选中值,也不驱动原生菜单（已单独实验确认：隐藏窗口 `document.hasFocus()` 为 false；`BrowserWindow` 被激活策略禁止成为 key window 时同样无效）。所以这次「选第二个 run」由页面内派发一次 `change` 事件完成——这正是真实选择会产生的事件——断言的重点在**选择之后的状态**。

指针路径没有被这次检查覆盖：chat 卡片按钮 → 面板选中对应 run 的真实指针点击在 `npm run test:workflow-archive`（第一轮 D）里已经用真实 CDP 指针事件验证过。这次没有重复造一个假的点击。

如果以后要把指针也纳入这条检查,需要把 fixture 改成可交互的 `<select>` 替代控件——那属于改产品 UI,不在本轮范围。
