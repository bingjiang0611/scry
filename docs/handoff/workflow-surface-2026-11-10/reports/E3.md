# E3：两个会话并发与第四轮 A 进程消失的采证

**部分成立，第四轮 A 消失的直接原因仍不能定论。** 新一轮在 A 已开始输出后才切换；A 与 B 各有不同的 `qodercli --sdk` PID。一次测试中，B 点停止 12 秒后 A 的 PID 仍存在；另一次 A 在 B 停止前自然完成，native 流给出 `result/success`。旧第四轮 A 的 native 流既没有回答也没有 `result`，且当时没有保存 main 日志，不能凭「本次不互杀」倒推旧 A 一定是测试步骤、Scry 停止或守护进程自行退出。

测试实例均为新的临时 userData、临时 Git 工作区、独立调试端口，`SCRY_PROVIDER_EVENT_LOG=1`、真实 CDP 指针点击。E3 为隔离两轮运行的生命周期，**未运行 `scry init`**；前一次带 recorder 的尝试在 A 输出前因本机 recorder CLI 验证失败，未进入并发步骤。`e3-plain`、`e3-isolation` 的 `psTimeline` 是每秒取样、只保存 PID 变化时的完整 `ps -axo pid,ppid,lstart,command` 行；第三次保存了每秒快照，但因 A 未输出不构成双会话案例。主进程 stdout/stderr 中 stop、interrupt、forceKill 的过滤结果为空，**空日志不证明 Scry 没有发过停止**：该版本可能不记录该动作。

源码只读核对：`src/renderer/app-session-actions.ts` 新建会话调用 `focusRun(null)`、`newSession(...)`；`src/main/bootstrap/workspace.ts` 的 `agent:newSession` 重置会话上下文并调用 Provider `invalidateContext`，而 Qoder adapter 没有该方法。此路径没有显式停止旧 run。该事实与本次 A 存活相符，却不足以证明旧现场的具体退出原因。

**未满足**：B 停止后在 A 页面上读回新增正文。切回 A 时界面只显示会话壳（`tok —`），未能证明 A 继续输出；旧 A 的退出原因缺少其时主进程信号日志，无法恢复。若要进一步定位，需要在**允许的诊断层**对 run-scoped PID 的退出原因和 stop 调用留下可归属日志，不改运行登记或停止语义。本包不改产品代码；E5 的「E1–E4 全部通过」前提不成立。
