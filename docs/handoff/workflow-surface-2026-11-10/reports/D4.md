# D4：干净 worktree 门禁

结论：四道门禁里 **三道通过**（`typecheck`、`test:renderer:ui`、`pack:artifact`），
`test:unit -- --maxWorkers=1` **退出码 1**：18 个用例在 5 秒超时，全部是 `Test timed out in 5000ms`。
同一个机器上用 `origin/main` 做对照，同类用例同样 5 秒超时，因此判定为**本机负载导致的超时**，
不是本次改动引入；但按要求不修改测试超时，也不把它写成通过。

### 对照：`origin/main` 同样超时

在 `origin/main` 的独立 worktree（`/tmp/scry-main`，`npm run build` 已通过）上跑其中 5 个失败文件：

```
Test Files  2 failed | 3 passed (5)
     Tests  6 failed | 48 passed (54)
```

失败的两个文件是 `scripts/check-pacman-package.test.mjs`（4 条）与 `src/cli/managed-tool-hooks.test.ts`（2 条），
同样是 `Test timed out in 5000ms`（共 11 处超时记录）。也就是说：**这个 5 秒预算在本机当前负载下不够用，
与本次 Qoder 迁移无关**。

本分支复跑 `pi-lifecycle` / `pi-commands` / `pi-transport` / `commit-environment` / `content-copies-crash`
这 5 个文件，仍有 8 条超时，且每次跑失败的用例集合不同（这一轮是 `pi-lifecycle` 的另外 4 条），
进一步说明是负载抖动。

按要求**没有**调大测试超时、没有跳过用例、没有放宽门禁。

## 未验证

  上述失败集中在 Pi 与打包脚本，且 `origin/main` 同样失败，因此判断无关；这是推断，不是证明。
