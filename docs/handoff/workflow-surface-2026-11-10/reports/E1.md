# E1：三种时机停止的真实复测

**未通过；停止本包的进一步试验。** 在已登录 `qodercli 1.1.86`、SDK 1.0.59、`f2f11334` 的独立 App 和带 `scry init` 的新工作区上，启动窗口点停止三次；两次真实进入中断，一次停止点击未使轮次中断。Hook 已出现但模型未回答时，有一次中断后 recorder 报 `managed recorder open identity is not available yet`。该错误涉及 R5 明令不得改变的 managed recorder 身份/提交边界，因此不通过补丁或绕开 recorder 来刷绿。没有继续声称完成「三种时机各至少三次」。

|---|---:|---|---|---|---|

统计脚本逐行扫描各测试 `userData/provider-event-log/*/*.ndjson` 的 `stream=native`、`payload.type=system` 且 `subtype=hook_*` 的帧，只保存类别计数和非空 ID 的 distinct 数，不提交原生帧（包含提示词/环境）。六例合计 **有值 55、空串 0、缺失 0**；有 hook 的四个案例各只有一个非空 session ID。这说明这些样本没有复现「空字符串被当作 ID」，**不能**证明所有时机不会出现空串。`trace-turn-progress/` 在取样点均没有 JSON 文件；`hook-1` 的失败发生在 managed recorder 的 open identity，而非该目录的 `missing_provider_session_id`。

每例 `evidence/r5/e1-*.json` 保存经过 HOME→`~` 脱敏的 `ps -axo pid,ppid,lstart,command` 前、停止时、停止后、后续轮次、退出后的快照；截图 `evidence/screens/e1-*-stop.png`。事件日志未出现足以将 `startup-1` 认定为中断的终态，不能用「点到了按钮」代替成功。`hook-2` 与 `startup-2` 遇到本机高负载下的 recorder CLI 验证/版本探测 5 秒超时；无证据表明是网关或安全软件拒绝。

**未完成**：Hook 时机有效中断不足三次；模型输出中途零次。再做这两项之前，需要维护者决定如何处理 `managed recorder open identity is not available yet`（涉及已禁止修改的身份/提交边界），以及区分 CLI 验证超时和 recorder 故障。这里不改变 trace 恢复判据、不清理任何 pending 文件、不改停止语义。
