# G4 · C7 与相邻路径：一个实例里切换 Claude 以外的会话

**结论**：在同一个 test 实例里，会话 A 是真实的 Codex 两个子 Agent 轮次，会话 B 是真实的 OpenCode 一轮（0 工具）。Workflow 标签始终开着：切到 B 时面板是空态、没有残留 A 的任何运行或「状态未知」；Agents 面板同样按会话分开（A 两个子 Agent，B 明确说本会话尚未观测到）；切回 A，两个子 Agent 又回来了，Workflow 仍是空态。

## 场景与结果

| 步骤 | Workflow 面板 | Agents 面板 |
|---|---|---|
| A：Codex，`spawn agent` 两个子 Agent（129.7k in / 8 工具 / 45.7s） | 空态「本会话尚未观测到 Workflow」 | 子 Agent 2：`count_files`、`read_readme`，都「已完成」 |
| 新建会话 B：OpenCode，真实一轮（6.4k in / 0 工具） | 空态，文本与 A 相同；没有 B 之外的运行 | 子 Agent 0：「本会话尚未观测到子 Agent」 |
| 切回 A（Workflow 标签一直开着） | 空态；仍无残留 | 子 Agent 2 恢复 |

证据：`evidence/screens/g4-switch-a-workflow.png`、`g4-switch-a-agents.png`、`g4-switch-b-workflow.png`、`g4-switch-back.png`。

## 一个观察（不是缺陷）

切回 A 的瞬间，第一次读取（1.5s 后）拿到的是「右面板没有 `[data-session-surface-current]` 元素」——也就是面板正在按会话重新挂载。逐级等待后复测：500ms、1s、2s、3s 都稳定返回同一个空态，标签也还在（`总览 | Workflow | Agents`）。所以这是切换过程中的短暂重挂载，不是面板丢状态。

## 没做到的（重要）

R2 这一段想验的是「切走再切回时，Workflow 面板不会留着上一个会话的**运行**」。本机 Claude 被阻塞（见 [G1](G1.md)），我拿不到一个带真实 workflow 行的会话，于是这条只能验到「没有运行泄漏」，验不到「有运行时不丢/不串」。

试过的办法和为什么停：

- 用归档回放（第一轮 D 的做法）在一个实例里造一个有 workflow 行的会话：`app-sessions.json` 里写入了这一行，但侧边栏显示「暂无会话」。第一轮 D 的冒烟是在**临时 HOME** 里同时种了 Provider 原生 transcript 才显示出来的；这次要在同一实例里跑真实 Codex/OpenCode（需要真实 HOME 的登录态），两者不能同时满足。
- 往**真实 HOME** 的 `~/.claude/projects/<临时 cwd>/` 种一份 transcript：立刻把真实历史里的无关 Codex 会话带进了侧边栏。这是干扰用户数据，我停手并清理了。
- 没有为此改 App 的会话列表逻辑，也没有造假会话。

要做完整这条，最小前置是：Claude 能跑（真实 workflow 会话），或给测试实例一个「只信任 fixture 会话」的开关（属于产品改动，本轮不做）。

## 复现方式

脚本在 `/tmp/scry-g4/real.mjs`（一次性工具，未进仓库）：`/tmp/scry-g1/harness.mjs` 起独立实例（临时 userData、临时工作区、真实 HOME、`SCRY_TEST_APP=1`、`SCRY_PROVIDER_EVENT_LOG=1`），`SCRY_OPENCODE_PATH` 指向支持范围内的 `opencode` 1.18.31；所有点击都是 CDP 真实指针事件。
