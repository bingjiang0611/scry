# G4 · OpenCode 空状态：整轮测量 + 真实指针切换回来仍是空态

**结论**：用 Scry 自己声明的支持版本（`opencode` 1.18.31）在真实 App 里跑通了一整轮 OpenCode 会话。Workflow 面板是空态，文案不与 OpenCode 的能力冲突；用真实指针切到「总览」再切回来，面板仍是同一个空态，没有出现「状态未知」的零行运行。canonical 流 71 行，`workflow_activity` 为 0，没有任何 `task_*` 事件。

## 先解决一个环境前提

本机装的 `opencode` 是 2.2.6，发送后 `POST /session → HTTP 405`（见 [G1](G1.md)）。用手工起的服务复现：2.2.6 的 `POST /session` 就是 405，`@opencode-ai/sdk` 1.18.25 打不通它。

于是我装了仓库兼容性清单里的版本，用 Scry 自己的覆盖变量指过去：

| 项 | 值 |
|---|---|
| CLI | `opencode-ai@1.18.31`（npm 安装到 `/tmp/scry-oc`，用包自己的 postinstall 取平台二进制） |
| 指向方式 | `SCRY_OPENCODE_PATH=/tmp/scry-oc/node_modules/.bin/opencode`（`src/main/claude-locate.ts` 里的官方覆盖项） |
| 是否改产品代码 | 没有 |
| 是否换启动方式 | 没有：Scry 仍然自己 spawn `opencode serve --hostname --port`，只是换了可执行文件版本 |

**顺带发现一个不一致**（没改，记录在此）：把 `/tmp/scry-oc` 放在 `PATH` 最前面时，`detect()` 报的路径是 1.18.31，但真正去跑的是 `~/.opencode/bin/opencode`（2.2.6）。原因是运行期用的是「登录 shell PATH + 进程 PATH + 附加目录」拼出来的路径，登录 shell 里的 `~/.opencode/bin` 排在前面，而版本探测用的是进程 PATH。界面显示与实跑二进制可能不是同一个。

## 空态文案与切换

| 断言 | 结果 |
|---|---|
| 面板是空态而不是零行运行 | `.workflow-phase` 0、`.workflow-agent-chip` 0、没有「状态未知」 |

## 一条要说清的观测

同一个截图里，composer 显示「版本探测超时（5s）」+「重新检测」。这是那个 npm shim 版 `opencode --version` 太慢导致的探测超时，**不影响**这一轮运行（运行走的是 server 模式，日志与轮次都完整）。我没有为了让它变绿去改超时。

## 未验证 / 限制

1. 装在本机的 2.2.6 仍然跑不通；要支持它需要改 OpenCode 适配层（服务端 API 变了），属于功能改动，本轮不做。
2. 这轮 OpenCode 会话没有子 Agent（提示词明确要求不用工具），所以「OpenCode 子 Agent 显示」没有真实样本；G1 里 OpenCode 是阻塞项，本来就没有样本。
3. 只在 `claude/sweet-ptolemy-qxysuh` 的 worktree 构建上验证；本机主检出在验证期间被切到了另一个分支（`claude/gracious-feynman-nlrtdp`），所以改在 `/tmp/scry-b2` 的 worktree 里跑，`node_modules` 软链接到主检出。分支本身没有被改动。
