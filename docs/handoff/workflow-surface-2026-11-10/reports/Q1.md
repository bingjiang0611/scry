# Q1 · Qoder 能不能跑起来

**结论**：只升 SDK 不够。本机装的 `qodercli` 1.1.86 在 SDK 1.0.57 下仍然 `exit 42`，stderr 只有一句 **`sdk_worker_removed: SDK worker sessions are no longer supported. Upgrade to the latest Qoder SDK version, or roll back the CLI to 1.1.80 or earlier.`** 1.1.81 也一样拒绝。换成 **CLI 1.1.80**（用 Scry 自己的 `SCRY_QODERCLI_PATH` 指向）后，真实 App 里的 Qoder 一轮跑通。

这条与 [R3](R3.md) 的表格有出入：R3 写「1.0.57 配套 CLI 1.1.81」，但 CLI 自己的说法是 **1.1.80 或更早**。以 CLI 的报错为准。

## 三次尝试

| CLI | SDK | 结果 | 证据 |
|---|---|---|---|
| 1.1.86（本机装着的） | 1.0.57 | `exit 42` | App 显示 `Qoder CLI process exited with code 42`；tok 0 / tools 0 |
| 1.1.81（npm 装到临时目录） | 1.0.57 | `exit 42`，同一句 stderr | 仓库外探针 |
| **1.1.80**（npm 装到临时目录） | 1.0.57 | **跑通** | 探针事件流正常；App 真实一轮完成 |

仓库外探针：`/tmp/scry-q1/probe/qoder-sdk-probe.mjs`，与 Scry 用同一份 SDK（1.0.57）、同一个 `qodercliAuth()`、同一种可执行文件解析（都指向 CLI 的 JS bundle）、同样的 `permissionMode: 'default'`。唯一多出来的是把 `stderr` 接到管道上——`stderr`/`stderrHandler` 是 `ProcessTransport` 的选项，不是 `query()` 顶层选项，所以探针自己包了一层 `new ProcessTransport({...options, stderr:'pipe', stderrHandler})`，这与 Scry 现有的 `QoderTaskControlTransport` 包法一致。

失败的 stderr 原文（脱敏后只有颜色转义，无路径无凭据）：

```
sdk_worker_removed: SDK worker sessions are no longer supported.
Upgrade to the latest Qoder SDK version, or roll back the CLI to 1.1.80 or earlier.
```

Qoder 自己的日志（`~/.qoder/logs/qoder-context.log`）里没有这条：它只在 stderr 上出现，日志里是别的组件的 SSE 重连与 `Config resolve failed: HTTP 429`，与本次启动无关。

独立 test 实例（临时 userData、临时工作区、真实 HOME、`SCRY_TEST_APP=1`、`SCRY_PROVIDER_EVENT_LOG=1`、CDP 真实指针），`SCRY_QODERCLI_PATH` 指向 1.1.80：

| 项 | 值 |
|---|---|
| 提示词 | `只回复一个字：好。不要用任何工具。` |
| 结果 | 回答「好」；`in 29.8k / out 3 / cache·r 21.9k / dur 6.3s / api 3.8s / tools 0` |
| 事件 | canonical 60 行：`hook/hook_response` 19、`hook/hook_started` 17、`input_receipt` 2、`llm_stream_end` 1、`result` 1、`credit_usage` 1；`workflow_activity` **0** |
| native | `system` 12、`command_lifecycle` 3、`assistant` 1、`result` 1 |

`system/init`（第一次 init）：`model: "Ultimate"`、`permissionMode: "default"`、`apiKeySource: "none"`、`cwd` 是临时工作区、`session_id` = `ed943865-…`。工具 19 个：

```
Agent, AskUserQuestion, Bash, Edit, Glob, Grep, ImageGen, ImageSearch, NotebookEdit,
```

## 需要维护者决定的事（本轮不动）

1. **配对关系要改正**：1.0.57 能用的 CLI 上界是 **1.1.80**，不是 1.1.81。若要继续用「每轮一个子进程」的模型，安装说明或兼容性清单里应写明 CLI ≤ 1.1.80。
2. **本机 1.1.86 仍然跑不起来**：它要求 SDK ≥ 1.0.58，也就是守护进程模型。按本轮边界我不升，也不改进程登记/停止/环境注入/认证。
3. 后续 Q2 的回归全部在 **CLI 1.1.80** 上做；本机默认 1.1.86 的失败状态保留原样，报告里分别标注。
