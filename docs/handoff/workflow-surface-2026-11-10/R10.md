# 第十轮：后台 Agent 记录复测与分支会话 ID 采证

## 审查方对第九轮的核验（2026-11-16）

**I1 通过（3/3）**：Hook 窗口停止后不用重启就显示中断，每次各有一条带 Provider turn id 的 `interrupted` 记录，pending 目录为空，下一轮正常。第八轮 H4 的问题已在 CLI 1.1.89 上解决。

**I2 的计数定位了根因**，已修复：

> commit turn id present; 2 lifecycles: 0 with a turn id, 2 from this run, 0 listing it as a continuation; 0 matched

CLI 1.1.89 的 hook 载荷不带 prompt id。每个后台任务的通知都会作为**同一 run** 里的又一次 `UserPromptSubmit` 到达，文本不同，于是替换了本 run 的 open lifecycle，留下多个都没有 turn id 的 lifecycle，提交时无从选择。审查方第八轮写的测试用了带 prompt id 的载荷，所以没能复现。现在按真实形状（无 id）写的测试能复现，计数与 I2 一致。

| 提交 | 内容 |
|---|---|
| `88eb6b1c` | 纯拆分：把会话收件箱的重放从 `recorder-hook-locked.ts` 移到 `recorder-hook-inbox.ts`（该文件已到 20KB 门禁），行为不变。 |
| `941a3fc4` | 一个 Scry run 只启动一个 Qoder 守护进程，带一个 managed 身份；recorder 从守护进程的环境变量读取这个身份，从不信任载荷。带同一身份的后续 prompt 改为并入当前轮次，不再替换。来自别的 run 的 prompt 仍然开新轮次（有负对照）。 |

**I3 的计数**：该会话在其他工作目录下有 0 份归档；本工作目录下有 1 个其他会话的归档。说明工作目录的键是对的，问题出在**会话 ID 对不上**：分支请求的会话 ID 不是这一轮归档时用的那个。审查方的怀疑：CLI 1.1.89 的守护进程可能不再采用 Scry 预设的会话 ID，同一个 run 里先后公布了两个不同的会话 ID，会话列表和归档各用了一个。代码层面还不能确认，本轮补了两项诊断（`3110f66d`）：

- 分支报错现在还会说明：「其中几个以这一轮结尾」「会话列表有没有请求的会话」「有没有归档这一轮的会话」。
- 主进程日志对每次会话 ID 采用记一行 `[scry] qoder session adopted`，内容是 `preset`（是否 Scry 预设的 ID）和 `adoptions`（第几次采用），不含 ID。

容器内验证：4,937 条测试通过，另有 4 条已知环境失败（2 条 root 权限、2 条 root 下的 Chromium）；`typecheck` 与 `build:cli` 通过；新增用例在旧代码上会失败。

**I4**：打包按原路径重试后通过；unit 有 7 条超时，与第八轮测得的 node 启动 0.9 秒一致，属于环境成本。

## 工作包

### J1：两个后台 Agent（复测 I2）

- 收口后 `.scry/records` 增加 1 条 `completed` 记录，有 Provider turn id；三个 pending 目录为空；没有 recorder 报错。
- 时间线照第九轮格式交出，`query closing` 必须晚于最后一个 `result`。
- 再发一轮普通提问，正常完成。

### J2：新会话的会话 ID 采证（为 I3 定位）

在新对话里发一轮普通提问，等它完成，然后：

1. 主进程日志里该 run 的所有 `session adopted` 行：交出每行的 `preset` 和 `adoptions`。
2. native 帧里出现过几个不同的非空 `session_id`；第一个非空 `session_id` 出现在第几帧。
3. 点「在新会话中分支」。失败就交出报错括号里的全部内容；成功就确认新会话能发送一轮并完成。

只交是否和计数，不交 ID。

### J3：回归

Hook 窗口停止一次、输出中途停止一次、长命令审批允许一次，都要实时收口。

### J4：清单

J1、J3 通过，J2 的分支成功，才可以把 Qoder 的 `>=1.1.80 <1.2.0` 改为 `supported`。否则不改。门禁本轮不跑（第九轮已有结果，产品改动只涉及 recorder 与诊断），除非 J1–J3 全部通过。

沿用 README、R4–R9 的全部条件。新增：J1 里同一个 run 出现两条记录，或者出现一条没有 Provider turn id 的 `completed` 记录：立即停下，保留现场。
