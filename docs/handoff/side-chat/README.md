## 1. 已确认的产品合同

| 项目 | 决定 |
| --- | --- |
| 目的 | 临时岔开去提问或做改动，不打乱主会话的对话上下文 |
| Provider | Claude、Codex、Qoder、OpenCode、Pi 都纳入首版范围；不假装能力完全一致 |
| 上下文 | 冻结主会话截至最近已完成轮次的用户消息、助手正文；不是原生 fork |
| 主聊运行中 | 直接读取已完成消息，不接管、不迁移主聊，不等待当前轮结束；没有已完成消息时明确不可用 |
| 保存 | 长期保存；关闭页签、隐藏面板、退出 App 都不等于删除 |
| 关联 | 每个主会话有自己的多个侧聊；切换主会话时跟随切换 |
| 执行 | 完整 Agent；主聊与侧聊、多个侧聊可以并行 |
| 文件 | 共用同一工作区；改动立即互相可见，不做 worktree 隔离、不设合并步骤 |

**一句话：隔离的是对话，不是文件。** 这句话用共享工作区标识与上下文来源表达，不每轮弹提醒。

## 2. 设计方向

本表面为 **Operate**：用户在主任务旁开启独立工作，不需要学习新的导航。沿用 `DESIGN.md` 的「执行观察室」：低饱和中性色、细分隔线、蓝色只标当前焦点与主操作、琥珀色只表示需要注意。复用 Scry 现有侧栏、右侧工具面板、正文列和圆形发送按钮，不照抄 Codex 品牌。

```text
项目 / 主会话                 主会话正文                 右侧工作面板
├ 当前主会话                 标题 · 运行状态             文件 | 侧聊 A | 侧聊 B | +
│ └ 侧聊 2 · 1 需处理        主任务继续运行               侧聊标题 · 独立状态
└ 另一个主会话                                          来源：主会话 · 截至第 8 轮
                            工具 / 输出                 共用工作区
                            …                          当前侧聊输出 / 审批
                            主聊输入框                 侧聊自己的输入框
```

右侧用**一层平级页签**承载工具和侧聊，不再套一层「侧聊列表」。工具页签仍然只有一份；侧聊可以有多个实例。侧聊不是 Agents 子 Agent，它由用户独立驱动。

## 3. 核心操作

1. 入口放在用户指定的「打开一个 Surface」选择器：最上方增加一张横向「侧边会话」卡片，文案为「带入主会话快照，独立提问或修改代码。」下方六个工具保留原顺序与文案。页签栏 `+` 仍打开工具选择菜单，菜单也有同名入口；点击 `+` 本身不创建会话。主会话顶部只保留工作区入口，不另设一个直接创建侧聊的图标。
2. 只读主聊已完成的消息，创建持久侧聊并固定来源轮次；主聊继续运行，不要求转换管理方式。默认沿用来源 Provider / profile / model / effort，权限仍需通过当前 Provider 校验，不跨 Provider 沿用旧审批。
3. 右侧出现空态与输入框，主会话不导航、不重置滚动、不停止。**创建不发送，也不调用模型生成标题。** 空侧聊也保留，可显式删除。
4. 用户第一次发送后，使用首次问题的截断文本作标题，可手动重命名。两侧的运行、停止、审批、错误与草稿相互独立。
5. 点击侧聊页签的关闭按钮只关闭视图，运行继续。关闭最后一个页签回到 Surface 选择器。侧栏显示该主会话的侧聊数量，以及运行/待审批数量。通过「历史侧边会话」列表选择要恢复的会话，不直接恢复列表里的任意一条。
6. 切换主会话，右侧切换到它自己的页签集与活动页签；旧侧聊继续运行。恢复 App 后恢复布局与草稿，但不自动续发、不自动重跑。

设计稿默认展示截图对应的深色 Surface 入口；顶部可切换进行中、空侧聊、发送失败、窄窗口和深浅主题。可点击入口创建侧聊，使用 `+` 菜单、历史列表、切换主会话与页签、查看快照。所有运行状态均为示例；六个工具只预览入口，不模拟真实工具功能。

## 4. 快照怎么让人理解

常驻一行：`主会话快照 · 截至第 8 轮`。点击查看详情：

- 来源标题、冻结时间、截止轮次、已包含消息数。
- 主会话当前第 9 轮尚未完成：明确「不含正在生成的第 9 轮」。选择边界时也排除尚未完成证据提交的轮次。
- 包含用户消息与助手正文；不重放历史附件、隐藏推理、工具状态。需要图片或文件时重新附加。工作区文件是实时的，不是冻结文件版本。
- 消息完整带入、部分通过受限历史检索提供、正文缺失，分别展示；不把后两者叫作「全部上下文」。预算不足且 Provider 无可靠历史检索时拒绝创建，提供缩小范围后重新预览；不静默截断或自动摘要。
- 来源后续变化不会自动同步；首版不提供「刷新快照」以免改变已发送会话的上下文。需要新的上下文就新建侧聊。

来源消息在侧聊顶部默认折叠为「查看来源快照」，不要复制一长段主聊正文占满右栏。快照只读；新回复才属于侧聊自身记录。

## 5. 布局与响应式

| 区域 | 默认设计 | 行为 |
| --- | --- | --- |
| 项目侧栏 | 约 208 px，沿用现有折叠能力 | 主会话下增加侧聊计数/状态，不把所有侧聊平铺到顶层 |
| 中间主聊 | 占剩余聊天区约 55% | 正文宽度受限；输入框固定在自己的列底部 |
| 右侧面板 | 约 45%，最小 400 px | 沿用 PaneSplitter；键盘可调；关闭后恢复上次宽度 |
| 页签栏 | 水平滚动，保留 `+` 和历史入口 | 长标题省略，完整标题可访问；状态不只靠颜色 |
| 窄窗口 | 可用聊天区不足 880 px 时只展示一列 | 顶部「主会话 / 右侧工作区」切换，右侧可展示选择器、工具或侧聊；后台运行照常 |

低高度窗口把工具卡片的图标与标题放到同一行，保留描述与双列排列；更小窗口允许选择器内滚动。快照来源与共享工作区使用紧凑的两行信息，不用整条警告色抢占聊天内容。阈值是设计起点，实现时使用现有布局测量，不新增全局 window resize 轮询。

首次打开自动聚焦侧聊输入框；切换页签恢复该页签焦点/草稿；关闭活动页签后聚焦相邻页签。打开快照使用可关闭对话框、焦点陷阱与关闭后焦点恢复。Tab 按 DOM 视觉顺序；页签支持方向键、Home/End。快捷键建议 `⌥⌘S` / `Ctrl+Alt+S`，实现前核对现有键位和系统冲突，不在设计稿中假装已注册。

## 6. 状态与文案

| 状态 | 呈现与操作 |
| --- | --- |
| 创建中 | `正在保存快照…`，不允许再次提交相同意图 |
| 空侧聊 | `换个角度，继续探索`；显示来源与共享目录，输入框可发送 |
| 两边运行 | 两边各自显示运行状态；共享工作区标识保持可见 |
| 审批 / 提问 | 只在所属侧聊展示操作；隐藏时主会话侧栏和页签显示 `需处理`，点击定位 |
| 停止中 / 保存中 | 单独显示，不能因为文字停止就显示「已完成」 |
| 已知未发送 | 保留草稿、错误详情，提供用户手动重试 |
| 发送结果未知 | `发送结果待核对`，提供只读核对；禁止用新 commandId 重发 |
| 来源没有已完成轮次 | 入口说明 `主会话还没有可用快照`，不伪造空快照；主会话仍可继续使用 |
| 正文缺失 / 预算不足 | 展示具体原因和缩小快照范围的入口，用户确认新预览后才创建 |
| Provider 不可用 | 保留侧聊和草稿；展示真实能力/认证原因，不自动换模型 |
| 父会话已存档/删除 | 侧聊保留；历史中以原父标题找回；来源链接不可用时仍能读冻结消息 |

关闭、存档、删除是三个动作。删除使用现有会话删除预览/指纹确认；父会话删除不默认级联子侧聊，快照由侧聊持有。

## 7. 并行的真实后果

- 主聊的对话记录不会被侧聊回复污染；用户需要时手动复制结论，不自动回写。
- 两个 Agent 可同时修改同一文件，可能覆盖或冲突。Scry 不是文件锁服务，也不承诺检测所有冲突。
- 共享 Git 工作区的 before/after diff 可能包含另一个运行或用户的改动。显示「工作区变化 · 并行运行期间」，不能标成某侧聊的精确独占产出。
- 同一原生 session 的发送仍串行；停止只针对该 run。不能用杀掉共享 Provider 进程来实现单侧聊停止。
- 独立 worktree、自动合并、自动同步上下文、自动回写主聊、嵌套侧聊、移动/远程客户端入口不在本次桌面设计范围；它们不作为偷降全 Provider / 并行要求的替代方案。

## 8. 评审重点

用户已确认：侧聊只读消息快照，不要求先迁移或接管主聊；原「旧式会话首次接管需要等待」限制撤回。来源身份与运行中读取的约束见 [来源合同](./snapshot-source.md)。本轮按指定截图加入 Surface 入口，并打磨页签、快照/共享工作区说明与窄窗单列交互。当前稿不代表 App 功能已实现或真实 Provider 已通过并行验收。
