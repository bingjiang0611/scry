# R3 会话页：正文结构、头部、状态条

分支 `design/ios-redesign`，基于 R2（已核验）。先读 [SPEC.md](SPEC.md) §2、§3、§5.2 和设计稿 `mockups/Session.dc.html` / `SessionLight.dc.html`。

会话有两个页面：`ChatView`（本机发起 / 正在跟踪的 run）和 `SessionTranscriptView`（打开的历史会话，含其中的 live run 与待发送消息）。**两个页面必须用同一套轮次组件**，来源只决定有哪些证据，不决定布局（这是现有约定，见 `ConversationTurns.swift` 顶部注释）。

## 数据边界（先读，和设计稿不同的地方以这里为准）

iOS 收到的一轮内容是 `OutputLine` / `RunHistoryChunk`：`kind` ∈ `output`（正文）/ `reasoning` / `tool` / `tool_result` / `truncated`，`tool` 的 `text` 是主机给的一行自由文本（如「读取 HomeView.swift」「rg -n …」）。用量只有 `resultSummary`（主机 `result` 标记生成的一行字，没给时是「主机报告完成（未提供用量）」）。因此：

- **who 行只显示 Provider 名**（来自会话 / 当前 Provider），不显示模型和强度。Composer 里选的模型是下一轮的偏好，不能拿来填本轮。
- **思考行只写「思考过程」**，不显示秒数。
- **工具组不按类别分徽标，不显示时长**。只能如实计数：连续的 `tool`（连同吸收的 `tool_result`）合成一行「N 个工具调用」；本轮被截断（`truncated` 或 `run.truncated`）时写「至少 N 个工具调用」。不要解析 `tool` 文本去猜「读取 / 编辑」。
- **页脚不显示文件数和 +/− 行数**（没有逐轮 diff 证据）。页脚只在本轮已结束且 `resultSummary` 存在时显示这一行；进行中不显示；`resultSummary` 是「未提供用量」那句时照原文显示，不改写成 0。长按气泡的「本轮详情」菜单保留。

## 要做的事

1. **头部**（`RemoteHeader` 及两个页面的调用处）：56pt，下方 1pt `border3` 线。返回 44 / 标题 `Typography.headerTitle` 最多 2 行 / 副标题 = Provider 图标（`Palette.provider`）+「项目 · Provider」，`Typography.meta`、`dim2` / 更多菜单 44。原来的文件按钮移进更多菜单，作为第一项「项目文件与 Diff」（保留不可用时禁用）。`SessionTranscriptView` 的历史状态（`moreWithStatus`、`HistoryEvidenceDetails`）保持在更多菜单里，不要丢。总览按钮留到 R4，本批不加占位。
2. **用户气泡**（`TurnUserBubble`）：右对齐，左侧至少留 15% 宽；`panel2` 底、圆角 18（continuous）、内边距 10/14、`Typography.bubble`；加极淡阴影（深色 `黑 30% y1 r2`，浅色 `黑 6% y1 r2`），浅色下再加 1pt `border3` 描边，解决 R1 记录的「白底上看不出气泡」问题。附件列表和长按菜单不变。
3. **助手部分**：
   - who 行：6pt `dim2` 圆点 + Provider 名，`Typography.meta`。本轮在运行时圆点换成 11pt `accent` 运行环。who 行之后是内容流。
   - 内容流：左侧缩进 20pt，x=3pt 处一条 1pt `border3` 竖线贯穿整条流；块间距 12pt。
   - 思考：折叠行（箭头 + 「思考过程」，`dim2`，`Typography.meta`），展开为 `dim` 色正文。展开 / 收起用 `.disclosureOpen` / `.disclosureClose`，箭头旋转 90°。
   - 工具组：在 `ConversationEntry.group` 之后再合一层（只读视图逻辑）：相邻的 `tool` 条目成一组。一组一行「N 个工具调用」（规则见数据边界），点开是 `panel2` 底、圆角 10、1pt `border3` 边的列表，每条工具一行（等宽 `Typography.mono`，单行截断），再点单条展开它的完整文本和结果（沿用现有展开内容）。只有 1 个工具时也按组显示，保持一致。
   - 正文：`ConversationMarkdownText` 改用 `Typography.reply` + `replyLineSpacing`；行内代码 `subtle` 底（2026-10-25 核验后改为不要求圆角，见 SPEC）；代码块 `bg` 底、圆角 10、1pt `border3` 边。改 Markdown 渲染时不能破坏 README 里写的「每条消息完整布局、不嵌套 lazy」约束，`markdown-blocks.py` 必须仍然通过。
   - 页脚：见数据边界。有时显示为上方 1pt `border3` 线 + 右对齐 `Typography.meta` `dim2` 文本。
   - `TurnOutcomeNote`（失败 / 已停止 / 未读取到输出 / 截断）保留语义，换成新 token。
   - 轮与轮之间 34pt；新流入的块用 `.streamIn`（180ms 淡入上移 4pt）。
4. **状态条**（`SessionStatusStrip`）：逻辑和文案不动，只改样式：44pt、圆角 12、左右 12。`running`：`accentSoft` 底、`accent` 字、运行环；`attention`：`warn` 12% 底、`warn` 字，按钮「回答」用 `warn` semibold；`warning`：`warn` 12% 底；`neutral`：`panel2` 底、`dim` 字。破坏性按钮（停止）用 `bad`。
5. **底部区域**：页面底色 `main`；Composer 已在 R2 改好，会话页不显示上方 chip 行（已锁定上下文的现有逻辑保持）。去掉 R2 之前遗留的 Composer 区域顶部 0.5pt 分隔线（如果还在），由外壳阴影分层。
6. 本批涉及的文件里把 R1 旧别名换成新 token、固定字号换成 `Typography`。R1 别名如果在全仓库已无引用就删掉，否则留到 R4。

## 不要做

- 不加总览按钮和总览 Sheet、不改「需要你决定」Sheet、不改模型选择（R4）。
- 不改 `RemoteRunStore` 的输出合并、历史分页、tail-following、新鲜度逻辑（README「Conversation positioning and freshness」一节）。滚动行为要和改版前一样：打开会话落在最新消息、发送后恢复跟随、阅读旧消息时不跳。
- 不从工具文本、Composer 选择或时间戳推断任何数字。

## 验收

- README「验证」一节全部；`ConversationUITests` 里与思考 / 工具展开相关的 accessibility identifier（`reasoning-toggle`、`tool-detail-toggle`）要保留或按新结构更新断言（更新要说明依据，不能删断言）。工具组新增 `tool-group-toggle`。
- 一个只读检查（可并入现有 Checks）：工具分组的计数、截断时的「至少」、单个工具成组、`tool_result` 无前置 `tool` 时单独成行。加一个负对照。
- 截图（真机、mock、深浅各一）：会话-已完成一轮（`-uiMockData`）、会话-运行中（`-uiMockMacRun`）、思考与工具组都展开、历史会话页（`-route transcript`）、长回复（`-uiMockLongOutput`）、Markdown 表格（`-uiMockMarkdownTable`）。
- 真机重放：打开会话落在最新消息；向上翻再回到最新；展开 / 收起思考和工具组；减少动态效果下展开只有淡入淡出。
- 报告写 `reports/R3.md`，不写设备 UDID 和团队 ID；STATUS 改「已提交」，push。
