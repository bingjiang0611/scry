# F1 「动态」补上「已完成」段

2026-10-27。用户请求：「动态 tab 下只有『进行中』，没有『已完成』，要求优化」。用户选择「给主机加字段，做完整版」，接受改主机协议的成本，换取跨设备、重启保留、不会贴错会话。

## 1. 查证结论：主机侧字段早就有，缺的只有 Swift 传输模型

R2 当时写的「iOS 拿不到 `lastRunOutcome`」只对 Swift 传输模型成立，Mac 侧其实一直在发：

| 位置 | 作用 |
|---|---|
| `src/shared/desktop-remote.ts:79-82` | `RemoteSessionRef.lastRunId?` / `lastRunOutcome?`；`isRemoteSessionOutcome` 只放行 `completed \| failed \| cancelled \| interrupted` |
| `src/main/bootstrap/remote-host.ts:245` | `listSessions` 按 `s.lastRunOutcome` + `s.runId` 输出 |
| `src/main/remote/remote-gateway-sanitizers.ts:174-175` | `sessionRefs` 白名单校验后透传，非法值直接丢弃 |

本机实测（只统计，不读内容）：`~/Library/Application Support/Scry/app-sessions.json` 668 条会话中 `lastRunOutcome` 为 `completed` 190 条、`interrupted` 23 条、`failed` 11 条、缺失 464 条。也就是说主机确实持久化了结果，设备侧只是没解码。

**因此本次没有改 Mac 端任何代码，也没改传输协议**——协议原本就有这两个字段，缺的是 iOS 端。

### 关键规则

1. **只有主机持久化的 `completed` 进「已完成」**。`failed` / `cancelled` / `interrupted` 不进任何段——它们不是「完成」，而 SPEC 的动态段语义是「需要我处理」和「跑完了」。这类会话仍在「项目」里。
2. **live run 优先于更早的结束**：同一会话不会同时出现在「进行中」和「已完成」。源码顺序由 `home-sections.py` 断言，不再只靠注释。
3. **旧主机兼容**：字段缺失、或取值不在四值集合里，`turnOutcome` 恒为 `nil`，行为与改之前完全一致（不出现已完成段）。
4. **默认标签不变**：`defaultTab` 仍只看 live 证据，完成记录不会把首页默认切到「动态」。

## 4. 未验证 / 已知限制

1. **真机未走查**。iPhone 17 Pro 没有 iCTRL Runner（自动化通道只在 iPhone 13 上），`com.scry.remote.local` 与正式包 keychain/配对不通用，所以「真实配对下真机看到已完成段」没有截图证据。已装的构建需要用户自己打开「动态」确认；也可等 iPhone 13 上用正式包再走一遍。
2. **`ScryRemoteUITests` 仍未在任何设备跑通**（本批之前就存在）：模拟器 `DTServiceHubClient failed to bless service hub`（宿主未开 Developer Mode），真机免费描述文件槽位已满。新增/改写的 UI 断言只验证了编译，没有执行。
3. **`Checks/theme-motion.py` 当前跑不起来，且与本批无关**：进程被系统 SIGKILL（`ASP: Security policy would not allow process`）。对照实验：`git worktree` 取出未改动的 `448c3475` 同样失败；连一个只 import AppKit 的最小程序编译后也被 kill。同一会话早前（19:5x）它还是 exit 0，所以是宿主执行策略的当前状态，不是代码回归。
4. **没有做「未读点」**，主机协议也仍然没有已读状态。README/FINAL 里那条差异还在。
5. `failed` / `cancelled` / `interrupted` 的会话目前不在「动态」任何段里。这是按 SPEC「其他都不进动态」执行的结果；如果希望「失败也需要我看」，那是新的产品决定，需要另开一项。

## 5. 性能

改动只在已有列表投影里多一次字段读取和一次 `==` 比较；没有新增网络、磁盘、定时器或重复解析。主机侧零改动，`sessionRefs` 只是本来就在序列化的两个字段。未跑 `npm run performance:measure`：本批没有改 `scripts/performance-paths.json` 里列出的任何热路径文件（`src/main/**` 未改）。
