```sh

  -configuration Debug -sdk iphoneos -destination "id=$DEVICE" \
  -derivedDataPath "$DERIVED_DATA" DEVELOPMENT_TEAM="$TEAM" \
  CODE_SIGN_STYLE=Automatic PRODUCT_BUNDLE_IDENTIFIER=com.scry.remote.local build-for-testing

  "$DERIVED_DATA/Build/Products/Debug-iphoneos/ScryRemote.app"
xcrun devicectl device process launch --device "$DEVICE" --terminate-existing --console \
  com.scry.remote.local -- -selfTest

  -configuration Debug -sdk iphoneos -destination "id=$DEVICE" \
```

## 核验意见（核验方，2026-10-25）

结论：**需修改**，只有一项。其余已核验：

- 数据边界全部守住：who 行只有 Provider 名；思考只写「思考过程」；工具组只计数、截断时写「至少」、孤立结果不计数，不解析工具文本；页脚只在已结束且 `resultSummary` 存在时原文显示，历史轮次不补。`tool-groups.py` 与负对照有效。
- `ConversationScrollView` 只改了间距、内边距和「回到最新」的样式，跟随 / 阅读旧消息 / scrollTo 逻辑没动；三个业务状态模块无 diff。
- `ChatView` 与 `SessionTranscriptView` 共用 `ConversationTurnRow`。头部、气泡（浅色阴影 + 描边）、时间线竖线、状态条四种色调、Composer 区域都符合 SPEC §5.2。25 张截图看过。

需要修改：

1. **行内代码不要用 `UITextView`**。`RoundedInlineCodeText` 让每个含行内代码的段落都变成一个 TextKit 视图。Agent 回复里几乎每段都有行内代码，而 README 要求每条消息完整布局、不能嵌套 lazy，长回复会一次创建大量 UITextView，违反 `CLAUDE.md` 的性能默认要求；它还让含代码的标题和表格单元格丢掉了原来的字号（统一用了 `.callout`）。
   改法：回到 SwiftUI `Text(AttributedString)`，对 `.code` 段设置等宽字体（`Typography.mono` 对应的 `.footnote` monospaced）和 `backgroundColor = Palette.subtle`。**不再要求圆角**，我已把 SPEC §5.2 改成「`subtle` 底，不要求圆角」。删掉 `RoundedInlineCodeText` 和 `InlineCodeLayoutManager`；`ConversationUITests` 里因此改查 TextView 的断言改回 StaticText，并说明依据。标题、表格单元格的字号回到改版前的层级（标题用原 `headingSize` 对应的语义样式，表格与正文一致）。重跑 `markdown-blocks.py`、Markdown 表格截图、长回复定位重放。

记录、不在本批处理：报告里两项在基线 `392f9684` 也能复现的滚动异常（Chat 发送后内容空白；`-route transcript -uiMockFirstScreen` 首屏不落到末尾）。核验方已报告用户，是否另开修复由用户决定，R4 不处理。
