### 失败及对照详情

拆分前 catalog 与交接基线均失败：

- `catalog.followUp.routingDoesNotResumeAnotherProfile`
- `catalog.recovery.explicitModelChoice`
- `catalog.model.explicitAutoIsRemembered`
- `catalog.model.catalogRecoveryRestoresReadiness`

真机 selfTest 失败后三项（前缀为 `run.`）。二者调用的是原样的 `selfTestInteractionState()` / `selfTestModelSelection()`。交接基线由 `git archive 5a6b6ac5 apps/ios` 导出到 `/tmp/scry-r1-baseline`，共享未改动的 Swift transport 包后运行其原始 catalog 检查，复现 146 / 4；没有以新测试覆盖旧预期。按 README 不修、不删、不 skip 这些业务用例。

新增 token 检查的首次失败是 `9 * 0.016 == 0.144` 的浮点精确比较；改为 1e-9 容差并保留索引 100 与索引 9 严格相等的封顶断言后通过，没有改动动画时长。

临时负对照曾以 SIGKILL 终止、没有断言输出，不能算有效负对照；改为显式打印颜色差异并 exit 1 后，取得上表所列有效失败证据。

拆分后 CMS 签名运行 token/catalog 检查均遭 SIGKILL；检查本地日志没有查到足以归因的系统原因。按已有检查文档改用默认 ad-hoc 签名做一次诊断：token 通过，catalog 仍遭 SIGKILL（shell exit 247）。未禁用系统安全策略、未增加重试或更改测试断言；catalog 最新运行保持受阻。
