## 第一步：定位原因（先写报告，再改代码）

三个问题都表现为「跟随末尾时视口落在没有渲染内容的位置」，很可能和 `ConversationScrollView` 有关：`LazyVStack` 的估算高度、`scrollTo("bottom")` 的时机（`onAppear` / `onGeometryChange` 里的 `DispatchQueue.main.async`）、`defaultScrollAnchor(following ? .bottom : nil)` 的切换，以及 AX3 下更高的头部 / 两行 Composer 让视口变矮。**这只是线索，不是结论。**

- 在 DEBUG 下加临时诊断（不提交，或只在 `-uiPreview` 下编译）：记录 `contentSize`、`contentOffset`、视口高度、`following` / `browsingOlder` 的变化顺序、每次 `scrollTo` 的调用来源。
- 对每个问题写清楚：触发序列、空白时 offset 和 contentSize 的实际值、根因。
- 问题 C 的 Transcript：用 `288903e3`（R4）和基线对照，找出改版里是哪一处让它从「可见」变成「空白」（二分 R2–R5 的提交也行）。
- 原因写进 `reports/R6.md` 第一节。三个问题如果是同一个根因，要说明证据；**找不到根因的问题不要修**，写明卡在哪。

## 第二步：修复

- 优先改 `ConversationScrollView` 这一处共享组件，两个页面一起受益；不要给某个页面单独打补丁。
- 可以考虑 iOS 17 的 `scrollPosition(id:anchor:)` + `scrollTargetLayout()`、调整 `defaultScrollAnchor` 的用法、调整 `scrollTo` 的时机。选哪种由根因决定，在报告里说明为什么。
- **禁止**：`asyncAfter` / sleep 延时、重试循环、假高度或占位 spacer、强制刷新 `.id()` 让整页重建、把 `LazyVStack` 改成 `VStack`（长会话性能，CLAUDE.md「性能是默认要求」）、嵌套 lazy（README 已禁止）。
- 必须保持 `apps/ios/README.md`「Conversation positioning and freshness」的全部行为：打开落在最新消息、阅读旧消息时新内容不抢位置、「回到最新」立即对齐、发送成功后恢复跟随、跟随时取最新窗口。行为有变化就同步改 README 那一段。
- 不改 `RemoteRunStore`、`AppModel`、`ExecutionTargetCoordinator`、Markdown 解析、协议。
