# R5 收尾：动效、减少动态效果、浅色、大字号与无障碍走查

分支 `design/ios-redesign`，基于 R4（已核验）。这是最后一批，目标是把 R1–R4 做出来的界面在各种系统设置下走一遍、修掉问题，不新增页面、不加功能。先读 [SPEC.md](SPEC.md) §1（含 2026-10-26 补充）、§2、§4。

## 要做的事

1. **主按钮对比度**（SPEC §1 补充）
   - `Theme.swift` 新增 `Palette.accentFill`（`#2f6ad8`，深浅相同）与 `Palette.onAccent`（白）。
   - 全仓库找 `accent` 作**实心填充且上面有文字或图标**的地方（至少有问题 Sheet 的「提交」），改用 `accentFill` + `onAccent`。`accentSoft` 底、描边、勾、运行环不改。
   - 在报告里列出改了哪些位置。

2. **删掉 R1 旧别名**
   - `Theme.swift` 里 `ink / muted / faint / line / blue / green / amber / surface / canvas / message / glass / noticeBg / noticeInk / warnBg / warnInk / positive / negative` 还在被其他页面引用。全部换成 SPEC 里的语义 token（等值替换，R1 已定义对应关系），然后删掉别名区。
   - 只做等值替换，不顺手改布局。替换后如果某个页面颜色变了，说明对应关系错了，停下来写进报告。

3. **动效收口**
   - 所有 `withAnimation` / `.animation(` / `.transition(` 都通过 `Motion`（`Motion.animation(_:reduceMotion:)` 或 R1 定义的同类入口）取曲线和时长。不允许在调用处写死 `.easeInOut`、`.spring`、`.default` 或秒数。
   - 减少动态效果打开时：位移、缩放、`matchedGeometryEffect` 都退化为 120ms 线性淡入淡出或无动画（SPEC §4）。逐个检查 R2 的列表进入、R3 的 `.streamIn` 与折叠、R4 的选项圆点、浮层出现、强度滑块。
   - 扩展 `apps/ios/Checks/theme-motion.py`（或新建一个 Foundation-only 检查，按 R4 的执行方式）：扫描 `apps/ios/ScryRemote/**/*.swift`，凡是不经 `Motion` 的动画调用都报出来。加一个负对照（临时样本里写死 `.easeInOut` 要被抓到）。

4. **对比度检查**
   - 写一个只读检查：从 `Theme.swift` 读出颜色，计算这些组合在深浅两套下的对比度：`fg / dim / dim2 / accent / warn / bad / ok` 分别放在 `bg / sidebar / main / panel / panel2` 上，`onAccent` 放在 `accentFill` 上，`warn` 放在「`warn` 12% 叠在 `panel2`」上。
   - 文字用到的组合 < 4.5:1 的（大字或 ≥15pt semibold 的 < 3:1）列出来。能用现有 token 换掉的就换；需要改 token 数值的**不要改**，写进报告给核验方决定。

5. **Dynamic Type 走查**（真机）
   - 三档：系统默认、`xxxLarge`（最大的非辅助档）、`accessibility3`。
   - 页面：首页（项目、动态两个 tab）、会话页（已完成、运行中、历史页）、问题 Sheet、总览 Sheet（medium 和 large）、模型浮层、Composer。
   - 要求：文字不被裁掉、不重叠；固定 `height` 的文字容器改成 `minHeight`；单行截断的地方（会话标题、工具行、总览轮次）在大字号下仍然是有意截断而不是挤坏；底部按钮在 AX3 下可以变高或上下排列，但不能缩到 44pt 以下。模型浮层在 AX3 下如果放不下，允许变成可滚动，不允许截掉选项。
   - 只改布局约束，不改字号角色（`Typography` 的映射保持）。

6. **浅色走查**（真机）：同上页面在浅色下各看一遍，重点是发丝线是否可见、气泡和卡片能否和底色分开、状态条各状态的颜色。问题按截图列出，能用现有 token 修的直接修。

7. **VoiceOver 走查**（真机，简要）
   - 只有图标的按钮都有中文无障碍标签（返回、更多、总览、关闭、复制、附件、发送、模型按钮）。
   - 问题 Sheet：读到顺序为 标题 → 类型徽标 → 问题 → 选项（带「已选」）→ 取消 / 提交。
   - 运行环、圆点等装饰元素 `accessibilityHidden`。
   - 有问题就修，修不了的写进报告。

## 不要做

- 不改任何状态、协议、滚动 / 跟随逻辑（README「Conversation positioning and freshness」）。R3 报告里那两个滚动问题仍然不修，等用户决定。
- 不新增页面、不加总览里没有数据的区块、不改 `Typography` 的字号角色映射、不改 SPEC 里 token 的数值（`accentFill` / `onAccent` 是新增，不算改）。
- 不为了截图或走查方便改系统 Sheet 行为。

## 验收

- README「验证」一节全部。上一批没跑出结果的三个离线检查（`theme-motion.py`、`tool-groups.py` 等）这次再跑；还是被环境挡住就照实写，不要改脚本让它变绿。
- 新增检查：动效扫描（含负对照）、对比度表（输出放进报告）。
- 截图（真机、mock）放 `reports/R5/`：
  - 深色 / 浅色 × 默认字号：首页、会话页（已完成）、问题 Sheet（提交按钮可用状态）。
  - `accessibility3`：首页、会话页、问题 Sheet、总览 large、模型浮层（深色即可）。
  - 减少动态效果：不用截图，在报告里逐项写「已检查 / 行为」。
- 报告 `reports/R5.md` 额外加一节「与设计稿的最终差异」：逐页列出因为数据边界没做的部分（例如每轮模型、思考秒数、工具类别与时长、逐轮 diff、上下文占用、Token / 费用 / 时长、总览跳到某轮），每项写清楚缺的是哪个主机数据。这份清单会交给用户决定要不要扩主机协议。
- 不写设备 UDID 和团队 ID；STATUS 改「已提交」，push。
