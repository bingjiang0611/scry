## 2. 第 2 节 `run` 那一行改动后，等待决定横幅的行为

改成 `model.route == .newSession || model.route == .home ? targets.newTaskStore : targets.selectedStore`。

- **只有 Mac 本机（没有转发目标）时，行为不变。** `store(for:)` 对 `scope.isLocal` 直接返回 `localStore`，所以 `selectedStore` 和 `newTaskStore` 是**同一个对象**；`pendingQuestions`、`waitingLiveRuns`、`focusedQuestionIdentity`、`reachable`、`connectionObservation`、`hasRecoverableRun` 全是同一份数据，「需要你决定」横幅、问题 sheet、「另有 N 个任务需要你决定」都与改前一致。
- **有转发目标（多主机）且两个 scope 不同时，行为会变。** 例如在抽屉里打开主机 B 的会话（`selectedScope = B`），再 `goBack()` 回 `.home`：改前横幅/问题 sheet 取自 B 的 store，改后取自当前新任务 scope A 的 store。B 的待回答问题仍然出现在抽屉「动态」的「需要回复」里，也可以点进会话处理，不会丢；但顶部横幅不再替 B 说话。我没有为此改横幅逻辑（要改就动 `RootView` 的判定，超出本批范围），按 README 要求写在这里。
- 同一原因还有一处：`RootView` 的 `run.reachable` / `connectionObservation` 只在 `run.targetScope == nil` 时才写回 `model.link`。改后 `.home` 上新任务 scope 是本机时照旧；新任务 scope 是转发目标时，「已配对」链路指示不再由 B 的运行通道更新——这与「只有本机 store 能代表这条配对链路」的既有规则一致。
- `resumeRecoveredRun()` 未改：冷启动时 `selectedScope == newTaskScope`，行为不变；配对成功后 `beginNewTask()` 已经 `detachFocusedRun()`，新任务 store 没有可恢复运行，也不会误跳。

### UI 测试为什么没跑起来

`ScryRemoteUITests` 编译并链接通过（`xcodebuild test` 已走到 `ScryRemoteUITests-Runner.app` 的 `CopySwiftLibs` / `ProcessInfoPlistFile` / code sign），但测试会话建立不起来：

```
ScryRemoteUITests-Runner (…) encountered an error (The test runner hung before establishing connection.)
iOSSimulator: unable to connect to "com.apple.instruments.deviceservice.lockdown"
  (DTServiceHubClient failed to bless service hub for simulator …)
```

试过并排除的：

1. 两个 runtime：iPhone 17 / iOS 27.0（462 秒后报上面这条），新建的 iPhone 15 / iOS 26.5（同样）。
2. 杀掉 `com.apple.CoreSimulator.CoreSimulatorService`、启动 `Simulator.app`、重新 boot 后再跑：同样失败。
3. 控制组：用**本次没有改动的** `ConversationUITests/testOfflineComposerCannotSend` 单独跑，同样卡住 20 分钟以上、零用例执行（日志停在 `unable to connect`，最后是我 kill 掉的，所以出现 `BUILD INTERRUPTED`）。

根因证据：`DevToolsSecurity -status` → `Developer mode is currently disabled.`。开启需要 `sudo DevToolsSecurity -enable`，属于机器级设置，我没有改。**建议在有该项权限的环境上重跑 `-only-testing:ScryRemoteUITests`**；在此之前，本轮新增/改动的 UI 用例只有编译证据。

## 5. 设计稿没覆盖、我做了判断的地方

1. **顶栏胶囊的绿点**沿用 `HomeView.hostChip` 的语义：`run.hasConnection`（已配对）为绿，不表示「已连接 / 可达」；文案按 SPEC 用 `targets.newTaskScope.label`，未配对时用 `ConnectionCopy.unconnected`。
2. **会话框不再显示主机名**：`HomeComposer` 原本在多主机时把 `targets.newTaskScope.label` 传给 `hostLabel`，新页面顶栏已经显示同一台主机（设计稿的会话框也没有这一段），所以传 `nil`。要恢复只需传回那一行。
3. **三处「新建会话」完全一致（SPEC 第 5 节）会清掉已输入内容**：在**已经是**新建会话页时点右上角图标或抽屉那一行，`beginNewTask()` 会 `resetNewTaskContext()`（清掉已选项目 / Provider / 模型 / 强度 / 权限）并清空草稿。这是 SPEC 明确写的「三处一致」，我照做了，但它确实是真实的输入丢失风险。**建议核验方定一个方向**：已经在 `.newSession` 时只聚焦、不重置（就不需要清草稿），或保留草稿只重置上下文。我没有自己改。
4. **抽屉打开时没有把后面的页面 `accessibilityHidden`**：SPEC 要求 UI 测试在抽屉展开时仍能找到 `message-input`，所以页面元素保持可访问。代价是 VoiceOver 在抽屉展开时仍会走到后面的内容；另外「新建会话」在页面顶栏和抽屉行各有一个，两个按钮同名，所以抽屉那一行加了 `accessibilityIdentifier("drawer-new-session")`，☰ 用 `sidebar-toggle`，抽屉收起按钮用 `sidebar-close`。遮罩按 SPEC 是一个「收起侧栏」按钮（元素名与抽屉内按钮同名，测试里用 identifier 区分）。
5. **抽屉常驻挂载**（关闭时 `offset: -width` + `opacity 0` + 不接收点击），这样滑动动画、已展开的项目、滚动位置、刷新 toast 在收起/展开之间都保留。代价是关闭时仍参与布局；比改前多出来的只是「新会话页 + 同一份 HomeSessions」同时挂在首屏，量级与改前首屏相同。
6. **`targets.setHomeVisible(drawerOpen)`**（SPEC 第 4 节）：后台 refreshHome 的恢复重试只在抽屉展开时进行；进入页面时的一次性 `refreshHome` / `loadProjects` / `loadProviders` / `refreshArchived` 仍在 shell 的 `.task` 里。抽屉折叠期间列表可能变旧，但 footer 有「…读取」时间和既有的 unverified 提示，不会把旧数据当当前。
7. **抽屉底部**选了「provenance 挪到 footer」这一支，列表底部因此不再有那一行（避免出现两次）。
8. **未连接时的中间区**：保留 44pt 图标块 + 「新建会话」标题，把说明行换成 `Notice(ConnectionCopy.noGatewayForNewTask / targetUnavailable, warning: true)`（沿用旧 `NewSessionView` 的判定）。
9. **抽屉顶部「新建会话」行没有行级 scope**，所以调无参 `beginNewTask()`（按当前 `homeFilter` / `newTaskScope` 决定，和 `AppModel` 配对成功后的调用一致）；`HomeSessions` 里的两处仍然传具体 scope / cwd。
10. **减少动态效果**：抽屉用 `.animation(reduceMotion ? nil : Motion.animation(.select, reduceMotion: false), value: drawerOpen)`，开启后位移与透明度都直接跳变（不滑动、不新增长度）；没有新增 `Motion` token 或时长。
11. **对比度**：本轮新增的文字色只有 `Palette.fg` / `dim` / `dim2`（主题检查里最差 `dim2/panel3` = 4.24 属既有问题，本次没有在 `panel3` 上放文字）；没有新增以 `light.accent` 为文字色的元素，所以 `visual-contracts`/`theme-motion` 报的 3.65–3.92 仍是既有问题。
12. **触控尺寸**：☰ 44×44、右上新建 44×44、主机胶囊 44 高、抽屉收起 44×44、抽屉「新建会话」行 44 高、footer 齿轮 44×44、遮罩整块可点；会话框内部沿用既有 44pt 控件。
13. **测试夹具里的旧文件名**：`RemoteRunStore` 的 DEBUG 演示转写里仍有「读取 HomeView.swift / 编辑 HomeView.swift」的假文本，`HomeView.swift` 已改名。那是既有的 mock 内容（`ConversationUITests` 按它断言），属别的批次范围，我没动。
