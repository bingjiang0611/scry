# Agent 指令入口与迁移验收

## 当前入口

- `AGENTS.md` 是共同工程合同入口；领域细节由根目录的任务路由指向现有指南。路径和命令以仓库根为基准。
- 根 `CLAUDE.md` 暂留为旧版 Claude 的完整兼容入口。它不是第二套政策：常驻授权、安全和交付合同必须与 `AGENTS.md` 及其引用指南一致。
- 当前没有新增 `.claude/rules`、`paths` 或自动注入 hook。指南仍由 Agent 根据根路由主动读取，不应描述为工具自动注入。
- 不把 shell 示例中的 `CLAUDE.md`、测试用文件名或历史交接记录机械改名；只有当前政策引用改为 `AGENTS.md`。

## 2026-11-15 隔离验证记录

环境：macOS arm64，当前迁移工作区；下述结果不是已安装 Scry App 的端到端结果。

| 场景 | 结果 | 证据范围 |
|---|---|---|
| Rotom bundled Pi `1.4.0-rotom.4` 根入口 | 正、反对照通过 | 两个独立进程/空会话；有 AGENTS 得到随机暗号，无 AGENTS 得到 UNKNOWN；零工具调用 |
| 同版本 Pi 的领域指南路由 | 修正加载时机后，正、反对照通过 | 新会话先读 Provider 文件，再按根路由读 `change-checklists.md` 和任务契约并答出暗号；另一新会话读取 README、架构与任务契约指南，未读该 Provider 检查清单且答 UNKNOWN |
| 同版本 Pi 的全局符号链接入口 | 正、反对照通过 | UI 任务解析全局入口的 canonical realpath 后读取前端选型和文案指南并答出暗号；独立 README 任务未读这两份指南，答 UNKNOWN |
| 同版本 Pi 的技能广告路由 | 8 个样例通过 | 仅依据技能名称和描述选择；包含模型升级后审计指令的入口，零工具调用；不代表完整召回率等价 |
| native Codex `0.166.0` 根入口 | 正、反对照通过 | 独立 CODEX_HOME、只读 sandbox、hooks 关闭；有/无 AGENTS 分别得到暗号/UNKNOWN；零工具调用 |
| native Claude 安装链接 `2.1.226` | 受阻 | `--version` 被 SIGKILL，退出码 137；只读签名校验通过，但不能确定终止原因；未启动模型、未改安全策略 |

模型为 `openai-codex/gpt-6-astra`。暗号仅在隔离夹具文档中，不在提问或文件名中。凭据只通过现有文件引用提供，没有复制到报告或提交。相同会话先看到暗号再做负对照无效。

## 撤销兼容入口的条件

负责人：后续执行入口迁移的 Agent/维护者。native Claude 恢复正常后，在独立配置和临时工作区测试 `.claude/CLAUDE.md` 的 `@../AGENTS.md` 导入：正例能读到仅在 AGENTS 中的暗号，去掉兼容入口的负例按该版本的实际能力判断；另测迁移指南的正反场景。没有版本对应的真实加载证据前，不删除根 `CLAUDE.md`。

若要把任务路由升级为 hook 注入，按客户端分别证明触发、实际内容、信任校验与不匹配时不注入。Pi、Claude、Codex 的加载合同不等价；文件路径匹配也不等于用户意图匹配。保留根路由直到对应客户端通过验收，不为便利绕过 hook trust。
