# Agent 指令的唯一来源与加载

## 项目维护规则

- 唯一项目规则正文是 `.agents/AGENTS.md`；根 `AGENTS.md` 是指向它的符号链接，只用于 Pi/Codex 的自动发现，不是第二份正文。
- 所有项目技能只维护 `.agents/skills/<name>/`。不再保留 `.claude/skills/` 镜像；`scripts/agent-instructions.test.ts` 检查规则入口和技能唯一来源。
- 领域细则仍放在对应指南；修改正文或指南时不再同步第二份 Claude 文本。根入口指向目录不变时，不需要修改符号链接。
- **维护者 2026-11-15 明确确认**：本机不使用 Claude，不保留它的项目规则或技能副本。已移除根 `CLAUDE.md` 和 `.claude/skills/`；不再以恢复 Claude CLI 作为此次迁移的前置条件。
- 代码示例、测试夹具、Provider 合同或历史记录中的 `CLAUDE.md` 不等于本仓库规则副本，不作机械改名。`.claude/company-context.local.md` 是既有私有资料路径，仍保持忽略，不随删除技能副本而公开。

## 全局维护规则

全局规则与用户技能同样以 `.agents` 为唯一来源。Pi/Codex 需要固定规则发现路径时可以保留符号链接，但不能另存正文。解析规则内的相对引用时以 canonical realpath 为准，不能以客户端入口别名为准。

Pi 和 Codex 的公共技能发现目录是 `~/.agents/skills/`。Pi 专用技能可以置于 `.agents/pi-skills/`，仅由 Pi 的技能入口符号链接指向；这样不复制正文，也不向其他客户端公布专用技能。

## 验证边界

本次目录迁移后，Pi 与 Codex 的独立临时 HOME/工作区正反对照通过：全局规则与项目规则从符号链接加载，公共技能从 `.agents/skills` 发现，Pi 专用技能不出现在 Codex 广告中。所有样例均未调用工具。

Pi 的项目技能受项目信任控制：`--no-approve` 会忽略项目技能，但仍可读取规则与全局技能。首次样例因此未发现项目技能；对自建只读夹具显式使用 `--approve` 后验证通过。没有修改真实项目的信任设置，也不为迁移绕过该边界。

这些都是 CLI 加载与模型遵循入口的证据，不证明 Scry App 端到端或所有客户端兼容。未部署自动注入 Hook、`.claude/rules` 或通用文档加载扩展；任务路由仍是明确的阅读指令。

后续改动发现路径时，在临时 HOME/工作区中分别验证：有入口能读取只存在于目标正文的随机暗号；独立新会话去掉入口不能读到暗号。技能发现还需检查实际加载清单及来源，不以名字 grep 代替实际发现。不要在真实规则中留下测试暗号。
