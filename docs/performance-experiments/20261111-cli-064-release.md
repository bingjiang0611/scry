# CLI 0.2.64 发布 · 2026-11-11

发布 main 上的两处采集修复：Codex rollout compaction 不再丢失，以及一轮内新建 git worktree 的 diff。只覆盖独立 CLI 版本与发布；桌面 App、uploader、trade-telemetry runtime 未在本轮发布。

## 发布内容

| 修复 | 合并提交 | 对采集的影响 |
| --- | --- | --- |
| Codex rollout compaction 完整且有序（[#55](https://github.com/bingjiang0611/scry/pull/55)） | `8565bc49` | 一次 Codex 压缩不再因为 rollout 行乱序或预算截断被丢弃；`compactions` 由空值变为真实条目 |
| 一轮内新建 worktree 的 diff（[#57](https://github.com/bingjiang0611/scry/pull/57)） | `b2962415` | 回合中新建的 worktree 现在产出 diff；基线取该 worktree 自己 `logs/HEAD` 的第一条记录（旧值全 0，即创建时的检出提交），不退回回合开始快照 |

### 发布说明里要写明的限制

- 默认 `workspace-only` 模式下，**新建 worktree 只有创建那一轮有 diff**；后续轮次不再进入基线，因此那些轮次只报采集范围内的仓库。
- 要跨轮采集 worktree 内的改动，需要启用 `discover-nested-git`。
- 每轮最多为 8 个新 worktree 产 diff（`per_turn_limit`）；拿不到可信创建记录时记 `partial` + 原因，`files` 为空，不猜测内容。

## 发布流程

1. 由 CI 针对合并后的精确提交打包并留存 `pack.json` 与 `provenance.json`，本地不重新构建。
2. 解包 CI tarball，只按既有做法改两处：`package.json` 的 `name` → `@ali/scry-turn-recorder`，README 安装行 → `npm install -g @ali/scry-turn-recorder@0.2.64`。`diff -r` 只有这两个文件的两行差异。
3. `npm publish ./publish --ignore-scripts --registry https://registry.anpm.alibaba-inc.com/`。`packages/turn-recorder-cli` 的 `prepublishOnly` 是 `npm --prefix ../.. run check:cli-release`，只对仓库内目录成立；同一门禁已由 CI run `42981385928` 在该提交上执行并通过（`node`、`cli-compat` 20/22/24、`unit` 1-4、`packaged-electron` 1-3、`packaged-linux`），因此这里跳过本地重复执行，而不是跳过验证。
   - 注意：`npm publish publish`（不带 `./`）会把参数当成**包名**，去 registry 找名为 `publish` 的包并因 0.6.0 已存在而失败；那次调用没有发布任何东西，改用 `./publish` 后成功。
4. 发布后重新 `npm pack` 下载件，核对 shasum/integrity 与解包内容（见上表）。
