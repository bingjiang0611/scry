# recorder 0.2.76 发布记录

## 内容

PR #113（`a733195a`）修掉 CodeLens 0.2.28 接入 0.2.75 时实测到的三个问题，版本升到 `0.2.76`。

1. **采集路径不带宿主 pid。** CodeLens 的会话事件经 `.scry/capture/receiver.sh` 投递，脚本只带 `x-scry-capture-mode: session`；采集路径（`serveCaptureRequest` → `applySessionCaptureHook` → `handleRecorderHook`）也不传投递进程，所以采集轮次的 `open.json` 里 `host` 一直是 `null`（实测 21 个采集事件 clientPid 全为 `undefined`），`--expire-open` 对它们永远没有进程证据。现在 receiver 与 `provider-hook.sh` 一样带 `x-scry-client-pid: $$`，daemon 与 CLI 兜底路径都把该 pid 的进程链记入 `open.json`；claim 打开的第一轮也记录发起采集的进程链。
2. **宿主状态未知时被放行。** 0.2.75 只在 `running` 时否决，`unknown`（没有 `host`、旧钩子脚本不带 pid、进程表读不到）会直接收尾，与「核对不到就当作还在跑」的说明相反。`scry doctor` 推荐这条命令，用户手动执行时会收掉宿主还活着、只是没有 pid 证据的轮次。现在只有 `gone` 才收尾，`running` 与 `unknown` 都保持 open；`doctor` 与 stale 诊断输出 `host` 状态说明为什么没收。
3. **`--expire-open` 是全工作区开关。** 一个工作区里只要有一个轮次判断不了宿主，调用方就不敢带这个开关，其余本可收尾的轮次也一起卡住。新增可重复的 `--session <id>`，只在 `--expire-open` 下有效（单独出现报错），只对列出的会话强制收尾；不带 `--session` 时行为不变。

口径细节见 [证据口径](../../packages/turn-recorder-cli/docs/evidence-limits.md)、[生命周期](../../packages/turn-recorder-cli/docs/lifecycle.md) 与 [按会话恢复](../../packages/turn-recorder-cli/docs/scoped-recovery.md)。

## 未验证 / 限制

- 修复只对新写入的 `open.json` 生效。0.2.75 及更早留下的采集轮次没有 `host`，在 0.2.76 里属于 `unknown`，不再会被自动收尾；它们只能由真实终态证据（SessionEnd、结束回复 + 长时间静默、`scry recorder recover`）收口。
- 宿主进程链仍只在标准安装形态下取到宿主层（receiver/`provider-hook.sh` → 投递进程 → Provider 宿主，最多 3 层）；更深的包装层或旧脚本不带 pid 时记为 `unknown`，方向是保持 open，不会误收尾。旧脚本需要 `scry integrations repair --yes` 更新。
- PID 复用只在平台提供启动标记时排除（macOS `ps lstart`、Linux `/proc` start ticks）；标记缺失按「仍在运行」处理。
- CodeLens 每 15 分钟一次的定时调用本身仍未端到端验证，只验证命令、门槛与 `--session` 行为。
