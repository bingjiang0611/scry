## 发布流程

1. 由 CI 针对合并后的精确提交打包并留存 `pack.json` 与 `provenance.json`，本地不重新构建。
2. 解包 CI tarball，只按既有做法改两处：`package.json` 的 `name` → `@ali/scry-turn-recorder`，README 安装行 → `npm install -g @ali/scry-turn-recorder@0.2.63`。`diff -r` 结果只有这两个文件的两行差异；发布后重新下载并解包，与上传目录 `diff -r` 为 0 行。
3. `npm publish --ignore-scripts`。`packages/turn-recorder-cli` 的 `prepublishOnly` 是 `npm --prefix ../.. run check:cli-release`，只对仓库内目录成立；同一门禁已由 CI run `42751397512` 在该提交上执行并通过，因此这里跳过了本地重复执行，而不是跳过验证。

- **工作流运行时仍是 0.2.62**：trade-telemetry `uploader/package.json` 精确固定 `@ali/scry-turn-recorder: "0.2.62"`，当前激活的 runtime `0e917b38…`（`uploader` 0.2.13 + recorder 0.2.62）未变。要让 rate-workflow 新会话用上本修复，需要 trade-telemetry 侧改钉版本并走它自己的远端 CI 发布与安装；本轮未做。
- 未在真实 Provider 会话中跑升级后的 0.2.63。上面「保留现场」检查是对既有原生 transcript 与记录的只读重放，证明解析与判定行为，不证明新版本在本机端到端采集链路工作。
- 未发布桌面 App，未更新 uploader，未改动任何既有 record、ACK 或队列。
- 内网安装不会自动升级（`PACKAGE_NAME` 仍是公开名 `scry-turn-recorder`），升级需要显式 `npm install -g @ali/scry-turn-recorder@<版本> --registry https://registry.anpm.alibaba-inc.com/`。
