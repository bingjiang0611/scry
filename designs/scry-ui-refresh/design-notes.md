# Scry UI Refresh — 设计说明

## 已确认范围

- 聚焦侧栏、会话顶栏、对话流、Composer 与纵览面板。
- 同时设计深色与浅色主题；二者共享语义 token，但分别校准背景层级、边界和对比度。
- 已选定方案 A「Workbench」：宽屏保留三栏工作台，窄窗口时纵览自动转为抽屉。
- 原型使用现有会话中的真实示例值，但不连接 Provider，也不新增看似真实的业务状态。

## 设计语境

- 产品源码：`src/renderer/`，重点参考 `styles.css`、`Sidebar.tsx`、`ViewChrome.tsx`、`ChatView.tsx`、`OverviewPanel.tsx`、`theme.ts`。
- 用户提供的浅色主题截图：`reference-current-light.png`。
- 产品身份：本地优先的 AI coding agent 观测与治理桌面应用，不是通用聊天软件，也不是营销仪表板。

## 关键优化

| Before | After | Why |
| --- | --- | --- |
| 右侧纵览可被拖到 560px，主对话在常见窗口下被压缩 | Workbench 将纵览收敛为 340px；窄窗口自动转抽屉 | 主对话是首要工作区 |
| 浅色主题三个面板接近纯白，只靠细线分隔 | 侧栏、主区、纵览使用三档中性表面 | 不增加阴影噪音也能建立层级 |
| 会话行混排 Provider、标题与时间 | Provider 标记、标题、来源、时间分层 | 提高长列表扫描速度 |
| 纵览首屏一次铺开大量数字 | 上下文、会话判决、关键指标、证据逐级展开 | 先回答“是否正常”，再看证据 |
| 模型正文与遥测信息权重接近 | 正文使用更舒展的中文行高；遥测退到 mono 辅助层 | 阅读优先，事实仍可追溯 |
| 面板切换与高频导航存在过多视觉变化风险 | 高频 tab 即时切换；仅抽屉、浮层、toast 使用短促过渡 | 保持专业工具的响应感 |

## 方向决策

- A · Workbench 作为唯一设计方向，优先服务长时间观测与多栏并行扫读。
- 右侧纵览在宽屏上默认常驻，仍可手动隐藏；窄屏时为保护主对话区自动转为抽屉。

## 原型交互

- 切换深浅主题、紧凑/舒适密度。
- 折叠侧栏、显示/隐藏纵览。
- 搜索会话、展开项目、切换会话。
- 切换对话/拓扑/分段，以及纵览/账单/MCP、轮次/会话数据。
- Composer 包含 Enter 发送、空输入禁用和“不会调用 Provider”的原型反馈。
