## 为什么现在读起来是平的

| 现实现 | 观察 |
| --- | --- |
| `.queue-item` 44px 等高、`--surface-subtle` 底 + 1px `--border3` 框 | 3 行长得一样，队列里唯一真正的信息——**顺序**——只剩一个 22px 圆点数字 |
| 序号 10px、正文 12.5px、按钮 10.5px（`styles.css:2335–2375`） | 三档字号挤在 2.5px 内，「下一个」和「第 3 条」没有层级差 |
| 容器 12px 圆角 + `--shadow-pop`（`codex-alignment.css:1204`） | 一个贴着输入框的内联块带 64px 投影，边界比内容更响 |
| 行状态靠 `disabled` + `title` 暗示 | 「提交中 / 结果未知」默认看不见；`结果未知` 只在 hover 时才有解释 |
| `.queue-hint` 用 `--dim3` `#535d6e`（`styles.css:2312`） | 对 `--panel` 约 2.95:1，低于 4.5:1；这句正是「任务结束后依次发送」的关键说明 |

## 四稿

| 稿 | 峰值（先看到什么） | 结构装置 | 代价 |
| --- | --- | --- | --- |
| A · 现状 | 三行等高，无峰值 | 逐行卡片 | 对照用，不改 |
| B · 阶梯 | 第 1 条（15px 琥珀序号 + 抬高面） | 序号并进 1px 竖轨，其余行为发丝线；状态改由竖轨报 | 行状态的可读性依赖序号列 |
| C · 状态列 | 状态词竖列（下一个 / 等待 / 提交中 / 结果未知 / 已拒绝） | 保留逐行卡片，右侧固定 62px 状态列 | 正文少 62px，窄窗更早截断 |
| D · 单峰 | 下一条消息本身 | 只展开第 1 条，其余折成 `展开后面 N 条` | 对第 3 条 Steer 要多一次点击 |

共同做法（都不新增 token）：

- 序号、计数、时长用 mono + `tabular-nums`；序号不再是蓝色圆点，避免和「动作」抢蓝色。
- 琥珀 = 等待/未决，蓝 = 可执行动作，红 = Provider 明确拒绝。`结果未知` 用琥珀，不用红。
- 去掉 `--shadow-pop`，改用 `--surface-inset-soft` 内嵌面；B/C/D 的说明文字从 `--dim3` 提到 `--dim2`（2.95:1 → 5.45:1）。A 保留上线值，作为对照。

### B · 阶梯（建议方向）

```
┌ 等待运行 (3) ────────────── 当前任务结束后依次发送 ┐
│ 1▕ 都覆盖了哪些交互场景                 [↳ Steer] × │  ← 15px 琥珀 + 抬高面
├──┼─────────────────────────────────────────────────┤
│ 2▕ 顺便把队列在 720px 下的换行也过一遍… [↳ Steer] × │  ← 11.5px 灰 + 发丝线
├──┼─────────────────────────────────────────────────┤
│ 3▕ 再补一张截图：附件只保留文件名…  图1 [↳ Steer] × │
└────────────────────────────────────────────────────┘
```

骨架测试：去掉文字后仍是一条带「头」的刻度轨——头部亮、尾部落回发丝线，顺序和「下一个」不用读字也成立。

状态也走同一条轨：`提交中 / 结果未知` 时该行的竖轨转琥珀，`已拒绝` 转红，行内再给一行原因。不需要额外画框。

### C · 状态列

给「每行必须自己说明在等什么」一个固定位置。未决状态不只靠禁用按钮暗示。如果你更想保留现有逐行卡片、只补状态语义，选这稿。

### D · 单峰

只把真正会先跑的那一条展开。**收起的行里只要有未决状态，尾行必须用 warn 徽标写出来**（`1 条结果未知`），不能让折叠把证据藏掉。最激进，也最省空间。

## 建议

**B > C > D > A**。理由：B 用系统已有的东西（mono 序号、琥珀等待色、发丝线）把顺序讲清楚，没有引入新图形；代价最小，且窄窗口不牺牲正文宽度。C 的状态列信息最全，但每行多 62px 且「等待」会重复 3 次；如果你要 C，建议把它并进 B 的竖轨（B 已经用竖轨报状态，两者取一）。D 最有个性，但每次给后面的消息 Steer 都要先展开。

## 不放松的东西

1. 证据语义照旧：`提交中` 不可重复提交、不可移除；`结果未知` 不可重发、不可移除、不自动出队；`明确拒绝` 才可重试；`能力不可用` 必须写出原因。
2. 能力原因只在整个 composer 底部说一次，不复制到每一行（那是噪音，不是证据）。原型已按此实现。
3. 按钮始终保持可聚焦，焦点环 2px `--accent`；Steer 与移除按钮在视觉上必须能看出「可点」，不能靠 hover 才成立。
4. 只使用 `styles.css` / `codex-alignment.css` 现有 token 与 `Icon.tsx` 现有路径，不新增颜色、字体、图标。
