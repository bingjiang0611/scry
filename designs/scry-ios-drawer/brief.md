# Scry iOS · 会话抽屉（Codex 式入口）设计稿

状态：**设计稿，未实现。** 视觉沿用现有 iOS 深色语义色与 SF Symbols；只借 Codex/ChatGPT 的结构（首屏输入框 + 左上角抽屉），不借它的浅色皮肤。

模式：Operate（用户来完成任务，不是来看页面）。

原型：`index.html`（10 块画板：首屏、抽屉·最近、抽屉·项目、首屏证据、抽屉·工具，加五个面板屏；可切 tab、切换分段控件、点图例、右键/长按行打开操作），规则检查 `prototype.test.mjs`（23 项）。

---

## 1. 要解决的问题

现状：iPhone 首屏是一整页会话索引（`HomeView`），发消息要多走一跳"新任务"页；会话的置顶/重命名/存档只能回 Mac 做。

目标：

1. 首屏就是输入框。打开 App 先能发任务，再决定要不要找历史会话。
2. 左上角抽屉承载 Mac 侧栏的会话能力，一个手势可达，不占首屏。
3. Mac 侧栏的会话功能和它给出的证据，在手机上有对应物；没有主机接口的能力不做假入口。
4. Mac 侧栏的五个面板（分析 / LLM 性能 / 技能 / MCP / Meta Prompts）在抽屉里有真实入口，数据来自 Mac，缺字段就说缺。

不在本稿范围：项目级置顶与排序、未读状态、推送、五个面板的**写操作**（见 §7）。

## 2. 首屏结构

```
┌──────────────────────────────────┐  56pt 安全区
│ ☰        ● MacBook Pro ⌄      ↻ │  52pt 顶栏：开抽屉 / 当前主机 / 刷新会话
│                                  │
│                                  │
│           （留白，随内容让位）      │
│                                  │
│                                  │
│  最近                            │  可选：最近 3 条会话
│  会话归档与恢复的证据边界   草稿   │  点行 = 打开会话记录
│  补齐 iOS 会话抽屉的长按操作 运行中 │
│  重构远程会话列表…      55 分钟前  │
│ ┌──────────────────────────────┐ │
│ │ 🗂 scry ⌄   Codex ⌄          │ │  收件人：项目 + Provider
│ │ ＋  描述任务，或粘贴错误信息…  ↑ │ │  输入 + 附件 + 发送
│ └──────────────────────────────┘ │
└──────────────────────────────────┘  34pt 安全区
```

- **顶栏只有三件事**：开抽屉、看/切当前主机、刷新会话。不做 Chat/Work 那种切换一条都不改的装饰控件。
- **主机 chip** 是现有 `homeFilter`（全部主机 / 某台 Mac）的入口，圆点用现有 `StatusDot` 语义：只有真实配对且可达才是绿色。
- **最近**：最多 3 条，按主机返回的真实 `ts` 排序，不合成推荐。键盘弹起时整块收起，只看输入框。
- **输入区**（改造现有 `MessageComposer`）：外层圆角容器 + 边框，第一行是项目 / Provider chip，第二行是 `＋`、占位文案、发送。原有附件、slash commands、模型 / 思考强度 / 权限选择器都保留在容器内。
- **空状态**：主机没有会话时，不显示"最近"标题，只留一行安静说明 + 输入框；未配对时输入区禁用（占位"连接后可输入"），上方给"扫描配对码"入口。

## 3. 抽屉结构

```
┌────────────────────────┐ 272pt，左侧推入，右侧 26pt 圆角
│ Scry               ⌕   │ 标题 + 搜索（点开才变成输入框）
│ 最近   项目   工具       │ 三个视图：时间序 / 按项目分组 / 五个面板
│                        │
│ 需要你                  │ 只在有等待决定时出现
│ 验收 Mac1 到 Mac2…      │ 等待决定
│                        │
│ 置顶                    │ 跨项目平铺，按置顶时间倒序
│ 重构远程会话列表…  55 分钟前│
│ 排查支付页偶发白屏… 2 小时前 │
│                        │
│ 最近                    │ 4 条 + 查看全部
│ 会话归档与恢复…     草稿  │
│ 补齐 iOS 会话抽屉…  运行中 │
│ …                      │
│ 查看全部 11 个会话        │ → 切到项目视图（= Mac 的完整列表）
│ ────────────────────── │
│ ● MacBook Pro · 0.2.214 │ 主机与版本（不是"在线"承诺）
│ ( ＋ 新建会话 )   (⚙)   │
│ 已存档会话 0          › │ → 设置 · 已存档会话
└────────────────────────┘
```

**分段的理由**（每段对应 Mac 侧栏的一种信息）：

| 段 | 对应 Mac | 手机上的规则 |
|---|---|---|
| 需要你 | 侧栏行的"需回答"、活动视图 | 等待决定的会话**提到最上面并从下面移出**，同一证据不重复渲染 |
| 置顶 | `pinned` 段 | 跨项目、按置顶时间倒序；行内带项目名 |
| 最近 | 项目分组的时间序投影 | 按 `ts` 倒序，最多 4 条；"查看全部"切到项目视图 |
| 项目 | 按 cwd 分组 + 折叠 + 项目内新建 | 组头可折叠；组内按 `ts` 倒序；每行带 Provider 与项目名 |
| 工具 | 侧栏五个导航面板 | 五面板入口 + 每行真实状态摘要 + 只读说明（§4.1） |
| 底部 | 品牌 + 版本 + 设置 | 主机状态、`新建会话` 主按钮、设置、已存档入口 |

**行**（两行，高 52–56pt）：标题 15pt 单行截断；第二行 `Provider · 项目` 11.5pt + 右侧状态（草稿 / 运行中 / 等待决定 / 相对时间）。没有外部会话 id 的会话仍然列出，但标"未建立会话"且不可点，避免"点了没反应"。

**长按（或右键）行**：置顶 / 取消置顶、重命名…、存档。存档在会话仍在运行时改文案为"存档并停止"，并先确认（对应 Mac 的"存档并停止运行，取消排队消息"）。存档后底部出现 5 秒撤销条。

**搜索**：点 ⌕ 展开输入框（⌘/键盘友好，焦点直接进框）。匹配标题、项目名、Provider、cwd，与现有 `HomeView` 一致；空结果显示"没有匹配的会话"。

## 4. 工具标签页与五个面板（与 Mac 对齐）

抽屉的第三个 tab 是「工具」。Mac 把五个面板平铺在侧栏顶部，手机没有那份纵向预算，所以收进一个 tab；**面板内部的结构、字段、证据文案与 Mac 一一对应**，不做手机版自创布局。

### 4.1 工具页（第 5 块画板）

| 行 | 对应 Mac | 状态摘要（主机给的字段） |
|---|---|---|
| 分析 | `AnalyticsView`（usage-page） | `近 30 天 · 128 轮 · US$4.12` |
| LLM 性能 | `LlmPerformancePanel` | `2 个模型有样本 · 1 个会话运行中` |
| 技能 | `CapabilitiesModal view="skills"` | `项目 2 · 用户 3` |
| MCP | `McpTrustPanel`（侧栏 → MCP） | `3 servers · 1 项发现`（琥珀） |
| Meta Prompts | `MetaPromptsView` | `3 条提示词 · 可填入输入框` |

- 能力位不成立时整行 `disabled`，状态行写 `不可用 · <缺哪项能力>`（`copy.toolGated`）。Pi 没有 MCP 状态接口，就显示不可用，不探测、不推断。
- 工具页底部一行 `只读镜像 · 写操作在 Mac 上完成`。

### 4.2 面板屏通用结构

```
←          <面板标题>           ↻
        来自 MacBook Pro · 21:32 读取
├ 与 Mac 同序的 section（每节：标题 + 右侧控件/计数）
└ 证据脚注（覆盖度、来源、只读说明）
```

- 顶部固定来源与读取时间；读取失败或陈旧时保留旧内容并追加"未标为最新"，不把旧数据当当前事实。
- section 顺序、标题、右侧计数/分段控件与 Mac 一致；手机只把横向排布改成纵向。
- 明细一律有上限（默认 20 行）+ `再加载`，超出不下发正文。
- 缺字段显示 `不可用` + 原因（`主机未提供该字段`），不折成 0，不画进图表。

### 4.5 需要的只读主机接口

现有 op 白名单（`src/main/remote/desktop-client-ipc.ts`）没有这五类读取。建议加一个只读族，一个 kind 对应一个 Mac 现有查询：

```
toolPanel { kind: 'analytics'|'llm'|'skills'|'mcp'|'meta', params }
  → { status: 'ready'|'unavailable'|'stale', provenance: { host, readAt }, payload }
```

| kind | 复用的 Mac 查询 | payload 上限 |
|---|---|---|
| analytics | `usageAnalytics(rangeDays)` | totals + byProvider/byModel/byDay，明细 ≤ 20 行 |
| llm | `llmPerformanceSummary()` + `llmPerformanceHistory()` | 会话 live ≤ 20；样本 ≤ 240（与 Mac 的截断一致） |
| skills | `useIntegrations` 的 skills 清单 | ≤ 200 项（名称/描述/scope/dir） |
| mcp | `mcpGuard` 报告 + live 状态 | ≤ 50 target；只给短指纹与 findings，不给可执行配置原文 |
| meta | `readMetaPrompts(localStorage)` | ≤ 100 条，正文 ≤ 8KB/条，超出只给预览 |

- 权限沿用现有设备授权 + workspace 校验；写操作**不在这族里**。
- `status: 'unavailable'` 必须带原因，手机把原因原样显示，不翻译成"暂无数据"。

## 5. 交互、手势与无障碍

- **打开**：点左上角；首屏左缘右滑也可开。**关闭**：点遮罩、抽屉上左滑、选中会话后自动关。
- **手势冲突**：会话记录页的左缘右滑仍是"返回"；抽屉只在首屏和会话页"未开抽屉"时接受左缘手势，开着抽屉时该手势归抽屉。行不做 swipe actions（会和抽屉滑动抢手势），操作一律走长按菜单。
- **动效**：抽屉 340ms `cubic-bezier(.22,1,.36,1)` 平移 + 遮罩淡入；菜单 160ms 由 0.96 缩放；`accessibilityReduceMotion` 时全部退化为淡入。
- **无障碍**：抽屉是 `dialogue`（SwiftUI 用 `.accessibilityAddTraits(.isModal)` + `.accessibilityAction(.escape)` 关闭）；每个行按钮的朗读名 = 标题 + Provider + 项目 + 状态；分组头是"展开/收起"按钮带 `aria-expanded`；44×44 最小点击区（chip、已存档入口用外扩命中区补齐）；Dynamic Type 跟随系统，行高随字号增长。
- **证据不撒谎**：抽屉顶部不写"已连接"绿条；`MacBook Pro · 0.2.214` 只是身份，绿色圆点只在真实交换成功后出现。刷新失败保留旧列表并标"上次读取时间"，与现有 `CatalogRefreshBanner` 一致。

## 6. 与 Mac 侧栏的功能对照

`复用` = 现有主机接口与手机 transport 已够；`加方法` = 需要给 Swift transport 补一个已存在的主机能力。

| Mac 侧栏功能 | 手机方案 | 依赖 |
|---|---|---|
| 品牌 + 版本 | 抽屉底部主机行 | 复用 |
| 新建会话 | 底部主按钮 → 新任务页 | 复用（`beginNewTask`） |
| 搜索会话 / 项目 | 抽屉内展开式搜索 | 复用（`model.query`） |
| 置顶段（跨项目） | 置顶段 | 复用读取 |
| 按项目分组 + 折叠 | 项目视图 + 组头折叠 | 复用 |
| 项目内新建 | 组头 `＋` | 复用 |
| 会话行：Provider / 草稿 / 运行中 / 需回答 / 相对时间 | 两行行 + 状态徽标 | 复用（`liveRuns`、drafts） |
| 会话行：置顶 | 长按菜单 | **加方法**：`sessionAction {kind:'pin'}` |
| 会话行：重命名 | 长按菜单 + 输入弹窗 | **加方法**：`sessionAction {kind:'rename'}` |
| 会话行：存档 | 长按菜单 + 确认 + 撤销 | **加方法**：`sessionAction {kind:'archive'}` |
| 已存档会话（恢复 / 删除） | 设置里新增列表 | **加方法**：`sessionsPage {includeArchived}`、`sessionDelete` |
| 活动视图 | "需要你" 段 + 最近的时间序 | 复用 |
| 进行中 / 后台待发 / 结果未确认 | 首屏卡片（见 §6） | 复用 |
| 刷新与失败提示 | 顶栏刷新 + 首屏失败卡片 | 复用 |
| 会话索引健康提示 | 首屏一行"尚未核对" | 复用（`unverifiedCache`） |
| 项目置顶影响排序 | **不做**：远程 catalog 只给会话，不给项目置顶信息；跨项目顺序按时间 | 缺主机字段 |
| 未读会话点 | **不做**：手机没有 unread 跟踪，不合成 | 缺主机证据 |
| 分析 / LLM 性能 / 技能 / MCP / Meta Prompts | 抽屉「工具」tab + 五个只读面板 | **加接口**：只读 `toolPanel` 族，见 §4.4 |

主机侧已经具备、只需手机补客户端的能力（都是小改动，不需要新协议）：

- `src/main/remote/host-controller.ts:589` `sessionAction`（rename / pin / archive，`workspace.authorize` + 设备重验 + 能力位 `sessionActions`）。
- `src/main/index.ts:4922` 的 `sessionAction` handler 已接 `archiveSessionAndStop`（运行中存档 = 请求停止 + 取消排队消息）。
- `src/main/remote/remote-gateway.ts:657` `sessionsPage` 已支持 `includeArchived`；`host-controller.ts:658` `sessionDelete` 只允许已存档会话。
- 缺口在 `experiments/remote-g0/swift/Sources/RemoteTransport/Transport.swift`：没有 `sessionAction` / `includeArchived` / `sessionDelete` 的调用与响应校验。

## 7. 首屏继续承担证据责任（第 4 块画板）

抽屉不是"详情"的藏身处。以下内容留在首屏：

1. **等待决定**横幅（44pt，琥珀底）：与现有 `RootView.safeAreaInset` 横幅同一语义。
2. **刷新失败**卡片：标题 + "仍显示上次读取的内容，未标为最新" + 重试 / 详情（进现有 `CatalogRefreshDetails`）。
3. **返回当前任务**卡片：运行中 / 观察中断 / 结果未确认三种真实状态，动作是"继续"。
4. **待发送与核实**卡片：保留原主机与原消息，动作为"核实发送结果" / "移除"，不自动重投。

## 8. 明确不做，以及为什么

- **五个面板的写操作**：MCP 改配置、Meta Prompt 编辑/删除、技能启停都会改 Mac 本机状态或信任。手机只读；写要另开契约并重验指纹。
- **五个面板的图表简化**：不做。Mac 的面积图与对比表照搬——之前设想过"小屏换成数值 + 迷你条"，那会让手机和 Mac 给出的读数口径不同，撤回。
- **项目置顶、项目重命名 / 移除**：远程只给会话，没有项目元数据写接口。
- **未读**：没有 unread 证据，不能靠时间猜。
- **行内 swipe actions**：和抽屉滑动手势冲突，且在抽屉里几乎测不准。
- **推送通知**：不在本稿。

## 10. 已确认的决定（2026-10-21）

1. **输入框默认收件人**：默认选中上次使用的项目 + Provider；没有历史时回落为"选择工作目录"，发送禁用。

## 11. 验收时要看到的东西

- 首屏键盘弹起后只剩输入框；发送按钮在未配对 / 无项目 / 空文本时禁用且原因可见。
- 抽屉能用三种方式关闭；行点击只在有外部会话 id 时进入记录页。
- 置顶 → 行从"最近"移到"置顶"；存档 → 行消失且 5 秒内可撤销；重命名 → 列表与记录页标题一致（以主机回执为准，失败要回滚并提示）。
- 刷新失败时旧列表仍在，并显示上次读取时间；等待决定的会话同时出现在横幅与"需要你"，但不在下面重复。
- VoiceOver 能读完一行（标题 + Provider + 项目 + 状态），Esc 手势能关抽屉。
- 工具页：能力不成立的行不可点且写明缺的是哪项能力；五个面板都能打开。
- 面板屏：顶部显示"来自哪台 Mac · 何时读取"；section 顺序与 Mac 一致；明细显示 `前 N / 总数` 且"再加载"可用；缺字段显示"不可用 + 原因"，页面上不出现把缺失折成 0 的数字。
- 分析：`≈` 与"下界"标记必须出现且着色；Token 五项覆盖度逐项显示。
- LLM 性能：运行中会话在历史之前；速度与首字两个指标都能切换；模型图例可点选。
- 技能：来源计数为 0 的页不出现；脚注说明只读。
- MCP：与 Mac 同为只读观测（策略状态 / 风险发现 / Fleet inventory / 策略与审计），动作只有刷新与扫描；报告标签旁要写"不是官方认证"。
- Meta Prompts：`放入输入框` 真的把正文填进首屏 composer；编辑/删除点了只提示在 Mac 上处理。

### P3 与设计稿的差异（需维护者确认）

- ~~MCP 风险发现缺席~~ → 维护者 2026-10-21 明确授权手机请求只读扫描。现实现：`toolPanel(mcpTrust)` 在主机侧跑静态只读扫描（`buildMcpExecutionSnapshot`，mode=read），返回目标清单 + 严重度汇总 + 风险发现（标题/规则/策略决定/受影响目标/建议）与截断标记。边界：设备只传 providerId，扫描路径固定为 Mac 当前工作区，设备无法指定路径；报告中的证据（配置路径、环境变量名、哈希）不下发给手机；扫描失败返回 `scanUnavailable`，不显示成"没有风险"。
- **图表降级**：分析每日图用条形而非面积图，LLM 历史用行表而非折线；数据口径（`≈`、下界、覆盖度、截断说明）与 Mac 一致，缺的只是 SVG 级图形。
- **技能 / Meta Prompts**：工具页显示"手机端暂未提供"，不是"Mac 未提供"，避免把客户端缺口说成主机缺口。
