## 原始复现与设计动作

- **已在修改前真机复现**：新任务输入 → 返回 → 新任务，草稿消失。改为 AppModel 按会话身份持有内存草稿与附件；新任务独立；发送被本地拒绝不清空。
- 历史续聊没有待决定入口 → 将同一个请求 sheet 放到 Root，仍受登录态门禁；可暂时收起，保留明显的待决定入口。请求取消不宣称整轮已经停止。
- 本地新会话 UUID 与主机 external session ID 不同 → 主机报告 ID 后建立草稿别名，重新从目录进入同一会话不丢输入。
- 运行未收敛时 reset 会丢 intent/checkpoint → store 拒绝覆盖；首页提供返回当前任务入口。当前保持**单一未收敛手机运行**，不能用多个并行新任务覆盖恢复记录；若未来要求并行，先升级为按 run ID 持久化的多运行存储与独立观察，不能仅去掉按钮门禁。
- 终态先于尾部输出、归档与当前轮重复 → 保留终态事实，但 drain 完成后才开放下一轮；按 run ID 排除当前归档项，不按 prompt 文本猜测去重。
- Provider / 目录 / slash 请求返回乱序 → 使用对应请求身份/代次隔离；恢复控件分字段保留缺失问题，不因选权限而静默更换缺失模型。
- 每次输出强制滚到底部 → 两个会话视图复用 `ConversationScrollView`；上滑阅读暂停跟随，提供“回到最新”。
- 小图标有效点击范围不足 → `CircleButton` 明确 contentShape；附件入口 44pt。这是原生触控判断，不冒称 Craft 未发布规则。
- 相机权限拒绝时黑屏 → 清晰错误、取消与手动粘贴配对码；仍经过原 PairingCode/mTLS/Mac 确认。相机 start/stop 同一串行队列，避免主线程 stopRunning。
- 清除配对单击即删除 → 原生二次确认，明确不会停止 Mac 任务；未决任务禁止清除恢复凭据。
- 真实历史读取曾出现 `handshakeFailed / uncleanShutdown` → 保留错误详情，提供原地重新读取与非阻塞返回，不改成空历史或假成功，不扩大传输超时掩盖问题。

## 视觉检查重点

保留文字层级、SF Symbols 与既有圆角；按照 [Craft](https://craft.gustavofior.com/optical-alignment) 的实际视觉重心原则检查图标，不批量偏移。输入控件的内外圆角沿用项目 tokens。新增操作不抢正文，错误技术详情折叠但可展开。代码块、长文本、多行输入、输入焦点与返回路径须实际看图；构建不等于交互验收。
