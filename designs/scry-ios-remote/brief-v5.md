# Scry iOS Remote v5 全量重设计 brief · 2026-09-14

## 任务

让离开电脑的 Scry 用户在 iPhone 上快速找到会话、继续对话、确认运行状态、处理配对与连接问题。成功标准：核心动作单手可达、会话内容优先、真实状态不被装饰淹没，并且在 iPhone 17 Pro 尺寸与系统安全区下不过度放大或留下无意义空白。

## 用户本轮确认

- 全量界面：登录、配对、首页、会话、新建任务、选择器、错误/空/离线与设置都纳入统一设计。
- 视觉优先贴近 Codex iOS，但先调研主流 App，不机械复刻。

## 硬约束 H

- H1：生产实现仍为 SwiftUI；HTML 仅用于隔离探索，不接真实凭据或服务。
- H2：连接、运行、审批、停止和用量必须保持真实语义；未知不显示为成功或零。
- H3：仅主机已授权项目可被选择；Provider 差异与续聊身份不可隐藏。
- H4：离线可浏览缓存，但禁用发送/批准；配对确认仍由 Mac 完成。
- H5：支持 390×844 基准与 iPhone 17 Pro 真实安全区；触控目标至少约 44pt，正文 15–17pt，不绘制假状态栏/键盘。
- H6：先比较结构方向，经用户选择后再修改 `apps/ios/ScryRemote`，不在生产代码里试错。

## 可协商偏好 S

- S1：靠近 Codex 的轻量顶栏、内容留白、底部输入，但减少现版本过大的空白和控件比例。
- S2：浅色、低饱和、细分隔；蓝色只留给主动作，绿色/琥珀/红色仅用于真实状态。
- S3：会话正文优先，运行证据折叠成可展开摘要，不把手机变成日志面板。
- S4：优先系统 SF Symbols、原生 sheet、导航和 Dynamic Type；形成 Scry 自身的远程/证据识别，而不是复制竞品品牌。

## 已观察的现状

- 当前真机新建页顶部出现系统通知遮挡，主机地址、项目与 Provider 行字号/间距过大，页面中段长期空白，底部 composer 过高。
- 当前 v4 HTML 已有 Codex 结构，但首页项目列表重复、远程状态弱，信息组织尚未被用户确认。
- 已有真实功能：公网配对、项目/Provider 列表、会话目录、历史读取、续聊、实时生命周期与输出。此次不改协议状态机。

## 三个结构方向

1. **A · Codex Refined（推荐）**：维持 Codex 的无底栏结构；首页改为紧凑会话流，项目成为筛选上下文；新建页把上下文压到 composer 上方；运行证据在回复下方折叠。
2. **B · Chat First**：参考 ChatGPT，把“开始任务”置于首页核心，历史与项目进入抽屉；路径最短但弱化项目扫描与多主机可见性。
3. **C · Work Queue**：参考 GitHub Mobile，以 Sessions / Runs / Devices 三段底部导航组织；状态与审批最清晰，但离 Codex 更远、界面更工具化。

## 状态与尺寸

- 状态：已连接、已配对未验证、离线、加载、空列表、失败、运行中、待确认、完成、历史部分缺失、长项目名/长消息。
- 尺寸：390×844 比较稿；生产需额外验证 320pt 宽和 iPhone 17 Pro 真机。

## 验收

- 同一合成数据并排比较三个方向，不只换颜色。
- 每方向至少展示首页与会话/运行关键画面；说明任务路径、代价与适用场景。
- 用户选定方向后，补齐全量页面和状态，再进入 SwiftUI 实现与真机验证。
