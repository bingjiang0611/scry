# 远程主机并入统一会话流程 / 2026-10-14

任务：已保存 mac2 等主机的用户，在新建会话时选择“哪台机器 + 哪个目录”，之后的发送、追问、停止、历史和证据阅读都使用本机会话的同一套界面。成功标准：用户不需要学习“远程会话页”这个独立概念。主机只在单独的「主机」页里添加、连接和撤销。

感受：远程只改变 Agent 在哪里执行。界面结构保持不变，只在三个位置显示执行位置：composer 上下文、会话顶栏和侧栏项目。不使用“远程”横幅、独立的表单式侧栏，也不重复显示“已连接”文字。

约束：
- H1 离线、未知或已删除的主机不得静默回退到本机。草稿保留，自动重发被禁止（docs/desktop-remote.md「行为与边界」）。
- H2 已有会话锁定机器、项目和 Provider/profile。切换新会话的位置不会迁移当前会话（D-20261014-machine-navigation）。
- H3 远程能力缺口必须显式展示：文件只读，首版不支持附件、终端和单个后台任务停止。界面把这些入口显示为不可用并说明原因，不隐藏成“无”（CLAUDE.md 第 2 条）。
- H4 权限文案说明真实效果：完全访问表示 Provider 以 mac2 上的用户权限运行，不写成“本机完全访问”。
- H5 「我连接的主机」和「允许其他设备访问本机」是两个方向，不能合并成一个列表。
- S1 只有本机、没有保存主机时，composer 和侧栏与当前版本一致。
- A1 侧栏要合并显示远程会话，需要定期读取各主机 catalog。当前 API 有 `catalog().sessions`，但是否适合在侧栏轮询未验证。
- A2 远程目录只能从主机 catalog 的 projects 中选择。现有 API 不支持任意远程目录浏览，所以原型不提供“浏览 mac2 文件夹”。

范围：新会话位置选择、侧栏归属、远程会话视图、离线状态、主机管理页与添加主机。保留现有 composer C4 结构、Provider/Model/Effort 选择器和 ChatTurn。不做：生产代码修改、真实连接。

复用：P-SCRY-DESKTOP-REMOTE（docs/desktop-remote.md）；composer C4（designs/scry-composer-refresh v4）；生产 tokens `src/renderer/styles.css`；`WorkdirPicker` / `MachineNavigation` / `DesktopRemote` 组件语义。个人库没有匹配的组件。

调研：
| 来源/区域 | 观察 | 采用/不采用 | 动作/检查 |
