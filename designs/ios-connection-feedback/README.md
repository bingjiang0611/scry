## 范围与用户反馈

本轮仅制作独立交互稿，不修改 Swift、后端或权限合同。用户反馈：iOS 状态混乱，希望更简洁；可考虑不常驻状态，在刷新成功时提供反馈。此反馈只适用于 Scry iOS 连接与刷新区，不升级为全局隐藏状态的偏好。

预览：`http://127.0.0.1:8765/ios-connection-feedback/`。

重新启动：在仓库根目录运行 `python3 -m http.server 8765 --bind 127.0.0.1 --directory designs`。

重新生成原型脚本：

```sh
node_modules/esbuild/bin/esbuild designs/ios-connection-feedback/prototype.jsx --bundle --format=iife --outfile=designs/ios-connection-feedback/preview.js
```

`preview.js` 是生成文件。使用项目既有 React 18 本地文件与 `../scry-ios-remote/design-canvas-v5.jsx`；没有新依赖。须通过上面的 designs 根目录服务，以解析相邻资产。原型内的刷新、时间与 TLS 错误均为演示数据，不访问真实 Mac。

## 设计比较

| 方向 | 常态 | 优点 / 代价 |
| --- | --- | --- |
| A · 推荐 | 仅保留“远程”标题 | 最安静。具体的配对、更新时间与请求结果按需查询 |
| B | 标题下保留“上次更新 HH:mm” | 更直接看到数据时间；标题始终多占一行 |

A 的失败态是同一结构的状态变化，不是第三个方向。只调整连接反馈区域，保留置顶、项目层级、搜索与新建任务。

### 推荐 A 的交互

- 正常：没有连接圆点、配对徽标和常驻解释。标题右侧保留刷新与更多。
- 主动刷新：下拉或点刷新，显示进度；进行中合并操作，不并发刷新。
- 完整刷新成功：浮现“刷新成功”2.6 秒，随后消失。成功反馈不推挤列表；后台自动刷新不反复提示成功。
- 传输失败：一条低饱和提示：“会话列表刷新失败”，附上次完整更新时间、重试与详情。它不是全屏错误，不清空旧内容，也不叠加 toast。
- 重试：复用原提示；成功后移除提示。再次失败只更新这一条提示。
- 详情：半屏呈现设备、配对、本次请求结果；技术详情默认收起。TLS 握手错误不等于 Mac 没有响应或已离线。
- 未核对：缓存列表可见，显示轻量的“尚未核对 · 下拉刷新”。不把历史成功伪装为当前已连接。
- 缓存中的运行徽标在未核对或失败时使用“上次：运行中”，不把历史运行状态当当前事实。

原型的菜单、搜索、置顶折叠、结果切换、重试、详情与技术信息可操作。会话与新建入口只说明原型边界，不模拟真实任务。弹层支持关闭、Escape 和键盘焦点约束；尊重减少动态效果设置。

## 生产集成时必须保留的边界

此表是设计合同，不代表本轮已经实现这些原生状态。

| 情形 | 首页呈现 | 证据要求 |
| --- | --- | --- |
| 手动刷新全部分页完成 | 成功短提示 | 只有当前设备、当前 generation 的完整请求完成才可触发 |
| 收到部分页后失败 | 单条“列表未完整更新”提示 | 保留部分数据语义，不显示普通“列表未更新”或成功 |
| 远端已刷新，但手机缓存写入失败 | 单条“列表已更新，未保存到手机”提示 | 不误报成连接失败，也不无条件吞掉缓存错误 |
| 无上次成功时间 | 不编造时间；显示“尚未核对”或对应错误 | 不使用缓存文件 mtime 代替服务器核对时间 |
| 无任何可显示数据且请求失败 | 一个空状态与重试 | 不再叠加顶部失败卡与全屏错误 |
| 配对失效、权限撤销 | 单条明确问题与重新配对入口 | 不折叠成普通传输失败；授权语义不变 |
| 发送结果未知 | 保留消息级结果未知提示 | 不用列表刷新成功清除发送错误，不自动重发 |
| 后台刷新失败 | 更新同一刷新状态 | 不用新旧多个警告争抢同一区域 |

`AppModel.swift` 的连接观测与 `RemoteRunStore.swift` 的列表/分页/磁盘错误仍应保持分离。设计减少的是投影层重复提示，不是删除诊断或降低错误证据粒度。配对与请求成功不得互相替代。

## 调研与复用依据

| 来源 / 区域 | 观察 | 本稿采用 / 拒绝 | 检查 |
| --- | --- | --- | --- |
| 用户截图 / 顶部四处状态 | 配对、未收到响应、状态未知、TLS 明细同时出现 | 合并为一条任务级失败提示；技术信息下沉 | 首页只保留一个失败提示 |
| [Apple HIG · Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback) / Best practices | 反馈强度匹配重要性；状态可被动查看；不可执行的操作应说明原因 | 常态收起；失败持续可操作；拒绝把每次普通后台成功都做成提示 | 手动成功才提示；失败不自动消失 |
| Apple 同页 / Mail 示例 | 状态可以靠近相关内容，不需要打断任务 | B 只显示更新时间；拒绝绿色“持续在线”暗示 | B 时间可见，无绿色连接点 |
| `apps/ios/ScryRemote/HomeView.swift:18–35` | connectionBanner、softWarning、catalogError 可同时展示 | 刷新区选一个最相关结果呈现，详情保留来源 | 单一提示而非重复横幅 |
| `apps/ios/ScryRemote/AppModel.swift:174–187` | 配对、失败、可达属于不同观测 | 详情分列配对与本次请求；不改合同 | 成功说明明确不代表持续在线 |
| `apps/ios/ScryRemote/RemoteRunStore.swift:640–710` | 分页进度、完整成功、网络失败、缓存写入失败分属不同阶段 | 完整列表才触发成功；部分结果和缓存失败另列设计合同 | 不以一次进度回调判断刷新完成 |
| `designs/scry-ios-remote/brief-v5.md`、`v5-canvas.jsx` | 既有 iOS 原型与本地 React/画布资产 | 复用比较环境与既有首页结构，不另造产品视觉系统 | 本地资源，无 CDN、无上传 |
| 个人库按项目及交互分别检索 | `toast` 无匹配；`status` 匹配用量组件，不适合连接反馈 | 不强行复用不相干组件；直接复用项目既有原型运行资产 | 未宣称复用不存在的组件 |

Apple 原文通过其公开 JSON 文档端点读取：`https://developer.apple.com/tutorials/data/design/human-interface-guidelines/feedback.json`。研究没有上传项目内容或截图。
