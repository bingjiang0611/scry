# Same-root revisions — ordinary and native effect seams

These are bounded implementation increments, **not M3 or M1–M6 acceptance**. Static/dynamic/native same-root execution, separate-controller recovery evidence and the production review/approval entry now exist. See [current production revision entry and acceptance](revision-entry-status.md). Full quality programs, generic failure restart and the remaining M1–M6 obligations stay open.

## Implemented seam

`WorkflowService.revise(preview, approval, { expectedRevision }, commandId)` is main-only. It validates the complete frozen candidate, current runtime capabilities, root settlement and observed state version. It enters the existing Runner → Interpreter; it does not create a scheduler, replacement root, arbitrary command/path IPC surface or synthetic Provider outcome.

A revision claim appends an epoch/control segment and a governing revision snapshot. File storage writes content-addressed immutable governing artifacts before atomically publishing their references in the root manifest. Existing intents, outcomes, system ledgers, approvals and prior programs remain historical facts. Missing or hash-invalid governing artifacts fail closed. Legacy roots without revision artifacts remain readable; their untouched first revision is retained without inventing an earlier approval.

The root keeps its ID, non-refundable 1000-intent budget, existing per-revision logical task identities/six-attempt ceiling, 256 control-segment limit and 16384 system-effect ceiling. No new revision is admitted while any historical intent lacks an outcome, any scope is unsettled or any historical business outcome is unknown, including removed nodes. Stop receipts do not establish settlement. Existing same-program continuation equality is unchanged; a program change is accepted only by the explicit revision/CAS branch retaining the complete prior snapshots.

## Bounded historical result reuse

The source admits pure/static `sequence`, `parallel`, `call`, `bind`, `return` and dynamic `branch`, `map`, `loop`, `collect`, plus closed `replica`, `check`, `verification`, and replica-bearing Agent effects in explicit same-root revisions. The prior static eager selector remains for static-to-static ordinary calls; SystemSteps and scoped Agent calls are represented as non-reusable current effects. If either revision is dynamic, reached call frames select individual historical invocations through the same Interpreter callback; governing revision arrays are never lazily rewritten. Static dependencies include call input references, bind expression references and consumed container outputs. Local definitions, transitive effective IR inputs, workspace/goal and full frozen role/runtime identity must match. Mere launch-order changes do not invalidate independent call facts. A changed B invalidates B and an actual consumer D, not independent A/C.

A reusable call must also have a canonical admitted, observed-model, settled successful outcome; a main-issued completed control frame and hash-verified output/value; and matching main-observed workspace manifests before/after the original call and again at new consumption. Requested/observed model aliases that cannot be shown equal are conservatively not reused. Original attempt/frame/value/revision provenance is retained. No new attempt, usage, external receipt, zero cost or fresh Provider execution is invented.

New call frames capture immutable main-issued declared-input artifacts, a local definition/role/runtime/workspace/goal key, and committed ancestor control evidence. Branch evidence retains the selected decision. Map evidence retains the stable key, original item artifact and validated sealed-source association, not array launch order. Loop evidence retains the ready iteration, actual state/invariants, immutable semantic-state references and committed previous-iteration records. Pure regenerated artifact names/revision prefixes are not semantic dependencies. Source opaque Provider attempts remain dependencies even when replacement JSON is identical. Native SystemStep provenance resolves only the durable main `SystemOutcome.resultRef` plus its historical program/type proof; a projected scalar consumer may differ from the full SystemStep result while retaining the native source leaf.

The production request renderer was inspected: it includes `block.prompt`, declared `inputRefs` (with selected paths), and the structured-output footer; it does not implicitly inject ancestor map payloads. With explicit parent approval, unused ancestor map payloads are still validated as source evidence but omitted from call matching. Stable ancestor keys and genuinely consumed inputs/selected controls remain keyed. Explicitly consumed outer fields, ancestor-key changes, and replaced opaque producers invalidate the affected consumer. The ordinary call descriptor never creates collection/replica/path authority from model JSON. Pure-transform provenance resolves main evaluation-envelope refs to real canonical facts, not identically spelled fields inside model payloads. Traversal is iterative and bounded to 16384 distinct value refs. Linear pure-binding depth is not expression nesting; an 80-reference regression fails the former recursive depth64 implementation and passes the iterative reader. Bounds still reject unsupported evidence rather than guessing.

A selected source is checkpointed on the current call frame before consumption. It carries the original governing revision, attempt, input artifact and committed result frame/value. Cold continuation validates that selection again; missing, modified or foreign evidence rejects instead of silently redispatching. Unchanged admitted failures also compare effective request/control inputs without treating a mere changed control-definition hash as permission to resend. Existing safe pre-Provider retry authority is unchanged.

Production `WorkflowSystemHost` automatically observes ordinary Agent inputs. Before evidence is saved before executor invocation; after evidence is acquired only after scope settlement. Scanner/metadata/observation failures are explicitly unavailable and do not block an otherwise admissible original Agent call. They forbid reuse. Roots without a main Host and old records without these observations are not reusable. Missing/corrupt artifacts that claim availability reject revision recovery instead of rerunning under fake evidence.

Repository HEAD/root metadata uses the existing read-only, environment-scrubbed Git transport; non-repository directories need no Git CLI. The existing bounded manifest scanner excludes `.git`/`.scry` content and rejects unsupported links/entries. Git revision observation supplements those exclusions; it is not a complete Git config/index/recorder read-set.

**These observations do not prove read-only execution, absence of external effects, a sandbox, exact file read-sets, or freshness of undeclared network/outside-workspace inputs.** Reuse means a bounded historical result under matching declared IR inputs and observed workspace/runtime, not a statement that external facts are current. Native trust/fingerprint checks remain in the original App execution chain for every newly dispatched call. Catalog runtime identity and workspace observations do not attest external executable/config freshness. This ordinary result reuse cannot mint replica/path authority or supply a current quality-check/independent-verification pass.

## Explicit limitations and next seam

- Same-root revisions now admit `replica`, `check`, `verification`, and replica-bearing Agent calls through the canonical Runner → Interpreter → main effect path. New SystemSteps receive fresh frames and step IDs; scoped Agent calls are never ordinary historical reuse. Historical system facts use immutable revision boundaries and governing previews, including legacy pure/static multi-revision roots with effective zero system offsets. The main Service seam now passes the current Workflow and full Node unit selections described below, including real FileStore/local Node, native canonical-frame CAS, legacy boundaries, diagnostic verification and dynamic observation checks. The unchanged three-revision/eleven-call map passes its original5000ms gate after the explicitly authorized second bounded investigation. This is not complete quality/M3 delivery. Dynamic cold faults passed in-process controller replacement. The [separate OS-controller native recovery fixture](native-process-recovery-status.md) now also passes in the current full unit run, including a hash-corruption refusal and no redispatch. Direct dynamic six-attempt exhaustion remains additional acceptance work; shared original root-budget tests passed.
- Pure grouped-key reuse deliberately retains main-resolved opaque member origins for that group, not unrelated groups. A scalar/group-key-only consumer may rerun when a same-group member is replaced, even if selected scalar bytes are identical. This parent-approved conservative aggregate boundary is not exact field-level lineage. If product requires key-only reuse across same-group member replacement, add main-generated path lineage before widening matching.
- Any observed ambient workspace change can prevent all reuse. This is deliberately coarser than an exact Provider read-set. Native-tainted raw arrays without sealed per-member lineage conservatively retain whole-source origins; unrelated rows may rerun. Exact per-path native lineage and an unaffected-row regression are still required before claiming fine-grained M3 reuse; this is not the approved same-group boundary above.
- Unchanged admitted failures/stops without canonical pre-Provider non-dispatch proof cannot be replayed merely by changing another node/revision. Generic failure restart, watchdog/stall recovery and replay of unknown external effects remain unsupported.
- The main-only full-preview Service method is now reached through fixed typed `prepareRevision`/`revise` IPC and an explicit desktop review. Main compiles source-only input, freezes runtime/native authority and binds the candidate to the expected state revision. Accepted durable retransmission survives an actual App-process restart without dispatch. See [entry acceptance and limits](revision-entry-status.md); this is not generic failed/stopped restart.
- Actual dispatch still retains before/after observations, and historical consumption still rechecks source. Unused dynamic-admission/ineligible-candidate scans are removed. Native frames reference the canonical durable result; successful terminal sequence cursor/result publication is consolidated without an early ACK or weaker CAS/flush. See the [bounded stage investigation](../../docs/performance-experiments/20261024-workflow-map-stage-profile.md). The global providers.catalog collector is still unavailable; no App-wide speedup or L3 claim.
- Full revision snapshots are immutable artifacts; hydrated reads and journal/value artifacts still enforce existing size limits. This is not unlimited history storage.

Next: complete dynamic-limit evidence, explicit settled-failure restart, typed owned-copy source/output and current quality authorities, then the remaining M1–M6 management and real-account acceptance. The production revision entry above does not finish M3 or M1–M6.
