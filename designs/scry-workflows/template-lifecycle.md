# Scry Workflow v10：保存、编辑与复用

状态：**待实现合同，不是生产功能或原型验收**。本次补齐个人/项目保存、手动与Agent修改、差异预览、保存新版/另存为，以及单次运行与模板隔离。与 [主方案](implementation-plan.md)、[入口合同](chat-entry-semantics.md)、[执行语义](execution-semantics.md)、[限额](runtime-limits.md)、[运行管理](run-management.md) 共同生效；覆盖此前“模板只存App-owned”的范围限制，不改变Scry不是安全沙箱的边界。

依据为原文的 [Save the workflow for reuse](https://code.claude.com/docs/en/workflows#save-the-workflow-for-reuse) 与 [Edit a saved script](https://code.claude.com/docs/en/workflows#edit-a-saved-script)。**原文保存JavaScript，Scry保存结构化WorkflowProgram的可复用定义**；不导入/执行原生 `.js`，不复刻 `/workflow-authoring`、`/reload-skills`，不引入插件市场或通用拖拽编辑器。

## 1. 保存的对象与身份

- `TemplateDefinition` 包含 schemaVersion、templateId、显示名称/说明、参数合同及明确选择的默认值、角色与可移植的Provider/model偏好、完整程序体、输入/输出及验证合同。sequence/parallel/map/branch/loop/call/return和prompt均可编辑，不退回固定阶段列表。
- 个人/项目新templateId由main生成，内置定义使用分发的固定ID；显示名称不参与路径拼接。修订标识为保存内容字节的SHA-256，读取后重新核验；文件未变则不凭时间戳造新版。模板修订、schemaVersion与运行的programRevision是三个不同字段。
- 身份是 `(scope, projectIdentity或personal数据域, templateId, revisionHash)`，不能只靠名字或裸ID。内置模板只读；另存后才成为可编辑副本。
- 保存有效的草案或运行定义均可，不要求运行已成功。失败/未结束的运行保存后仍不能标“执行已验证”。保存的是定义，不是运行记录、展开后的那批文件、成功缓存或恢复点。
- 参数化预览列出输入合同、固定值与待绑定角色；用户明确哪些成为参数、哪些保留为常量。按字段白名单排除凭据、授权收据、session/attempt、transcript、产物正文、临时文件引用和自动应用授权。项目定义不携带本机profile ID、可执行路径或绝对工作区路径；使用角色别名、模型偏好和相对输入，运行时重新绑定。
- 自由文本prompt仍可能含敏感信息；保存前显示实际内容，不宣称自动去敏完整。个人转项目的另存为单独展示将写入仓库的内容；私有来源路径和运行引用留在本机收据，不写入项目文件。

## 2. 个人、项目与共享

以下路径均为拟实现的Scry路径，不声称现在已创建：

| 作用域 | 位置与可见范围 | 写入与复用 |
| --- | --- | --- |
| builtin | 随App分发的内置定义 | 只读；可另存到个人或项目 |
| personal | `userData/workflows/templates/<templateId>.json` | 当前Scry数据域跨项目/会话可用，不等同云同步或多设备共享 |
| project | `<canonicalWorkspaceRoot>/.scry-workflows/<templateId>.json` | 当前获授权项目；通过用户明确的Git提交/分享传给协作者 |

- 项目根是项目authority登记的canonical workspace root，不因当前cwd、文件链接或嵌套目录猜另一根。只加载该根下的固定目录，不扫描父目录、其他项目或 `.claude/workflows`。单仓多包可分别选择其授权项目根；不引入隐式向上继承。
- `.scry-workflows/` 与recorder的 `.scry/records` 等数据分开。保存只写指定定义，不自动修改 `.gitignore`、stage、commit或push。被忽略/未跟踪时提示实际状态，不能把“写入本地”说成“已共享”。项目不在Git中仍可本地保存，但不宣称已随仓库分发。
- 从另一个clone/设备读取共享定义，只获得程序数据，不获得原用户的profile、凭据、workspace authority或执行确认。缺模型/能力/参数时先绑定或显示unavailable，不偷偷替换模型。
- 不采用原文“项目同名自动遮蔽个人”的规则：同名必须显示来源并消歧，不劫持Provider命令。支持 `/scry-workflow template <scope>:<templateId> <参数>`；原有裸ID仅在当前可见来源唯一时解析。project绑定当前授权项目，不接受命令中的任意目录。
- 模板存在、被列出或被选中均不启动任务，不打开manual/auto，也不改变权限模式。项目模板视为不可信数据，不能授予自己shell、插件、MCP或Hook权限；既有仓库配置自动授权与fingerprint重验策略不变。
- 本合同先交付桌面入口，不新增远程读写模板API。个人作用域不是对同一macOS用户的安全隔离承诺，配对设备也不因此获得个人模板目录访问权。

## 3. 统一草稿与手动编辑

从模板详情选择编辑，或从计划/运行详情选择“仅修改本次”，均创建独立草稿。草稿记录来源引用、baseRevisionHash、draftRevision和编辑目标；不直接修改已保存定义或运行快照。

1. 显示结构化JSON源码编辑器及同源的只读结构/连接预览。可改节点prompt、角色/模型偏好、输入参数、依赖、分支条件、循环carry/终止规则和输出验证合同；不要求用拖拽才能改结构。
2. 本地编辑不发模型请求。未完成或非法文本可保存为App-owned草稿，但不能进入可运行模板目录；离开有未保存修改的草稿时允许保留/放弃，不静默丢弃。
3. main对候选执行与自动规划相同的schema、类型/作用域、依赖、控制流与终止校验；拒绝任意JS/eval/import和未知执行指令。错误定位到具体字段/节点，不能自动删除不认识的部分来凑合法程序。
4. 模板结构有效不等于当前Provider可运行。可移植角色先保留需求，实例化时解析实际profile/model并做能力、权限、trust及参数检查；界面分别标“定义有效”和“本次执行可用”。
5. 保存前比较基线与候选：完整源码diff与按节点的语义差异共用同一候选哈希。突出参数/默认值、模型、prompt、依赖、条件、循环上限、验证标准和写入需求变化；不能只显示改名而藏掉执行语义变化。
6. 用户选择操作后才写入。编辑器内容、diff、保存收据和之后实例化的内容必须是同一修订，不能预览A却保存/运行B。

## 4. 用自然语言让Agent修改

- 在草稿中提交“把复核模型换成……”“增加失败后的修复循环”等要求。发送前明确编排Provider/profile/model、将发送的定义/参数与附加资料、费用授权；默认只给基线定义、修改要求和编写合同，不附带原运行的transcript、文件正文或凭据。
- 复用规划路径，在独立编写session和App-owned临时工作目录中产出结构化候选与修改说明，不让Agent直接发布文件；不把源项目作为cwd或自动复制其执行配置，用户profile/runtime自身仍过既有trust检查。编写说明由Scry提供，包含可用指令、作用域/终止规则和硬限额，不依赖Claude的专用skill。该调用占用共享Agent槽位并单独记录用量；不因编辑而创建执行根或启动模板中的节点。定义超出模型上下文/传输限额时明确拒绝，不截断后假装完成全文修改；聊天edit路由与费用时点遵循入口合同。
- 此路径要求adapter有可验证的结构化候选接收/校验与显式禁用宿主工具的编写能力（不要求原生schema采样）；不满足时标Agent编辑unavailable，保留手动编辑，不能拿普通full_access coding run冒充只产草稿。禁用工具不是OS沙箱：原生启动/配置代码仍服从既有trust边界，不保证同用户进程绝无文件副作用。
- Scry只接受候选数据；模型声称“已保存”、返回路径或命令都不成为保存指令。源文件意外变化按冲突处理，不自动回滚或覆盖。Agent编辑请求不等于保存、运行或授权扩大范围。
- 返回结果绑定baseRevisionHash和baseDraftRevision。模型等待期间用户又编辑过时，迟到候选单列为过期建议，不覆盖当前草稿；用户可手动合并或明确按新基线再请求，不能偷偷多调模型重做。
- 候选经过同样校验和差异预览，用户接受后只是更新草稿；仍须另选保存/仅本次执行。主会话只接收草稿入口、修改摘要及用量/结果引用，不回灌整份候选或旧运行上下文。非法候选保留诊断，不改原文件；失败/unknown不当作空改动成功，也不自动重发。

## 5. 保存新版、另存为与发布一致性

| 动作 | 实际效果 |
| --- | --- |
| 保存新版 | 同作用域、同templateId，在基线未变时原子更新当前定义；内容哈希变化形成新修订 |
| 另存为 | 用户选个人/项目与名称，main生成新templateId；原模板不变，跨域不携带私有运行引用 |
| 仅本次使用 | 冻结当前草稿为本次WorkflowProgram；不写模板文件，不改变默认参数 |
| 重命名 | 修改显示元数据并产生修订，不改稳定ID/文件名，不重新绑定已有运行 |
| 恢复旧版本 | 从有证据保留的历史内容生成草稿，经预览/确认再保存；不倒改旧收据 |
| 删除模板 | 确认指定来源/修订后删除当前定义；不连带删除运行快照、归档或其他同名模板 |

- 当前个人/项目JSON是该来源“最新定义”的权威；App-owned历史保存已观察/已保存修订的不可变快照及来源，不是第二个可悄悄覆盖源文件的权威。项目Git历史可随Git保留，但本机只列实际持有的旧修订；另一台机器没有历史时明确不可用。
- 用户也可用外部编辑器改当前JSON；普通Provider直接修改文件也按外部改动处理，其“已保存”文本不是Scry保存收据。重新打开/显式刷新后重新读取、计算哈希并校验，不需 `/reload-skills`；保存或准备新计划时也重验，不能仅信缓存mtime。不支持的schemaVersion明示拒绝，不能自动执行或改写文件。
- Scry写操作按canonical目标串行，校验expectedRevisionHash，使用异步临时文件+原子替换；另存须目标不存在，删除也须基线匹配。冲突保留草稿并显示磁盘版本，用户选择合并或另存，不采用最后写入覆盖。
- 保存commandId和候选/基线指纹有持久收据。重复请求只返回同一操作结果。先持久候选/旧快照，再发布当前定义；中途孤立的候选不是“已发布新版”。崩溃后核对实际文件和收据，无法证明结果则unknown，不自动重写。文件写入与收据不是跨文件事务，不承诺exactly-once。
- CAS和原子替换保护Scry内并发与可检测的外部修改，不宣称能阻止不合作的同用户进程在检查后抢写；后续重读发现不一致必须显示冲突。个人/项目目录及目标在main重验canonical containment，拒绝固定模板子目录或目标文件的符号链接写入，读取也拒绝链接逃逸；文件名须匹配定义ID，不以JSON中的路径/身份换目标。renderer不传任意路径，不可写时明确失败而不是偷偷换保存位置。
- 列表分页、目录迭代读取，源码按需打开；单定义/草稿上限4MiB、每页最多100项，超限明确报错，不截断定义。巨大数据改作参数/运行输入；确需更大定义时先验证编译/IPC/编辑器成本，再显式调整合同，不暗中绕过上限。缓存有界并按来源/内容指纹失效；保存/刷新不逐键全库扫描。

## 6. 模板与运行实例隔离

- 创建计划时绑定模板身份和准确修订，并持久化所用定义、参数、实际角色绑定及WorkflowProgram快照。计划确认只授权该快照；新参数、模型或结构必须重新确认。只要求更换参数不需要编辑原模板。
- 模板更新、改名、删除或Git切换不能替换已冻结的草案、排队实例或运行。新版供下一次明确实例化使用；若用户想在当前预览采用新版，先载入差异再确认。旧快照仍可执行并不代表当前workspace/trust免于重验。
- 活跃、暂停或等待权限的运行都不能注入新prompt、模型、参数或loopState。可以编辑脱离运行的草稿，但不能用“保存”把它应用到正在执行的实例。
- 对已启动实例选择“修订后恢复”：先确认旧scope全部收敛，审批新programRevision，再创建新的执行实例（新workflowId），旧实例不改写；**保留rootExecutionId、既有逻辑调用身份与已消耗预算/重启次数**。按v8依赖/局部定义指纹复用有效结果，变化节点与受影响下游失效；不能直接沿用失效控制帧。未知作用域/副作用或缺失恢复证据仍阻止重放。
- 改显示名或重排不能重置逻辑身份；运行taskId/attemptId由main管理，不接受编辑器指定的重置值。新增节点必须显式记为新调用，仍计入原根预算。不可证明可迁移的状态不猜测复用，说明缺口。
- “作为全新运行”是不同的明确操作：重新绑定输入/能力/授权，创建新根并告知预算重新计数，不伪称恢复。不能由自动编辑、子工作流、重命名或保存动作自动走这条路逃避1000次/五次重启限制。
- 保存新模板可以与旧实例运行并行；若用户另行启动新版，是另一个获确认的任务，仍受共享槽位、workspace写隔离及Provider session fencing约束。不得把旧版已完成当新版已验证，也不双计复用结果的旧用量。

## 7. 实施与验收

M2增加模板来源/修订与草稿合同、共用编译器及Agent编写请求；M3落实发布收据、快照隔离与同根修订恢复；M5完成保存/编辑/diff/来源与冲突界面，复用现有文案模块；M6才执行明确授权的真实Provider编辑/运行验收。没有上线全部路径前，不称保存与编辑能力完整。

| 验收 | 必须证明的行为 |
| --- | --- |
| 保存与参数化 | 从草案/失败/成功运行提取定义，去掉运行私有字段；重开会话、换项目/参数/角色后仍走同一执行链并重新确认 |
| 两种作用域 | 两个临时userData及本地Git clone：项目定义随明确Git操作可复用，个人定义不随clone出现；缺profile拒绝，不带旧凭据/授权 |
| 手动编辑 | 真正修改prompt、branch、loop/carry/终止条件，落盘重开内容一致；非法程序只留草稿；没有编排调用 |
| Agent编辑 | 捕获真实transport请求的输入范围，响应只改候选；宿主工具能力缺失拒绝；迟到响应不覆盖新草稿；接受前原定义不变 |
| 保存与冲突 | 新版保持ID、另存新ID、重名消歧；两编辑器/外部改动不丢更新；在每个发布边界中断后不把候选当已保存，不盲目重写 |
| 路径与共享 | 实际trusted wrapper拒绝任意路径、未授权项目、链接逃逸及超限内容，证明特权写listener未执行、目标未改变 |
| 运行隔离 | 运行/排队期间更新删除模板，旧快照不变；仅本次修改不改模板；修订恢复只失效正确依赖，不重置root预算和既有重启计数 |
| 无隐式执行 | 保存/刷新/外部编辑不启动Agent；只在明确请求编辑时有编排费用；保存模板不生成运行成功或权限批准证据 |

关键反例：移除基线比较时并发覆盖测试必须失败；将运行改为每次读“最新模板”时旧实例隔离测试必须失败；把Agent响应直接写文件时未批准写入测试必须失败。桌面焦点、diff选择与真实保存动作走隔离Electron交互，不用纯字符串断言冒充UI验收。以上均是新增的待实现验收，当前没有执行这些生产场景。
